# Computer Use 插件 v0 实施计划(里程碑 1:macOS 可用回路)

## 选型答案(已定)

- **截屏+输入注入**:`@computer-use/nut-js`(Apache-2.0 npm,三平台预编译,实测通过)+ `@computer-use/node-mac-permissions`(TCC 查询引导)
- **a11y 树读取**:JXA(`osascript -l JavaScript` 读 System Events AX 树,macOS 自带零依赖)
- **协议形状**:照 ZCode CUA 开源契约(只借形状);**不引入** UI-TARS/Agent-S/OpenAdapt 运行时

## 架构(用户已拍板:双层插件 + 直接奔可用 + scope:code + display 后置)

```
plugins/computer-use/        零能力 bundle(市场可见门控,FORM-11 flow 同款,~10 行)
features/computer-use/       代码级插件(全部重活)
  ├ plugin.ts                PluginDefinition;mounted 期查 plugins 注册表安装态 → ctx.tools.register
  ├ tools/                   8 个工具(name=mcp__computer-use__<action>,scope:"code")
  ├ executor.ts              ComputerUseExecutor 接口缝(A→B 档换实现不换协议)
  ├ executor-macos.ts        nut-js(截屏/注入)+ JXA(AX 树)+ 黑帧检测
  ├ ax-tree.ts / target.ts / lease.ts / budget.ts   纯逻辑,TDD 主战场
  └ service.ts               ComputerUseService(lease/预算/actionSent/受信 targetApp)
profiles/server.ts           清单一行
```

**并行安全(零改动清单)**:不改 `apps/server/src/agent/**`、不改 `apps/web/**`、不改 zcode 原件、不改 permissions。依据(已探明):ctx.tools→`list(preset)`→bridge 自动进主 agent;工具名全链透传直达已照搬 cua renderer 并自动聚合;`/^mcp__/` 前缀天然 ask 档;子代理白名单制默认隔离;display 投影与 events.ts 契约改动**全部后置**(里程碑 1 连 packages/shared 的 WS 事件都不动,截图走输出内 base64 data URI,`CuaScreenshotSection` 深度识别)。

## 实施步骤(TDD 垂直切片,一步一提交一步一测试;新分支,显式 `git add <path>`)

1. **纯逻辑内核(测试先行,零原生依赖)**
   - `ax-tree.ts`:AX JSON → 元素行文本 + structuredContent;≤32KB 裁剪保祖先 → 验证:单测(fixture 进 → 形状出)
   - `target.ts`:元素索引/坐标解析 + raster 帧绑定校验(过期帧→`element_stale`,越界坐标拒绝) → 单测
   - `lease.ts`:run 级单会话独占(第二个 run→`controller_busy`)、释放、actionSent 语义 → 单测
   - `budget.ts`:内联/落盘阈值、黑帧检测谓词 → 单测
2. **插件装配(stub 执行器)**:`features/computer-use/plugin.ts` + `executor-unavailable.ts`(显式 unavailable,fail loud)+ profiles/server.ts 加一行 → 验证:compose 测试;code preset 可见、design 不可见;子代理 toolbelt 不含
3. **零能力 bundle**:`plugins/computer-use/`(package.json 声明 kenfutwork.bundle + index.js 空 apply,照 `plugins/flow/` 结构)+ features 层 mounted 期按安装态门控注册 → 验证:module-scan 通过;市场可见/可装/可卸
4. **macOS 执行层**:`apps/server` 加依赖(`@computer-use/nut-js`、`@computer-use/node-mac-permissions`,executor 内动态 import,非 mac 不加载);`executor-macos.ts`:list_apps/list_windows/get_app_state(JXA)/screenshot(nut-js 窗口级裁剪+黑帧检测)/click/type(nut-js,Unicode 剪贴板先备份后还原)/request_access(权限查询+黑帧双源判定)/stop_computer_control → 验证:JXA 读计算器树手动核对;单测覆盖解析层
5. **治理键 + 技能**:`packages/shared/src/governance.ts` 五键(computerUseActionTimeoutMs/ObserveMaxBytes/ScreenshotMaxBytes/MaxActionsPerRun/SessionMaxMs,全链 DEFAULTS/LIMITS/clamp/env/schema);内置 `computer-use` 工作区技能(a11y 优先/坐标纪律/错误恢复,走 workspace-skills 机制)
6. **记账**:`docs/日志.md` 同提交记回执;`ComputerUse集成设计.md` 状态推进;`pnpm test:docs` 过

## 验收门(里程碑 1 完成 = 全部通过)

- **真机演示**:Code 模式对话「打开计算器,按 7」全回路——观察树文本进上下文、逐动作审批 ask(可 forever 记忆)、元素索引点击生效、截图(输出内 base64)渲染、连续 `mcp__computer-use__*` 行自动聚合成贴底操作组
- **负向**:无 TCC 权限时工具报 `permission_denied` + 引导(不信 getAuthStatus 单边结论);design run 看不到工具;子代理派发不可用;executor 缺席时显式 unavailable 不摆空壳
- **工程**:`pnpm --filter @kenfutwork/server test` + `pnpm typecheck` 全绿;compose/契约单测齐;卸载 bundle 后工具消失

## 风险与对策

- JXA 读大树慢 → 限深 + 治理键超时;P2 上 delta 观察树(state_id/changes,UI 已能消费)
- 输入注入 TCC 主体 = 服务进程(dev 形态是 dev server,桌面形态是内嵌 server)→ request_access 文案按运行形态给引导
- 原生包体积(~36MB)→ executor 动态 import,非 macOS 平台零加载
- 与 Agent 核心优化的冲突面仅 profiles/server.ts 一行 + governance.ts 增量,均为加法
