# KenFutWork 子代理与后台任务体系 v1（Design/Code 双模式）实施方案

## 一、已拍板决策（实现时登记《改造计划》§6 为 DEC-14…DEC-19）

- **DEC-14 分阶段架构**：v1 = in-process 深化（并行 fan-out + 后台任务 + 完成通知），契约字段按 v2 一步到位命名（`taskId`/`agentName`/`parentRunId` 预留）；v2 独立子 run + continuable + 面包屑另立项。
- **DEC-15 统一后台原语**：子代理与 Code 长命令共用一套「后台任务注册表 + 完成通知注入 + run 持有至全部结算」；run 取消连带取消全部后台任务。
- **DEC-16 内置清单按 preset**：design = `batch_image` / `video_generate`（收编）/ `planner`；code = `explore` / `review`（均只读）；主 agent 按任务量自主判断派生，工具描述写清「何时该用」（给 LLM 最大自由度 + 给足工具）。
- **DEC-17 治理默认档**：派生深度 1（禁孙代理）、并发上限 4、plan 模式放行只读子代理白名单（现状是 task 被整拦，要改）、子代理 usage 归父 run（DEC-6 采集点不变）、失败结果带 next_step 恢复指引（kimi 式）。
- **DEC-18 禁止硬编码 tunables（全仓）**：运行时可调数值（深度/并发/重试/超时等）代码里只许 `DEFAULTS` 常量 + zod schema 校验，覆盖入口 = `workspace_settings` 缝 + env 兜底；本规则写入 AGENTS.md 硬约束。含 LLM 请求重试：次数可调 + 无限重试 opt-in（治上游 429 卡死，kimi `KIMI_CODE_INFINITE_RETRY` 同款心智）。
- **DEC-19 事件归因以 metadata 为准**：`parent_ids` 在 @langchain/core 1.2.12 不存在；归因用 deepagents/自建 runtime 写入的 `metadata.lc_agent_name` + `ls_agent_type:"subagent"`；顺带修 stream-adapter 嵌套模型流泄漏进主消息流的 bug（`on_chat_model_stream` 现在不按子代理 metadata 过滤）。

## 二、可行性结论（已核 deepagents 1.14.0 / langchain 1.5.11 实际源码）

- 并行 fan-out **原生可行**：每 tool_call 独立 Send、PregelRunner 并发执行，`maxConcurrency` 默认不限。
- 后台+通知 **需自研、机制成立**：`beforeModel`/`wrapModelCall` 钩子可注入消息（mailbox 方案）；必须剥离父 abort signal（后台任务自有 AbortController）+ promise 必须 `.catch`；纯内存（run 持有结算后语义自洽，进程重启 = run 本身已亡）。
- 取消传播原生可行；子代理天然不共享 checkpointer（v1 不持久化子代理）。
- **关键架构裁定**：弃用 deepagents 内置 `task`/`subagents` 参数（schema 只有 2 字段、同步阻塞、per-spec 固定），**自建 SubagentRuntime**——`createAgent({model, systemPrompt, tools, middleware, name})` 直接组子代理（参照 deepagents createSubAgent 的装配方式），工具面/中间件按 spec 显式给。这正好落成 dsh 式完整能力缝：Definition（TS 声明注册表）+ Provider（in-process runtime，v2 增独立 run provider）+ Consumer（task/task_output 工具）。
- 轮末闸门不依赖 deepagents：runtime 层 continuation 循环（run 结束时若后台任务未结算 → 注入提醒消息重入同一 thread 再跑一轮），现成先例是 run-retry 的重跑路径。

## 三、实施序（新分支 `zcode/子代理与后台任务v1`，一步一提交，TDD 接缝先行）

**PR-1 契约 + 设置 + AGENTS.md 规则**
- `packages/shared`：stream 事件 `tool.started/completed` 增可选 `agentName`；消息块新增 `task_notification` 块类型（`{taskId, kind, label, status, summary, nextStep?}`，单形状无旧数据兼容）；settings 契约扩展。
- server `features/settings`：`workspace_settings` 增列 `subagentMaxDepth=1`、`subagentMaxConcurrency=4`、`llmRequestMaxRetries=10`、`llmInfiniteRetry=false`、`executeTimeoutMs=120000`（DEFAULTS 常量 + zod 校验 + env 兜底，复用现有 findAgentMaxRetries 先例）。
- AGENTS.md 增「运行时 tunables 禁止硬编码」硬约束小节。

**PR-2 后台任务原语（server agent runtime）**
- 新 `agent/background-tasks.ts`：TaskRegistry 纯函数状态机（注册/并发闸门超限返回可读错误/结算/abortAll/drainedNotifications）。
- 自有 `task` 工具（scope shared，schema `{subagent_type, description, background?}`）+ `task_output` 工具（block 轮询读结果）；深度 1 = 子代理工具面不含 task。
- mailbox 中间件（beforeModel 注入 `<task-notification>` XML user 消息，zcode 同款形态）+ runtime continuation 循环（轮末闸门）。
- `execute_background` 工具（scope code，共用 LocalShellBackend，输出内存缓冲，task_output 可读）。
- LLM 重试进 settings（langchain maxRetries + 无限重试包装）。
- 取消路径：run cancel → registry.abortAll()。

**PR-3 内置子代理清单 + 归因修复（server）**
- `sub-agents.ts` 重写为 Definition 注册表（`{name, label, description, preset, readOnly, tools, systemPrompt}`）；video_generate 收编。清单：design=planner（inspect_canvas/project_search/write_todos）、batch_image（generate_image）、video_generate；code=explore（ls/read_file/glob/grep/project_search）、review（+ diff_files/preview_file）。
- `task` 工具描述按 preset 动态生成可用清单（zcode buildAgentProviderDescription 同款）；plan 模式白名单按 Definition.readOnly 放行。
- 失败 ToolMessage 附 next_step 指引；stream-adapter 归因改 `metadata.lc_agent_name` + 修嵌套模型流泄漏。

**PR-4 前端（web）**
- 通知行渲染（结合两家：zcode 扁平 task-notification 行 + dsh 的 notice 与 agent 消息区分形态）；subagent-directory 改用 `agentName` 识别 + 后台任务实时状态；轨迹账本/时间轴纳入后台任务行；设置页「Agent 治理」区（深度/并发/重试/无限重试/超时）。

**PR-5 文档收尾**
- 设计稿 `docs/方案设计/子代理与后台任务设计.md`（登记 docs 地图）；《改造计划》§6 登记 DEC-14…19、§4.2 增 `subagentRuntime` key 行；`docs/日志.md` §五十五 记账。

## 四、TDD 接缝（本计划批准即视为接缝确认）

① TaskRegistry 状态机纯函数（注册/并发拒绝/结算幂等/drain/abortAll）② task 工具 handler（派生、深度拒绝、plan 只读白名单、preset 清单过滤）③ mailbox 注入纯函数（drain→消息块格式）④ runtime continuation 循环（fake 子代理 promise：先结算后收尾/收尾时仍挂起/取消）⑤ settings 新字段读写与默认值 ⑥ shared 契约 schema（新块类型/agentName 字段）⑦ web subagent-directory 与 trajectory 纯函数（agentName 识别、通知行、账本行）。红→绿逐切片，禁止横切。

## 五、验证门

每 PR：`pnpm test` + `pnpm typecheck` + `pnpm lint`。行为测试必含：双子代理并行 fan-out、超并发第 5 个被拒且可读、深度 2 拒绝、plan 模式只读放行/可写拒绝、run 等待后台结算后才 terminal、cancel 清理后台任务、后台 usage 归父 run、嵌套事件不漏进主消息流。

## 六、明确不做（v2 及以后 / 另立项）

子代理独立持久化与 continuable、面包屑/独立会话跳转、用户自定义 markdown profile、ACP/跨产品委托 provider、SRT 沙箱档位（多端 §7 另一条赛道，本设计只消费现有 sandbox-dir/backend 抽象）、命令输出流式转发。
