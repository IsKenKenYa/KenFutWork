# 「契约权威化」实施方案（治理三次同源事故）

## 根因与对策总纲
三次事故（env 前缀、包名、零字节占位）共性 = **契约只存在于代码里：无单一权威登记处、无机械校验、并行修改无报警**。对策 = 「一张机械权威表 + 一条新门禁（R1–R4）+ 两条守则 + 样例互锁」，全部复用仓库现有基建模式（check-docs 的「权威表 vs 全仓扫描」、supabase 的「棘轮基线」、docs 的 fixture 正/负路径自校验）。

## 交付物

### 1. env 权威机械表 `tests/env-registry.json`（新建）
结构（首版内容直接采用探索盘点的全量数据，约 60 个变量名）：
```json
{ "vars": { "KENFUTWORK_EMBEDDED_PG": {
      "surface": "server",          // server | shell | script | test | build
      "readers": ["apps/server/src/config/env.ts"],
      "inExamples": true, "status": "active", "note": "桌面内嵌 PG 开关" } },
  "legacy": { "LOOMIC_MCP_SERVERS": { "allowedIn": ["supabase/migrations/20260914250000_mcp_servers.sql"],
      "reason": "已执行迁移的历史陈述，不可改" } } }
```
- 覆盖：服务端 27 个 KENFUTWORK_*、桌面壳 3 件套 + 注入 6 项、desktop/*.ts 8 个、scripts/测试门控约 15 个、无前缀第三方约定（OPENAI_API_KEY/PORT/HOST 等标 `external: true`）
- `LOOMIC_DATA_DIR` 注入名（server_handle → 子进程）登记为 active（服务端 env.ts 实读该名经兼容映射）

### 2. 机械门禁 `scripts/check-env.mjs`（新建，仿 check-docs.mjs 模式）
导出 `checkEnv({rootDir}) → {errors, files}`，四条规则：
- **R1 登记**：扫描面（apps/server/src、apps/desktop/{src-tauri/src,dev.sh}、apps/web/src、packages/*/src、scripts/*.mjs、.env.example、turbo.json、apps/server/Dockerfile）内所有 `KENFUTWORK_*/LOOMIC_*` 引用必须在表内；表外 → fail
- **R2 旧名白名单**：`LOOMIC_*` 只允许出现在 legacy.allowedIn 文件 + env.ts 兼容 shim 函数体（豁免清单硬编码，仿 MAP_EXCLUDE_FILES）
- **R3 读者存活**：active 条目的 readers[] 每个文件必须仍含该名（读者消失 = 契约漂移，即三次事故的直接形态）
- **R4 样例互锁**：.env.example 的 KENFUTWORK_* 条目 ⊆ registry；registry 中 inExamples=true 的条目必须在样例中出现

双入口：`package.json` 新增 `test:env: node scripts/check-env.mjs`；`tests/workspace.test.mjs` 挂 node:test 用例（真仓通过 + 仿 withDocsFixture 的临时 fixture 验证 R1–R4 各自正/负路径）。

### 3. 样例与残留全量修正（互锁数据修复）
- `.env.example`：修 2 处坏名（`KENFUTWORK_VIDEO_JOB_TIMEOUT_MS`→`VIDEO_JOB_TIMEOUT_MS`、`KENFUTWORK_VIDEO_POLL_DELAY_SECONDS`→`VIDEO_POLL_DELAY_SECONDS`，代码读无前缀）；删 `KENFUTWORK_MCP_LIFECYCLE=process` 死条目（改为门控 `=1` 用法说明）；补缺失 6 项（PG_BIN_DIR、DATA_DIR、AGENT_FILES_ROOT、DESKTOP_SERVER_CWD、CHROME_PATH、IMAGE_PROXY_ALLOWED_HOSTS）
- `apps/web/.env.local.example`：整文件替换为 `NEXT_PUBLIC_SERVER_BASE_URL=` 单条目（SUPABASE 死样例清除）
- `apps/server/.env.local.example`：首行加显眼「已废弃，看根 .env.example」指针
- 用户可见残留 3 处：`scripts/开发库临时集群.mjs` 的 LOOMIC_DATABASE_URL 打印命令×3、`docker/pg-dev-shim/Dockerfile` 注释、`.gitignore` 注释（LOOMIC_MCP_SERVERS→KENFUTWORK_MCP_SERVERS）
- `.gitignore` 补 `.loomic-data/`（唯一缺口）

### 4. 两条守则 + 文档登记
- **AGENTS.md**「可维护性」节新增：**资源可用性三重校验**——凡以 exists()/metadata() 判定资源「可用」并据此 spawn/加载，必须同时校验 非零字节 +（Unix）可执行位 +（进程）存活；正范例指向 `postgres.ts readRunningCluster`、反范例（事故）指向 `lib.rs bundled_server_exe` 与 `desktop/postgres.test.ts` 回归
- **AGENTS.md**「提交纪律」新增：**桌面冷启动冒烟**——碰 `apps/desktop/**` 或合并 main 后，提交前必跑 `pnpm desktop` 至服务端健康（≤60s 可判）；机制由 src-tauri 12 个 cargo 单测机械覆盖
- **改造计划.md §4.2**（ctx key 表属主）旁加一句登记：**env 名权威表唯一属主 = `tests/env-registry.json`**，新增 env 先登记再使用（门禁 R1 强制）；`.env.example` 为人读面
- `AGENTS.md` 环境契约处同步指针

## 执行顺序
1. 修 `.env.example` 坏名/死条目/缺失（门禁 R4 的前置）
2. 写 `tests/env-registry.json` 首版（盘点数据录入）
3. 写 `scripts/check-env.mjs` + `tests/workspace.test.mjs` 挂双用例 + `package.json` 加 `test:env`
4. AGENTS.md 两条守则 + 改造计划 §4.2 旁登记
5. 残留清理（开发库临时集群.mjs×3、Dockerfile 注释、.gitignore×2）
6. 四门禁 + `pnpm test:env` + 提交（两个 commit：`feat(gate): env 权威表与机械门禁`、`chore(env): 样例修正与残留清理`），推送 啃啃在开发

## 验收标准
- `pnpm test:env` 通过；故意改名任一 KENFUTWORK_* 引用 → 门禁红（fixture 负路径固化此行为）
- `pnpm test`（含 workspace 门禁）/ typecheck / lint / build 全绿
- `.env.example` 无「写不生效」条目；全仓无未登记 env 引用；LOOMIC_ 残留仅在白名单
- 不合并 main、只推 啃啃在开发（沿用现行纪律）

## 风险与边界
- registry 录入量大（~60 名）但数据已在手（探索报告 A 节直接转录）
- `withLegacyEnvNames` 兼容 shim **保留不动**（向后兼容是它的职责），门禁只管「新代码不许再引入 LOOMIC_」
- 不动 turbo.json globalEnv 之外的缓存配置；不加 GUI 冒烟进 test 管道（flaky）
- 服务端 env.ts 的 4 处 LOOMIC_ 残留与 .env.example 的 SUPABASE 说明行按盘点标注为「有意保留」，入 legacy 白名单
