# 运行形态与启动方式

> **角色**：参考——回答「KenFutWork 到底有几种启动方式、各自的身份（认证）与数据落在哪」。改启动链路（dev.sh / 桌面壳 / 健康检查）前先读本文；改完同步更新。

## 0. 一句话模型

**服务端只有一份代码，形态由启动 env 决定**。两个开关决定一切：
- `KENFUTWORK_AUTH_DRIVER`：`managed`（邮箱口令，SaaS/自托管/Web dev 默认）| `local-trust`（本机用户免登录，**仅桌面壳注入**，回环 + 回环 Origin 双判定）；
- 数据/队列：`.env.local`（dev/桌面 dev：内嵌 PG 54329）| 桌面打包（数据目录，PG 端口自动挑选）| 自托管（外部 PG + PGMQ）。

## 1. 启动方式清单

| # | 形态 | 启动命令 | 服务端来源 | 身份（auth driver） | 数据 / 队列 | 窗口/UI |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | **桌面打包版**（DMG/.app） | 打开 .app | 随包快照 `server.cjs`（打包形态的交付物） | `local-trust`（壳注入 `desktop_env`） | 数据目录 + 内嵌 PG（端口自动）+ in-process 队列 | server 托管 UI（回环 http） |
| 2 | **桌面 dev**（`pnpm desktop` / `dev.sh`） | `bash apps/desktop/dev.sh` | **源码**（`dev:server` = `node --watch --import tsx`，改文件自动重载） | `local-trust`（壳在 dev 拉起 env 里注入） | `.env.local`（内嵌 PG 54329） | web dev :3000（devUrl） |
| 3 | **Web dev**（`pnpm dev`） | `pnpm dev` | 源码（tsx）:3001 + worker | `managed`（`local@kenfutwork.local` / `kenfutwork-2026`） | `.env.local`（内嵌 PG 54329）+ PGMQ | 浏览器 :3000 |
| 4 | **自托管 / SaaS 后端**（原计划形态，FORM-3 认证档位待拍板） | Docker / 生产流水线 | 构建产物 | `managed`（注册/登录） | 外部 PG + PGMQ | server 托管 UI 或独立前端 |

辅助进程：`dev:worker`（队列 worker）是 #3 的伴生进程，不是独立形态。

## 2. 端口与互斥（踩坑记录）

- **3001 归当前形态独占**：桌面壳对「已健康的 3001」会原样复用且**不注入桌面身份**——残留的旧服务端（旧快照 / `pnpm dev` 的 managed 服务端）会让桌面 dev 出现登录页或旧代码。`dev.sh` 已改为启动时**无条件清掉 3001 占用者**再拉起。
- **`target/**/app/server.cjs` 快照在 dev 构建中永不执行**（`start_server` 按 `debug_assertions` 门控）：快照是上次打包的旧产物，dev 的意义就是跑最新源码。
- **内嵌 PG 单进程**：dev（54329）与桌面打包（自动端口）同数据目录但不同集群参数，同一 `-D` 目录不能双跑；切换形态先退另一形态的实例。
- 3000 的 web dev server 可安全复用（Next dev 热重载源码）。

## 3. 身份口径

- 桌面（打包 + dev）：`local-trust` → 固定本机账号（本机用户），免登录；数据即工作区边界。
- Web dev / 自托管 / SaaS：`managed` → 邮箱口令；dev 测试账号见根 README「测试账号」表。
- BYOK provider_instances 凭据加密落本机，不随账户迁移。
