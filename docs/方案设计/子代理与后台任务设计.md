# 子代理与后台任务体系 v1 设计（Design/Code 双模式）

> **角色**：方案稿——v1 已按本稿落地（2026-09-26/27，分支 `zcode/子代理与后台任务v1`，`DEC-14`…`DEC-19`）；v2（独立子 run + continuable + 面包屑）另立项。
> 决策引用一律用 ID（`DEC-14`…`DEC-19`，结论与理由见《改造计划》§6/§6.2）；本文不复述决策理由，只写**机制、接线与验证**。

## 1. 架构总览（能力缝三元组）

```
Definition  agent/subagent-definitions.ts   5 个内置定义（preset/readOnly/tools/systemPrompt）
                                        ↕ 按 preset 过滤，界面清单同源
Provider    agent/subagent-tools.ts + deep-agent 装配（childRunner：createAgent 组子代理）
                                        ↕ task / task_background / task_output 三工具
Consumer    runtime（注册表生命周期 + 轮末闸门续轮）+ 前端目录/通知行/轨迹账本
```

- **深度治理是结构性的**（`DEC-17`）：子代理经 `createAgent` 组装，不挂任何派发工具——深度上限 1 不靠提示词约定。
- **只读子代理无执行能力是结构性的**：explore/review/planner 的文件工具走 `createFilesystemMiddleware({tools: 白名单})`，白名单不含 execute。
- **plan 档派发门**（`DEC-17`）：`evaluateToolPolicy` 按目标定义只读性放行 `task`/`task_background`（`detail.subagentReadOnly` 穿透 ToolGate 全链）；`task_output` 恒只读；solo 全拒。
- **并行 fan-out**：一条 AIMessage 多个 task 调用 → langchain Send 原生并发（已核 deepagents 1.14 源码，PregelRunner 并行）。

## 2. 统一后台任务原语（`DEC-15`）

- `agent/background-tasks.ts`：TaskRegistry 状态机——`register`（并发闸门，超限返回**模型可读**拒绝理由）/ `settle`（幂等，首次获胜）/ `drainNotifications`（按结算顺序出队并清空）/ `hasPending`（轮末闸门唯一判据）/ `abortAll`（逐个调 abort 回调 + canceled 结算，迟到结算不复活）。每 run 一个实例，随 run 生灭（WeakMap 挂 run 对象，cancelRun / finally 兜底 abortAll）。
- 消费方两个：后台子代理（`task_background`）与 Code 长命令（`execute_background`）。
- **通知双通道同源**：结算 → registry 通知队列 → ① mailbox 中间件（`beforeModel` 把已结算未消费的通知以 `<task-notification>` XML user 消息注入下一轮模型输入）② `task.notification` 流事件推前端（`task_notification` 消息块落库转录）。模型可见与用户可见是同一份事实。

## 3. run 生命周期：轮末闸门（continuation 循环）

模型收尾（run.completed）时若 `hasPending()`：吞掉该事件（状态/持久化保持 running 口径）、以通知文本为新 HumanMessage 重入同一 thread 继续跑（复用 run-retry 同款重跑路径）；全部结算后的 completed 才放行。保证：**通知必达、模型必须消化后台结果、usage 归属不变**。取消随时可用（abort → abortAll 连带清理）。

## 5. 治理与设置（`DEC-17`/`DEC-18`）

- 默认值/护栏唯一属主：`packages/shared/src/governance.ts`（`AGENT_GOVERNANCE_DEFAULTS`/`LIMITS`/clamp/env 解析）。
- 五项：`subagentMaxDepth=1`、`subagentMaxConcurrency=4`、`llmRequestMaxRetries=10`、`llmInfiniteRetry=false`、`executeTimeoutMs=120000`。
- 覆盖入口：设置页「Agent 治理」页签（`agent-governance-section.tsx`，PATCH `workspace_settings`）与 env 兜底（`KENFUTWORK_*`，非法值忽略）；优先级 **库值 ?? env ?? DEFAULTS**，读侧钳回护栏。
- LLM 请求重试：`llm-retry-middleware.ts`（wrapModelCall 级，内建与 BYOK 模型统一生效）——只重试可重试错误（429/5xx/超时/网络），指数退避 30s 封顶，信号中止即停；无限重试为用户显式开启。

## 6. 事件与归因（`DEC-19`）

- 归因读 `metadata.lc_agent_name`（自建派发与 deepagents 同写）；stream-adapter 给 `tool.started/completed` 事件带可选 `agentName`，前端目录/轨迹据此归属。
- 修复：子代理模型流（`on_chat_model_stream/end` 携带子代理 metadata）不再漏进主 assistant 消息流；usage 照算归父 run（`DEC-6` 采集点不变）。
- 契约新增：`task.notification` 流事件、`task_notification` 消息块、`tool.*`/工具块 `agentName`（`packages/shared/src/events.ts`、`contracts.ts`）。
