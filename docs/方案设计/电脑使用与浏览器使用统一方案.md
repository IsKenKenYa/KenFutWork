# 电脑使用与浏览器使用统一方案

> 角色：**方案稿**（整合 ZCode、Codex、nomifun、toonflow 的可用做法，形成一条实施路线）。
> 关联：《ComputerUse集成设计》（CU-A…D 已确认）、《改造计划》§4.2（服务 key 唯一清单）与 §4.10（扩展点目标机制）、`packages/shared/src/governance.ts`（运行时可调数值唯一属主）。
> 状态：§8 记录已确认事项；按 §5 的切片逐批实施，每批回执写《日志》。

## 1. 目标

1. **电脑使用看得准、点得对、说得清**：观察结果可信（全黑、遮挡、权限缺失、元素替换都能识别）、动作不误伤（帧绑定、元素身份、可能已发出）、用户知道当前由谁在操作。
2. **浏览器使用同一套规则**：观察、寻址、动作、再观察的顺序与电脑使用一致；元素寻址从填写 CSS 选择器改为使用带编号的元素引用；启动与连接可重复；默认在后台运行，用户要求查看时才显示。
3. **两条轴共用一套扩展点与一个治理入口**：能力接口形状一致，运行时可调数值只写在 `governance.ts`，不再各写一份。

完成条件（可验证）：

- 电脑使用的四个失败场景（无屏幕录制权限、窗口被遮挡、目标最小化、元素被替换）各自返回可读原因与下一步动作，且不把不可信像素交给模型。
- 浏览器的一次完整回路（打开页面、读取带编号的元素、按编号点击、再次读取）在真实页面上跑通，且用过期编号会被拒绝。
- 两条轴的观察、寻址、动作结果、控制权四条规则在代码注释、工具描述与测试名称里用同一套说法。

不在本期范围：

- 用原生浏览器视图替换现有 CDP 通道；本期只定义后端接口，为将来替换留出位置。
- Windows 与 Linux 的电脑使用执行器。
- 引入 Playwright 依赖；浏览器侧用 CDP 自带能力实现等价寻址。

## 2. 现状与差距

### 2.1 电脑使用（macOS，`apps/server/src/features/computer-use/`）

| 模块 | 现状 | 差距 |
| --- | --- | --- |
| 观察 | JXA 读取 System Events 树；`screencapture -R` 取屏幕矩形 | 每次动作重新遍历整棵树；元素身份只比较角色与标题 |
| 动作 | 元素用 `AXPress`；坐标用全局 `CGEventPost`，动作前激活窗口 | 会抢占前台；动作位置依赖当前前台应用 |
| 会话 | 运行级租约、动作计数、会话时长、已发出标记 | 已在上一批完成 |
| 权限 | 辅助功能、屏幕录制、输入事件、自动化四项探测 | 设置页只显示两项；未触发系统原生授权框 |
| 反馈 | 无屏幕指示 | 用户看不到操作位置 |

### 2.2 浏览器使用（`apps/server/src/features/browser/`）

| 模块 | 现状 | 差距 |
| --- | --- | --- |
| 启动 | 固定端口、独立资料目录、HTTP 探测就绪 | 端口冲突与代理环境容易失败 |
| 观察 | 渲染后 DOM 的文本与可交互元素，附定位提示 | 没有稳定编号，模型只能自行拼选择器 |
| 动作 | 选择器或坐标点击、输入文本、按键 | 选择器失败率高；坐标缺少与截图的绑定 |
| 面板 | 常开画面流 | 未查看时也占用资源 |
| 多标签 | 单会话单页 | 用户与 agent 共用标签时没有占用规则 |

### 2.3 参考实现中可采用的做法

| 来源 | 做法 | 采用方式 |
| --- | --- | --- |
| Codex 内置浏览器 | `tab.ax` 优先、定位器次之、坐标最后；`write()` 默认返回差异；默认后台，`visibility` 控制显示；`claimTab` 声明占用 | 作为浏览器的四条行为规则来源 |
| Codex 电脑使用 | 只做可访问性动作，按住拖动与组合键的缺口如实报错 | 动作能力不足时明确拒绝 |
| ZCode 电脑使用 | 窗口级事件投递、防抢前台开关、元素引用带归属 | 作为将来后端接口的能力项 |
| ZCode 权限引导 | 打开对应设置面板，浮动窗口把应用图标拖进列表，授权后重启辅助进程 | 设置页引导的改进方向 |
| nomifun | 启动 Chromium 用随机端口并读取 `DevToolsActivePort`；按使用者与会话隔离资料目录 | 启动与连接的改进方式 |
| toonflow | 观察结果带元素编号与句柄映射，画面用 CDP 推流 | 元素编号的直接参照 |

## 3. 统一结构

### 3.1 两个能力接口，同一形状

```
ComputerUseExecutor（已有）      BrowserBackend（本期新增）
  accessStatus()                   status()
  listApps/listWindows             tabs()/open()/close()
  observe()                        snapshot()   → 树或文本 + 元素编号
  capture()                        screenshot() → 帧编号 + 边界
  act()                            act()        → 已发出标记
  stop()                           stop()
```

`BrowserBackend` 的接口定义写在 `apps/server/src/features/browser/backend.ts`，本期只提供一个实现 `cdp`（包住现有 `cdp-session.ts`），消费方是工具注册与面板路由。将来增加 `native-webview` 实现时，工具面与事件形状不变。

### 3.2 四条共用行为规则

1. **观察优先给文字与树，像素作补充**。像素不可信时必须说明原因，不把全黑图或遮挡内容交给模型。
2. **元素引用优先，坐标只对最近一帧有效**。编号在动作后失效，必须重新观察。
3. **动作结果区分已发出与未发出**。已发出的动作只允许重新观察后决定，不允许直接重试。
4. **同一时刻只有一个控制者**。电脑使用用控制器租约，浏览器用标签占用，两者都向用户透出当前持有方。

这四条同时写进工具描述、接口注释与测试名称，成为两条轴的共同说明。

### 3.3 治理入口

新增运行时可调数值统一进 `packages/shared/src/governance.ts`：

| 名称 | 用途 | 默认值来源 |
| --- | --- | --- |
| `browserActionTimeoutMs` | 浏览器单次动作超时 | 与 `computerUseActionTimeoutMs` 同档 |
| `browserSnapshotMaxBytes` | 快照文本上限 | 32 KiB |
| `browserScreenshotMaxBytes` | 浏览器截图上限 | 256 KiB |
| `browserMaxActionsPerRun` | 单次运行动作上限 | 200 |

现有 `fetch-page.ts` 内的 8 秒与 512 KiB 是静态抓取的一次性限制，保留原处并保留行内注释，不并入治理表。

## 4. 改进项与验收标准

### 批次 A：电脑使用观察收尾

| 项 | 改动 | 验收标准 |
| --- | --- | --- |
| A1 全黑检测接线 | 工作区已接线，补回归用例 | 撤销屏幕录制权限时，单独截图返回 `permission_denied`；带截图观察返回树与警告 |
| A2 遮挡判定 | 工作区已接线，补回归用例 | 目标被同层窗口覆盖超过 2% 时返回 `occluded`，并给出遮挡方名称与进程号 |
| A3 自动化权限探测 | 工作区已接线，补回归用例 | 未授权时权限查询包含「自动化」，提示指向对应设置 |
| A4 元素身份 | 身份比较增加进程号、窗口编号、位置尺寸与动作集合 | 同位置换成另一个同角色同标题的控件时，旧编号动作返回 `element_stale` |
| A5 动作脚本直达 | 观察时记录元素路径，动作按路径定位，不再遍历整棵树 | 同一棵树连续 20 次动作的总耗时下降一半以上（本机实测记录在回执） |

### 批次 B：浏览器观察与寻址

| 项 | 改动 | 验收标准 |
| --- | --- | --- |
| B1 元素编号 | 快照时给可交互元素写入 `data-kenfutwork-ref` 属性并返回编号 | 同一次观察内编号稳定；页面跳转后编号全部失效 |
| B2 按编号动作 | `browser_act` 接受编号；编号不存在或已过期时报错并提示重新观察 | 用旧编号点击返回 `element_stale`；用当前编号点击命中目标 |
| B3 可访问性树 | 增加 `Accessibility.getFullAXTree` 通道，作为首选观察 | 树可用时快照包含角色、名称、编号；不可用时退回文本快照并说明 |

### 批次 C：浏览器启动与连接

| 项 | 改动 | 验收标准 |
| --- | --- | --- |
| C1 随机端口 | 启动参数用 `--remote-debugging-port=0`，读取资料目录下的 `DevToolsActivePort` | 连续启动 5 次都能连上；不依赖 HTTP 探测 |
| C2 失败分类 | 连接失败按端口占用、权限拒绝、浏览器缺失、启动超时分别给出原因 | 每种失败都有对应错误码与一句处理办法 |

### 批次 D：浏览器可见性与占用

| 项 | 改动 | 验收标准 |
| --- | --- | --- |
| D1 默认后台 | 画面流默认不启动；面板可见或用户要求显示时才启动 | 未打开面板时不产生截图帧；打开后 2 秒内出画面 |
| D2 标签占用 | 用户与 agent 共用标签时，先取得占用再操作；冲突时报当前持有方 | 第二个调用方取得同一标签时被拒绝，并看到持有方 |

### 批次 E：权限引导

| 项 | 改动 | 验收标准 |
| --- | --- | --- |
| E1 系统原生授权框 | 屏幕录制未授权时调用 `CGRequestScreenCaptureAccess`，返回失败再打开设置面板 | 首次使用出现系统授权框；拒绝后设置页仍可打开 |
| E2 第三项权限 | 设置页增加「自动化」一行，含状态与打开设置入口 | 四项权限状态与探测结果一致 |
| E3 未完成授权 | 权限查询返回「等待中」，工具描述要求继续调用而不是结束回合 | 用户在设置页停留期间，模型再次调用可拿到最新状态 |

## 5. 按测试驱动开发推进

按 `tdd` 技能的纵向切片：一次一个测试，一个测试只推进一步实现；不先写一批测试再写一批代码。每个切片完成后立即运行该范围测试与类型检查，通过后再进入下一个。

### 5.1 先确认的接口与行为

- 接口：`BrowserBackend` 的方法名与返回形状；`browser_act` 增加编号参数；权限查询增加 `automation` 与 `pending`。
- 行为优先级：观察可信（A1–A3）→ 浏览器寻址（B1–B2）→ 启动可靠（C1）→ 可见性（D1）→ 权限引导（E1–E3）→ 元素身份与性能（A4–A5）→ 标签占用（D2）→ 可访问性树（B3）。


涉及 `packages/shared` 时追加：

```bash

```

### 6.2 本机走查（macOS）

| 场景 | 操作 | 期望 |
| --- | --- | --- |
| 无屏幕录制权限 | 撤销权限后调用截图 | 返回 `permission_denied` 与设置入口说明 |
| 窗口被遮挡 | 用另一个窗口盖住目标一半 | 返回 `occluded`，遮挡方名称正确 |
| 目标最小化 | 最小化后截图 | 返回 `occluded`，原因是不在当前屏幕 |
| 正常窗口 | 打开计算器走一次点击 | 观察、点击、再观察全部成功 |
| 首次授权 | 新装应用首次使用 | 出现系统授权框；拒绝后仍可打开设置面板 |

### 6.3 浏览器回路

在本机启动一个开发服务器页面，依次执行：打开页面、读取带编号元素、按编号点击、再次读取。第二次读取应看到点击后的状态；用第一次的编号再次点击应被拒绝。

## 7. 风险与处理

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 编号在页面跳转后仍被使用 | 点到错误位置 | 编号带页面代际，跳转即全部失效 |
| 随机端口文件在沙箱内不可读 | 无法连接 | 保留固定端口作为显式回退，并在错误里说明走了回退 |
| 遮挡判定把悬浮窗算作遮挡 | 误报 | 只统计同层、不透明的窗口，覆盖率阈值可调 |
| 元素身份加严后误拒绝 | 正常动作被拦 | 身份字段只取稳定属性；位置尺寸用容差比较 |
| 画面流默认关闭影响现有面板 | 用户以为坏了 | 面板打开即启动；首次切换时给出一次提示 |

## 9. 规范对应

| 规范要求 | 本文对应动作 |
| --- | --- |
| 新增行为挂扩展点，不改装配层 | 浏览器能力经 `BrowserBackend` 接口由插件注册工具；电脑使用继续走现有执行器接口 |

| 一步一提交并同步日志 | §5.3 的完成动作 |
