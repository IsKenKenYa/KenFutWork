### R4-3 设置「索引库」页（**代码库索引**） ｜ 未做
- **来源**：`设置添加使用统计以及索引相关内容.png`（侧栏「索引库」，红框）+ `索引库-代码库索引开关.png`（页面正文与开关文案）
- **口径（用户已确认）**：**代码库索引**，不是向量检索、也不是文档库。页面就一组 `代码库` 开关：
  1. **索引新文件夹** —— 「自动索引文件数少于 50,000 的新文件夹。」
  2. **索引存储库以实现即时搜索（测试版）** —— 「自动对仓库进行索引，以加快 Grep 搜索速度。
     所有数据均存储在本地。」
- **现状**：无。全仓无 `索引库 / indexLibrary` 相关代码。
- **架构含义（这条不是加个开关那么简单）**：
  - 索引对象是**工作目录**（Code 模式的沙箱目录），恰好与上一轮做的

  - 「所有数据均存储在本地」是要守的**隐私承诺**，也决定了索引文件放哪（沙箱目录内 vs 独立目录）。

> R6-1 的来源不是截图，而是真机故障：接入 `opencode`（`https://opencode.ai/zen/go/v1/`，Chat Completions）
> 报 `Request is missing x-opencode-session and cannot be routed efficiently.` —— 网关要求额外头才路由，
> 而现契约只有 `apiKey`（固定映射 `Authorization`）与 `baseUrl`，表达不了。规格与安全约束（保留头不可覆盖、
> 禁 CRLF 注入、头值只写不读）见 §4.8。
>
> **注意该头不是静态值**：`x-opencode-session` 自 2026-09-05 起是**会话亲和头**，值须在单个会话内稳定
> （用于路由亲和与提示词缓存命中）。所以 §4.8 的规格除了静态头，还要求头值支持白名单占位符
> （`{{sessionId}}` / `{{threadId}}`）——写死一个固定值会把所有会话钉到同一分片。

**走查抓到的两个真缺陷（已修）**：
1. **取消不落终态**（`5291954`）：点「停止本轮」后流确实停了（服务端 `ws.run_cancel` → 38ms 后
   `stream_done`），但 `agent_runs` 的行**没有任何终态**——`syncPersistedRunFromEvent` 只认
   `completed`/`failed`。行永远停在 `running`（只能等下次启动的孤儿对账收敛成 failed），
   且用户主动取消被记成失败。修法：前向迁移给 status 的 CHECK 加 `canceled` 一档 + 取消分支落库。
2. **文档区空态撒谎**（`a38b690`）：没选工作目录时永远显示「读取中…」（effect 因 canvasId 为空
   提前返回、状态停在 null）。现在分三态：没选目录 / 读取中 / 确实没有文档。

**顺带修掉两处本次改动路径上的问题**：
- 迁移校验和在 Windows 上的**假漂移**（`ab9adf1`）：按原始字节取 SHA-256 时，LF（仓库/CI）与
  CRLF（`core.autocrlf=true` 的工作区）不是同一个摘要，`migrate status` 会把一条一字未改的
  已执行迁移判成被改动并拒绝继续（实测 `20260916021900_provider_instance_headers`）。现在
  摘要先归一行尾再算，成为内容的函数（本机开发库据此一次性重算了账本）。
- **服务端重启后客户端永久「生成中」**（`a38b690`）：重启把在飞的 run 收敛成 failed，客户端不知道
  ⇒ 停止键常驻、输入框一直禁用，而那颗键指向已不存在的 run。现在 `resumeCanvas` 回执里没有
