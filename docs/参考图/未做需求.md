  2. **索引存储库以实现即时搜索（测试版）** —— 「自动对仓库进行索引，以加快 Grep 搜索速度。

## 十四、2026-09-16 五轮回执（三栏宽度：面板能灵活调大，但对话列有下限）

用户原话要点：**「需要限制一下，右侧面板拉大了，要是面板里的东西塞不下了，思考强度和权限改成图标，

**问题**：面板宽度此前写死 280–720，与视口和左栏状态无关。小视口下拖到上限会把中间的对话列挤到
几百像素（实测 1100 宽视口下挤到 **152px**），composer 那排控件互相压扁。

**口径（收在新模块 `apps/web/src/lib/panel-layout.ts`，纯函数 + 单测）**：

| 数 | 值 |
| --- | --- |
| 对话列最小可用宽度 | **420**（低于它宁可让左栏让位） |
| 面板上限 | `min(900, 视口 − 左栏 − 420)`（左栏收起按图标栏 48 算） |
| 对话列宽度 | `视口 − 左栏 − 面板`（**算**而不是量 DOM，见下） |
| 紧凑阈值 | 对话列 < **620** → 权限 / 思考强度收成图标 |

**为什么不量 DOM**：三栏宽度都是受控 state，算出来与量出来同一个数（实测 `1716−256−720=740`
= 量到的 740）；而算的版本不依赖 ResizeObserver 回调是否送达——本机 IAB guest 就不派发，
量的版本在这里是瞎的。

| 行为 | 结果 |
| --- | --- |
| 拖过上限 | 通知工作台**把左栏收成图标栏**腾地方（一次拖拽只请求一次），上限变大、面板接着变宽 |
| 视口变小 / 左栏重新展开 | 面板收回到新上限内，对话列恒 ≥ 420 |
| 窄列 | 权限 / 思考强度**只剩图标**，当前值靠 `title` 交代（「权限档位：完全访问」），下拉照常可选 |

## 二十五、2026-09-18 第十五轮回执：浏览器面板改成**内嵌实时画面**（调试工具出现在面板里）

**用户口径（原话）**：「你不是说内嵌吗，注入吗，现在怎么又跳转外部了！！！」

**根因**：面板里的页面原先挂在 **iframe** 上，而 iframe 是**跨源**的——读不到 DOM、挂不上
调试工具、也注不进脚本（R3-4 当时就登记过这条边界）。于是「打开调试工具」只能去**受控浏览器
那个窗口**里注入 Eruda：用户看到的就是「面板里什么都没变，外面却多了一个窗口」。

**方案（本轮落地）**：面板显示**受控浏览器自己的画面**，调试控制台因此出现在面板里。

| 层 | 做法 |
| --- | --- |
| 传画面 | `Page.startScreencast`（jpeg）→ `multipart/x-mixed-replace`（MJPEG）→ 面板里一个 `<img>` 直接渲染（客户端零解码）；每帧 ack 由**发完这一帧之后**触发（Chrome 以 ack 做背压，写不动就等 drain） |
| 传交互 | `POST /api/browser/cdp/input` → `Input.dispatchMouseEvent / dispatchMouseEvent(mouseWheel) / dispatchKeyEvent / insertText`；坐标是**视口 CSS px**（客户端按面板里的显示尺寸线性换算，含 `transform: scale` 后的矩形） |
| 开流手续 | `POST /api/browser/cdp/view`：确认在连 → 同页不导航 → 设视口 → 换**短时一次性**票据；`GET /api/browser/cdp/stream?ticket=`（`<img>` 发不了登录头，故用 URL 凭证，取一次即作废） |
| 自由尺寸 | `Emulation.setDeviceMetricsOverride`——**真视口**（900px 宽就按 900px 排版），关掉时 `clearDeviceMetricsOverride` 还原 |
| 调试工具 | Eruda **源码整段注入**到面板显示的这一页（`Runtime.evaluate`），浮在页面底部 |
| 桌面形态 | 保持原生的子 WebView2（真实的本地渲染），调试工具改为把**同一份源码** `eval` 进去（`GET /api/browser/debug-console.js`），不再另开 DevTools 窗口 |

**真机踩到并修掉的三个坑**（都不是测试能预料的）：

1. **页面侧插 `<script src=CDN>` 会静默失败**：注入报成功、页面上什么都没有（用户在面板里
   看到「点了没反应」）。→ 改为**整段源码直投**（运行代码，不是新增资源请求），并且**注入后自检**：
   读 `window.eruda._isInit` 与页面自报的失败原因（`__kfwDebugConsoleError`），没生效就如实报错。
2. **UMD 分支**（真正的根因）：百度这类站点全局有 AMD 加载器（`typeof window.define === "function"`），
   Eruda 的 UMD 包装因此走 `define(factory)` 分支——**不往 window 上挂 eruda**。→ 注入期间临时
   藏起 `module` / `exports` / `define`（跑完 even 出错也原样还原），外层 `.call(window)` 保证 UMD 的
   `this` 仍是 window。已配**同形状 UMD 包**的回归测试（AMD 分支必须被跳过、`define` 必须还原）。
3. **会话的「当前页」会陈旧**：`currentUrl` 原先只在 `navigate()` 里更新，页面自己跳走（点链接）
   之后状态还停在旧地址（「是不是同一页」的判断跟着错）。→ 订阅 `Page.frameNavigated`（只认主框架）。

**顺带收掉的边界**：同一页不重复 `Page.navigate`（重复导航会把页面状态与调试控制台一起刷掉）；
画面流同时只留一个订阅者（重连时不发两份、不多 ack）；面板收起（量到尺寸 0）不开流，展开再开；
**「刷新」按钮在实时画面下不能是死的**（GUI 走查抓到）：`/view` 加 `reload` 语义——
用户点刷新时同一页也重新导航，另外两种触发（换地址/换尺寸）不带它。

**删掉上一轮那条被取代的路**（死代码即清理）：「打开调试工具」现在只有一种实现（注入页面内
控制台），于是 `/api/browser/cdp/devtools` 路由 + 会话的 `openDevtools` + CDP 客户端的
`probeDebuggerUrl` / `listPageTargetsWithDebugUrl` + `waitForDevtoolsFrontend` + 客户端
`openCdpDevtools` 一并删除——留着一条没人调用的路，只会让人以为还有第二个开关。

**顺带修掉一个仓库级门禁**：`apps/desktop/package.json` 是上一轮加的（Tauri CLI 入口），
但它没有 `test`/`typecheck` 脚本，`node --test tests/workspace.test.mjs` 的「app 脚本要真校验」
那条因此变红（`pnpm test` 一直没跑到它）。现在这两个脚本**委派给 Cargo**
（`node scripts/cargo.mjs check|test`，脚本会先找 PATH、再找 rustup 默认位置，找不到就指路），
Rust 侧从此进了 `pnpm typecheck` / `pnpm test`（实测 `cargo test` 6 passed）。

**验证**：`pnpm lint`（0 错 0 警）、`pnpm typecheck`（5/5）、`pnpm exec turbo run test --concurrency=1`
（8/8，server 1063+ / web 444）。**真机验收**（自管 PG + dev server + 真实 Chrome 153，无头）：
`connect(headless:true)` → `/view`（视口 900×600）→ `/stream` 拿到 JPEG 帧 → 存成图片**肉眼确认**
（example.com 按 900×600 排版）；`/input` 派发点击（取 `/snapshot` 的盒模型中心）→ 页面真的跳到
iana.org 且 `status().currentUrl` 随之更新；`/console` 注入后在帧里看到 Eruda 的 Console/Elements/
Network 面板；**GUI 全流程**（IAB + 测试账号）：右栏浏览器输入 `https://www.baidu.com` → 面板里出现

## 二十六、2026-09-18 第十六轮回执：调试控制台做成**悬浮窗**（可拖动 / 可关闭）

| 层 | 做法 |
| --- | --- |
| 消息 | `Runtime.consoleAPICalled` / `Runtime.exceptionThrown` / `Log.entryAdded` → 折成一行行文本（`console-log.ts`，纯函数）→ 环形缓冲（300 条，seq 单调递增） |

| 订阅时机 | **打标签时就订阅**（`attachPageTracking`）——「打开控制台之前页面就报的错」也在，不然用户先看到页面报错、再开控制台却什么都没有 |
| 悬浮窗 | `panel-browser-console.tsx`：标题栏拖动（pointer capture）、✕ 关闭、清空、输入行回车执行；**位置记 localStorage**（关了再开还在原地，与面板宽度同一条口径） |

## 三十一、2026-09-18 终端「连不上」的排查结论 + 一句更诚实的兜底文案

**现象（用户截图）**：右栏终端停在「正在开…」，约 10 秒后变成「已结束 · 会话启动失败，点右边的「重开」再试。」

**根因：不是终端坏了，是服务端进程堆了 17 个（端口争抢 + watcher 反复重启）**。
排查过程：
1. 服务端日志里刷屏的是 `listen EADDRINUSE 127.0.0.1:3001`——`node --watch` 每次重启都新起一个进程，
   而旧的没退（最老的能追到前一天），于是 3001 只有一个赢家，其余全是「起不来也没死」的空转实例；
2. 客户端那条 10 秒兜底（`panel-terminal-view` 的看门狗）发的是「会话启动失败」，**真实原因是
   `terminal.start` 没等到服务端 ack**——服务端在重启/或那个实例已经半死；

## 三十四、2026-09-19 第二十二轮回执：安装包做全（向导 / 环境变量 / 图标 / 无黑框）+ 打包后「Design 不是画布」的真根因

**用户口径**：「安装包应该给用户安装，而不是点一下运行……最接近原生的傻瓜式安装包，一键启动的那种，
最好不要显示 cmd 命令提示符弹窗，然后图标也帮我换上，design 模式是画布啊，怎么又给我改坏了！！！」

**四条独立缺陷，都不是「配置写错」那么浅**：

1. **打包后的窗口停在别人的服务上 → Design 整块失效**。壳只探 `/api/health`：用户自己的 dev API
   （探活 200、但不托管 UI）占着 3001 时，壳「复用」它并把窗口指过去，窗口停在
   `{"message":"Route GET:/ not found","error":"Not Found","statusCode":404}`（真机截图存证）。
   **修法**：壳按 `3001…3010` 找「探活 200 **且首页是 HTML**」的服务端
   （`probe_serves_ui` / `port_is_free`，`server_handle.rs`），撞上别人的服务就换端口；
   随包服务端用 `KENFUTWORK_SERVER_PORT` 跟随挑中的端口；一个都不行时窗口里如实写原因
   （`show_startup_error`）。**回归**：`tests/server_lifecycle.rs` 的 `ui_probe` 三例
   （真 UI 判可用 / 只回 200 没界面判不可用 / 无人监听判不可用）。

2. **打包 UI 的 API base 被烘成了开发值**。仓库根 `.env.local` 里有
   `NEXT_PUBLIC_SERVER_BASE_URL=http://localhost:3001`，Next 的 DefinePlugin 把它**烘进产物** →
   装到别人机器上变成「界面从自己的服务端加载、API 却打 3001」，侧栏「未登录」、项目列表空。
   **修法**：`scripts/package-win.mjs` 构建静态 UI 时把该变量置空（走同源相对路径），
   并断言导出里有 `canvas.html`（Design 的画布路由靠它兜底）。

3. **免登录形态没有令牌 ⇒ 客户端几十处「无令牌即未登录」的门全不放行**（这才是根因）。
   `local-trust` 认的是回环来源、从不签发令牌：上一轮已把 `loadSession()` 改成问 `/api/viewer`，
   但令牌留的是空串——而消费方写的是 `if (!session?.access_token) return;`。项目列表、权限档、
   MCP、技能、浏览器面板……全静默不发请求，于是 Design 模式永远停在「暂无项目」、画布起不来。
   **修法**：`session.ts` 给免登录会话一个**非空标记** `LOCAL_TRUST_SESSION_TOKEN = "local-trust"`
   ——它不是凭据（本形态服务端不看 Authorization 头，口令形态走真令牌），也不落盘。
   **回归**：`test/session-storage.test.ts` 断言标记非空且不进 localStorage。

4. **退出/升级/卸载留一堆孤儿进程**。Windows 上 GUI 壳**没法给控制台子进程送优雅信号**
   （`taskkill` 不带 `/F` 只对带窗口的进程有效），宽限一到就 `TerminateProcess`——服务端来不及停库，
   `postgres.exe` 全家成孤儿。真机后果：升级装到一半「无法写入: …\app\KenFutWork-server.exe」安装中止；
   卸载静默留下 51 MB 删不掉（`app\pg\bin` 下 12 个 `postgres.exe` 仍在跑）。
   **修法两层**：① 壳用 **Windows 作业对象**（`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`）把服务端及其后代
   绑成一个 job，壳退出（含被强杀）即由内核收树——`taskkill /T` 是顺着父子链走的，父进程一死就找不到后代，
   故不可靠；② 安装/卸载钩子按**可执行文件路径**清残留（不是按进程名，免得误伤用户自己的 PostgreSQL）。

**安装包做全**（`src-tauri/installer-hooks.nsh` + `tauri.conf.json`）：
- **环境变量**：装完写 `KENFUTWORK_HOME=<安装目录>`、把安装目录挂到 PATH、广播 `WM_SETTINGCHANGE`；
  `HKCU|HKLM\Software\KenFutWork` 记 `InstallDir`/`Version`。**卸载逐项撤掉**（PATH 只删自己那一段）。

  子进程加 `CREATE_NO_WINDOW`。
- 安装目录不再夹带测试夹具（`loomic-test-fake-server` 挂到 `test-fixture` feature 下）。

## 三十七、2026-09-19 第二十五轮：**机器级 PATH 被清空**的取证与修复 + 标题蓝色还原

### 事故：机器级 PATH 只剩 `C:\Program Files\AskLink`

**用户反馈**：「卸载命令是不是会删除我的系统环境变量啊，现在要怎么办，可以还原吗」，

**真机取证**：

- 用户级 `HKCU\Environment` 的 `Path` = nvm 的两条（`C:\Users\…\Author Software\nvm;D:\nvm\.nodejs`）**完好**；
- 从**改动前就已在运行的进程**（explorer.exe）的环境块里读出来的 PATH 与当前注册表一致
  （`AskLink;nvm;nvm-nodejs`）——不是刚刚发生的抖动；
- `C:\Program Files\AskLink` 是**连连控**，**今天装的**（卸载项 InstallDate `20260919`，目录 `LastWriteTime` 17:47）。

**判决**：值恰好等于连连控自己的目录，而我们的安装器只会写成「旧值;安装目录」或（读失败时）
「安装目录」——**形态对不上**，最可能是连连控自己的安装器把机器级 PATH 整键覆盖了。
但**我们那套写法本身也有同款失败态**，所以一并摘除（见处置 2）。
（附带影响：PATH 一坏，`pnpm` / `powershell` / `python` 这些靠 PATH 解析的启动器全都失灵——
本轮后半段是用绝对路径 `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`
与 `node <cli>.js` 绕过它们继续干活的。）

### 处置

1. **一键修复（用户执行，需 UAC）**：仓库根 `修复系统PATH.cmd`（自动提权）+ `修复系统PATH.ps1`
   —— 先备份当前值到同目录 `机器PATH备份-<时间戳>.txt`，再写回「Windows 默认项 + 盘上确实存在的
   机器级目录」（System32 / Wbem / WindowsPowerShell / OpenSSH / dotnet / Docker / AskLink / NVIDIA 两项），
   以 `REG_EXPAND_SZ` 保留 `%SystemRoot%` 变量形态，最后广播 `WM_SETTINGCHANGE` 让已开进程感知。
2. **我们自己的地雷拆了**（`apps/desktop/src-tauri/installer-hooks.nsh`）：安装器**不再改动 PATH**。
   原实现是「读出旧 PATH → 追加安装目录 → 写回」，失败态很致命：`ReadRegStr` 在值超长
   （NSIS 字符串上限 1024）或读失败时返回空串，而当时的兜底写的是 `$INSTDIR`
   ——**一旦发生，机器级 PATH 就只剩安装目录**。收益（命令行少敲几个字）远小于风险，故摘除：
