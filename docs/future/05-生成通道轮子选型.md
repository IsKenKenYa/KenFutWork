> 角色：调研结论（已闭环收口）。非权威——落地一律按《改造计划》§4.13 台账逐 PR 记账；BYOK 供应商缝规格以《改造计划》§4.8 为准。

## 1. 问题与判定规则

自定义供应商与生成通道（LLM 适配 / IGM / VGM）推进前，按「不重复造轮子」硬约束回答七个待决问题：

1. AI SDK 与 LangChain 之间有没有反向适配（AI SDK provider → LangChain `BaseChatModel`）？
2. AI SDK 的视频三段式 API 在**不经任何中间网关**的直连形态下，各 provider 的轮询实现是否完整？
3. 模型能力静态数据库（能力 hints 表）有没有现成的、可 vendor 进 GPL 系仓库的数据源？
4. 中转站（one-api / NewAPI / AIHubMix 系）对 OpenAI 新特性的透传现状如何，探测清单应包含哪些项？
5. OpenAI `/v1/videos` 任务形状是否已成行业收敛方向，内部 job 形状要不要对齐它？
6. 视频生成的输入参数词表有没有现成的行业形状可借？
7. Postgres 原生任务库（pg-boss / graphile-worker）是否足以取代 PGMQ + 自写薄轮询？

**轮子判定规则**（本仓沿用）：

- 官方维护 + Apache/MIT → 锁版本直接依赖；
- 社区活跃 + 通过本仓契约测试 → 锁版本依赖 + 走自有 protocol 缝包防腐层 + 留单 provider 逃生口；
- 不存在或停滞 → 才自研，且范围收窄到 wire 映射与持久化薄层。

**爆炸半径原则**：判定单位不是「谁维护」而是「这段代码离主链路多近」。chat 层适配器在 deepagents 主链路上（每条消息、每次工具调用都过它），门槛取第二档且必须先过契约测试；生成通道在独立缝后面，故障面有限，第一档即可。

## 2. 七项裁决总表

| # | 项 | 结论 | 证据强度 | 落点 |
| --- | --- | --- | --- | --- |
| 1 | AI SDK→LangChain 反向适配 | 不存在（官方与社区皆无）；chat 层维持 LangChain 薄适配器 | 本地 npm + 案头两轮一致 | chat 层冻结；触发器 T1（§8） |
| 2 | 视频直连 poll 完整度 | 5/5 provider 自含 submit+poll，webhook 全部可绕开 | 案头（kling/luma 弱于另三家，实现期契约测试确证） | 生成通道引 AI SDK；自有层只剩持久化+恢复 |
| 3 | 模型能力库 | vendor models.dev（快照 + 刷新脚本）；LLM 能力全量用之，IGM/VGM 任务级参数自建 | **本地实测**（§4） | 能力 hints 表不自维护 |
| 4 | 中转方言探测 | 4 探测项（`include_usage`=P0 / strict schema / Responses / `cache_control`） | 案头 | 实例级能力缓存的探测清单 |
| 5 | `/v1/videos` 对齐 | 已 deprecated 且从未 GA → **借形状、不绑路径** | 案头（带日期强声明，绑定前抽查官方文档） | 内部 job 形状 provider-neutral |
| 6 | 视频输入词表 | 借 fal per-model schema 形状 | 案头 + 两轮一致 | VGM 参数契约起点 |
| 7 | 任务队列 | 维持 PGMQ（否证理由已修正，见 §6.3） | 案头 + 本仓事实 | 不引 pg-boss / graphile-worker |

**一句话结论**：生成通道的 HTTP 适配、轮询、错误归一、能力目录都是现成轮子；确认要自建的只有两块——**IGM/VGM 的任务级能力声明**与 **job 持久化 + 崩溃恢复薄层**。这两块是产品差异化所在，不是轮子。

| `@ai-sdk/openai-compatible` | 3.0.51 | Apache-2.0 | 2026-09-16 |
| `@ai-sdk/bytedance` | 2.0.46 | Apache-2.0 | 2026-09-16 |
| `@ai-sdk/klingai` | 4.0.45 | Apache-2.0 | 2026-09-16 |
| `@ai-sdk/replicate` / `@ai-sdk/fal` / `@ai-sdk/luma` | 3.0.44 | Apache-2.0 | 2026-09-16 |
| `@ai-sdk/open-responses` | 2.0.47 | Apache-2.0 | 2026-09-16 |
| `@ai-sdk/langchain` | 3.0.105 | Apache-2.0 | 2026-09-16 |

同日同节奏发版 = Vercel 官方 monorepo 的一条发布火车，非社区野包。Apache-2.0 与 GPL-3.0 主仓单向兼容，license 无障碍。

### 3.2 API 面（`dist/index.d.ts` 实证）

- `ai@7` 导出 `experimental_generateVideo` / `experimental_startVideo` / `experimental_getVideoStatus`（video 三段式，含「一个进程提交、另一个进程查询」的分离形态）与稳定版 `generateImage`；
- `@ai-sdk/openai-compatible` 的 `ImageModelV4.doGenerate` 签名含 `files` 与 `mask`——**图像编辑（输入图 + inpainting）在共享接口里**，图像侧长尾（中转普遍转发 `/images/edits`）不需自研 wire 层；
- `@ai-sdk/bytedance` 内置 `seedream-4-0…5-0` / `seedance-1-0…2-0` 模型 ID 且带 `(string & {})` 逃生口——BYOK 自定义模型 ID 可走；`videoModel()` 返回 `Experimental_VideoModelV4`；
- 该包内部编码了模型级能力怪癖（如「output_format 仅 seedream-5-0 支持，4-5/4-0 恒定返回某格式」），但**只用于自己组请求、不暴露元数据**——印证：模型能力声明的 UI 面（本仓方向，见 04 §5）仍须自建。

### 3.3 反向适配不存在（裁决 1）

案头两轮一致：`@ai-sdk/langchain` 是 LangChain → AI SDK 单向（`toBaseMessages` / `toUIMessageStream`，喂 `useChat`）；社区仅有的相关项目方向也是反的（Python LangChain 后端 → AI SDK 前端流）。**chat 层维持 LangChain 薄适配器，不重开。**

**否决「定期监控」**：为低概率事件建周期性盯梢违反「不为极少数场景堆叠备选方案」。触发器写入台账（T1），机会性触发（升级依赖 / 读 release notes 时本就会看到），不建 cron。

### 3.4 接入形态

- chat 层不动（LangChain + deepagents）；generation 通道引入 `ai@7` 与所需 provider 包；
- `experimental_*` 全部包在自有生成缝接口之后（防腐层），上游 API 变化只改缝内一个文件；退出 experimental 时评估拆除（触发器 T2）；
- 自有「实例 → provider 实例」映射工厂保持薄：实例的 `baseUrl` / `apiKey` / 自定义请求头（2026-09-16 已落地，见台账）原样喂给 `createOpenAICompatible` / 各 provider 工厂。

## 4. 模型能力库：vendor models.dev（本地实测）

### 4.1 实测事实（2026-09-17，`https://models.dev/api.json`）

- 单文件 JSON **4.7MB**，**220 个 provider**；上游 MIT 许可；
- **无 npm 数据分发包**（候选名全 404、registry 搜索为空）→ 更新机制定为「**提交进仓的快照 + 手动刷新脚本 + zod 校验**」（实现落地为 **.ts 数据模块**而非 .json——dev/tsx/tsc/SEA 各形态零加载器差异，语义不变）；
- **国产覆盖实测优秀**：`deepseek` / `moonshotai`(+cn) / `zhipuai`(+coding-plan) / `zai` / `siliconflow`(+cn) / `minimax`(+cn+coding-plan) / `volcengine`(+coding-plan) / `stepfun` 全系 / `kimi-for-coding`；
- 模型行 schema 字段：`id` / `name` / `description` / `family` / `attachment` / `reasoning` / `reasoning_options` / `tool_call` / `interleaved` / `structured_output` / `temperature` / `knowledge` / `release_date` / `last_updated` / `modalities` / `open_weights` / `limit` / `cost`；
- **生成模型有目录**：seedance×24、kling×177、veo×38、sora×8、wan×10、qwen-image×15，带 `modalities`（如 input `text,image` → output `video`）、`cost`、`open_weights`、发布日期；**没有**任务级生成参数（duration / resolution / aspect_ratio 等）。

### 4.2 分工边界

| 层 | 来源 |
| --- | --- |
| LLM 能力（tool_call / reasoning / structured_output / 上下文 / 价格 / 模态） | models.dev 快照，**不自维护** |
| IGM/VGM 目录、模态方向、价格、发布状态 | models.dev 快照 |
| IGM 任务级参数（modes / supports / requirePrompt / maxInputImages 等） | 自建（形状借 cherry，见 04 §5.2） |
| VGM 任务级参数（duration / resolution / 首尾帧 / audio 等） | 自建（形状借 fal，见 §6.1） |

### 4.3 更新机制排序（按本仓约束）

npm 包 > 提交快照 + 刷新脚本 > CI 自动同步 > git submodule。快照档为本仓默认（无 npm 分发）；CI 同步引入 bot 提交通道与信任边界，低风险 hints 表不值得；**submodule 明确排除**——本仓多 agent 并行的工作方式使 submodule 指针常年处于脏态，构建路径依赖禁入 submodule。快照定位是**非权威 UI 提示**（用户声明优先、不进协议层，04 §5.4 同口径），过期无实害，低频手动刷新即可；刷新时按需裁剪 provider 子集以控制 diff 体积。

### 4.4 勘误（两轮调研报告的错误，防进台账）

- 「models.dev 收录 75+ provider」——实测 220；
- 「对国产模型覆盖需进一步核实」——实测全覆盖（§4.1）；
- 「models.dev 与 LiteLLM 均不覆盖图像/视频」——不准确：任务级**生成参数**确实无，但目录 / 模态 / 价格有（§4.1）；
- LiteLLM 本体许可证为 **MIT**（一轮报告误报 Apache-2.0，混淆了第三方 bundle 项目）——models.dev 已中选，此勘误仅备查。

## 5. 视频直连轮询与内部 job 形状

### 5.1 直连 poll 完整度（案头，5/5）

| provider | 机制 | webhook 可绕开 |
| --- | --- | --- |
| bytedance (Seedance) | queue API：submit → task id → poll；官方同时支持 polling 与 webhook | 是 |
| replicate | prediction API：submit → `GET /predictions/{id}` | 是 |
| fal | queue API：`request_id` + `status_url` + `cancel_url`，状态 `IN_QUEUE / IN_PROGRESS / COMPLETED` | 是 |
| kling | 任务查询端点 + `callback_url` 可选参数 | 是 |
| luma | `GET /v2/requests/status/{request_id}` | 是 |

桌面自托管无公网入口，webhook 一律弃用、纯 poll。kling/luma 的案头证据弱于另三家，**实现期以 per-provider 契约测试做运行时确证**（生成缝本来就要写这层测试），调研阶段到此为止。

### 5.2 `/v1/videos`：借形状、不绑路径

案头结论：OpenAI Videos API 处于 preview 即宣布 deprecated（宣称 2026-09-24 从 API 移除；**带日期强声明，凡要把某个绑定写进代码前先抽查官方文档**）；Gemini 兼容层已对齐该形状。裁决：**放弃「对齐 `/v1/videos`」**，内部 job 形状保持 provider-neutral，只吸收其设计：

- submit 返回薄体 `{id, status, polling_url}`；
- poll 响应刻意薄（无 progress 字段——进度条只能基于历史中位数做估计，这是行业现状不是缺陷）；
- 终态五态：`queued / in_progress / completed / failed / cancelled`；
- cancel 语义差异（如「运行中取消返回 400」）记为 per-provider 注记，不作兼容门槛。

### 5.3 剩余自建范围

自有轮询层收窄为三件事：**job 持久化**（`{provider_instance_id, task_type, 调用参数快照, provider job id, status, config_revision}`）、**崩溃恢复**（worker 重启后按 provider job id 续 poll）、**跨修订防护**（实例能力声明变更后旧 job 不得复用旧句柄——衔接 04 §5.3 的 `config_revision` 提案）。HTTP 轮询、重试退避、错误归一交给 AI SDK。

## 6. 词表、中转探测、队列

### 6.1 视频输入词表（借 fal per-model schema）

```text
VideoModelInput:
  prompt: string（必填）
  imageUrl? / videoUrl? / referenceImageUrls?: string
  duration?: { values: number[], default? }
  aspectRatio? / resolution?: { values: string[], default? }
  negativePrompt?: string
  seed?: number
  audio?: boolean
  firstLastFrame?: { first, last }
```

每模型声明支持子集与取值约束，与 04 §5.2 的「canonical 词表 + 逐模型 supports」同构——图像、视频两侧共用同一纪律。

### 6.2 中转站探测清单（进实例级能力缓存）

| 探测项 | 优先级 | 案头依据 |
| --- | --- | --- |
| `stream_options.include_usage` | **P0**（缺失则流式用量统计失效） | one-api 默认不补，需 `ENFORCE_INCLUDE_USAGE=true`；NewAPI 已跟进 |
| strict tool schema | P1 | 中转常见缺失点 |
| OpenAI Responses | P1（中转支持率低 → 失败自动回落 chat/completions 应为默认行为而非用户开关） | AIHubMix 宣称支持；one-hub 曾修 Responses `cached_tokens` 缺失，上游支持存疑 |
| Anthropic `cache_control` 透传 | P1 | BYOK 省钱刚需 |

探测结果缓存到**实例**上，运行期据此裁剪请求；与已落地的自定义请求头（台账 2026-09-16 行）同属实例层。

### 6.3 队列否证（维持 PGMQ）与勘误

pg-boss（12.15.0）/ graphile-worker（v0.17）功能齐备（重试 / cron / 超时恢复内置），但**本轮调研给出的否证理由是错的，必须修正**：二者并不需要「额外 Node 运行时」——本仓 worker 本来就是 Node 进程（桌面端内嵌的也是 Node 服务），pg-boss 只是 npm 依赖。**维持 PGMQ 的正确理由**：

1. 已集成且运行中，切换无收益；
2. 真正的难点是「外部 provider job 的状态机 + 崩溃后恢复轮询」，任何队列库的内建重试/cron 都不解决这件事；
3. PGMQ 的桌面扩展打包问题已由最小 shim 方案覆盖（台账 M2.3）。

重新评估条件：将来需要「无代码 cron 管理 UI」或跨语言 worker 时再看 graphile-worker。

## 8. 触发器与确证点

**触发器**（入台账，机会性触发，不建监控任务）：

- **T1**：出现官方（Vercel 或 LangChain 任一侧）反向适配，或某社区包通过本仓契约测试（流式 tool call 不丢块 / usage 不丢 / 多模态输入不丢）→ 重开「chat 层消费 AI SDK provider 包」评估；
- **T2**：AI SDK video API 退出 experimental → 评估拆除防腐层；
- **T3**：models.dev 上游 license 或 schema 变更 → 刷新脚本适配（zod 校验会先挡住）。

**确证点**（实现期，每条对应一类测试）：

1. per-provider 视频契约测试（kling / luma 优先——案头证据最弱的两个）；
2. models.dev 快照 zod 全量校验 + 刷新脚本幂等；
3. 中转 4 探测项的运行时矩阵（连通性测试落实例缓存）；
4. `experimental_*` 升级盯防（防腐层内 diff 即可）。

## 11. 编排与采用决议（2026-09-17 用户拍板）

**SDK 采用规则**：**AI SDK 为主（`@ai-sdk/*` 全家），官方 SDK 为辅**——仅当 AI SDK 无对应包的厂商才考虑其官方 SDK，且无论哪条路，适配器都必须实现同一套 `{submit, poll, cancel}` 防腐契约（§5.3），引擎层对底层来源无感。实测补充：`@ai-sdk/minimax@3.0.33` 存在（Vercel 官方 monorepo 同节奏包），故 MiniMax 也走 AI SDK 通道，无需第三方「官方 SDK」；现有 `metaso` 协议（`metaso.cn/api/minimax/` 中转，模型 `metaso/minimax-h3`）保持现状不动。

**编排引擎 = 既有 `features/jobs/` 引擎的扩展，不另起新引擎**（先改后增）。队列缝三原语已在：`delaySeconds`（延迟消息）、`read_ct`（重试计数）、`archive`（死信）——「PGMQ 自旋轮询」（submit 后投延迟消息、消费时 poll、未终态再投下一条）是**纯消费侧改造**，不需要任何新队列能力。同步小图的「同步体验」复用既有 job 状态查询与 WS 事件通道，**不引入 Redis**。

**状态机与错误分类**：五态（pending/running/succeeded/failed/cancelled）与 §5.2 一致（措辞归一）。错误四分类落到引擎策略：`transient`（指数退避重投延迟消息，`read_ct` 封顶）、`rate_limit`（尊重 `Retry-After` 定长延迟）、`fatal`（立即终态 + 死信 + 可读原因，worker 死信路径已有）、`provider_crash`（**SUSPENDED 熔断延后不做**——BYOK 桌面单实例场景 YAGNI，登记为触发器：同一实例连续 N 次 transient 时人工处理）。

**三条硬性补充（采纳外部评审）**：

1. **abort → 显式 cancel**：AI SDK 收到 `AbortSignal` 只断本地连接、不保证上游取消；防腐层捕获 abort 后必须显式调用 provider cancel（不支持 cancel 的记 `cancelled` 本地终态并照常落库，避免云端继续扣费）。
2. **快照白名单裁剪**：只保留与本仓协议/BYOK 常用相关的 provider 子集与核心字段，目标体积 **< 500KB**（原始 4.7MB），避免拖慢服务端启动。
3. **僵尸任务绝对超时**：视频 job 落库时写 `deadline_at`，executor 每次 poll 前比对，超过绝对时限（默认 30 分钟，env 可调）强制 `failed` 并释放队列——不许任何任务无限占用并发位。

**编排层纪律**：引擎（executor/引擎模块）只做状态推进与投递决策；**适配器内禁止 `while` 轮询与自管 `setTimeout` 重试**（HTTP 单次调用的超时/空闲看门狗除外，如 `stream-idle-guard` 同款思路）。轮询节奏由队列延迟消息承载。

**阶段序（拍板）**：**D → A → B → C → E**。D 提前为 Step 0（能力元数据是防腐层参数前置校验的输入），拆两步：**D1** 契约扩展 + 快照管线（行为不变）、**D2** 目录三层合并 + UI 消费（行为变化，测试护航）。

**google 系 provider 不切 AI SDK**（维持现状）、**klingai/fal/luma 协议值不投机新增**（等真实需求再扩 `providerProtocolSchema`）——均已拍板。
