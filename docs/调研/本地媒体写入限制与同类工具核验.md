# 本地媒体写入限制与同类工具核验

核验日期：2026-10-17。范围：本地创作工具的生成结果落盘、单次上传/下载保护，以及 TapNow、Lovart 官方公开帮助。源码结论固定到下列 commit；在线文档记录的是核验当天内容，不代表历史版本或未公开的后台规则。

## 结论

**本次没有找到等价案例，能够为“本地 BYOK 图片生成的结果落盘，应受通用 Agent 文件写入/patch 字节预算约束”提供同类产品依据。** 找到的真实限制分别是：ComfyUI 的 HTTP 请求体上限、Cherry Studio 的单次远程图片下载上限与真实磁盘空间预警、TapNow 的每文件上传上限、Lovart 的每次输入上传数量限制。这些限制保护的对象和计量周期不同，不能互相替代。

最接近生成结果路径的已确认案例是 **Cherry Studio 的远程图片下载限制为 100 MiB/文件**；其标准生成处理确实调用该下载函数。它也监控本地数据目录所在卷的剩余空间，低于 1 GiB 时通知用户。已核验链路中，没有把历史图片累计占用或通用 Agent patch 预算作为生成结果落盘前提。[生成结果处理](https://github.com/CherryHQ/cherry-studio/blob/dac9b72c7fd0982a9acacf46d8bda155f806d1c4/src/main/ai/provider/custom/tasks/imageGenerationJobHandler.ts#L206-L238)、[下载保护](https://github.com/CherryHQ/cherry-studio/blob/dac9b72c7fd0982a9acacf46d8bda155f806d1c4/src/main/utils/downloadAsBase64.ts#L40-L41)、[磁盘监控](https://github.com/CherryHQ/cherry-studio/blob/dac9b72c7fd0982a9acacf46d8bda155f806d1c4/src/main/services/StorageMonitorService.ts#L13-L39)

“没有找到等价案例”是本次有限范围的核验结果，**不是断言所有产品都不存在该限制，更不是宣称本地软件无限容量**。本项目报错的实际预算定义、配置值、是否按单次写入计算，由本项目故障复现与源码追踪确认；本报告不把它预设为累计媒体存储配额。

## 先分清限制对象

| 类型 | 计量对象/周期 | 本次可核验例子 | 能否证明通用 Agent 写预算适用于生成媒体 |
| --- | --- | --- | --- |
| 单文件上传/HTTP 请求体 | 一次用户上传或 HTTP 请求 | TapNow、ComfyUI | 不能；输入传输与生成结果持久化不同 |
| 单次下载/处理保护 | 一个远端结果的响应体 | Cherry Studio 100 MiB 下载上限 | 不能；但可作为生成结果接收保护的同类案例 |
| Agent 文件工具 write/patch 预算 | Agent 工具调用提交的文本或二进制 | 本次未核验到将其复用于生成图片落盘的同类案例 | 须找同一执行路径的证据 |
| 本机累计媒体存储配额 | 已保存媒体总字节数 | 本次核验的标准图片保存路径未找到等价规则 | 不能由上传限制推导，也不能由磁盘预警推导 |
| 本机真实剩余空间 | 数据目录所在磁盘卷的可用字节 | Cherry Studio 低于 1 GiB 预警 | 反映物理磁盘压力；不等于应用被分配的固定总量 |
| 云服务套餐容量/消费额度 | 账户权益、云存储或模型消费 | TapNow Tapies、Lovart credits/Brand Kit 数量 | 不能移植为本地 BYOK 磁盘配额 |

下文中的 MiB、GiB 用于源码明确采用 1024 进制的值；TapNow 页面写的 MB 保留原单位，不擅自换算。

## 五个主要案例

### 1. ComfyUI：上传请求体保护与生成保存是两条路径

- 固定源码：`Comfy-Org/ComfyUI@e087d8f6cb7c6cdb11b59dc7c9bf17c79f8d877d`（2026-10-16 提交快照，不将其冒称正式发行版）。
- CLI 的 `--max-upload-size` 默认 100；服务器乘以 `1024 * 1024` 后传给 aiohttp 的 `client_max_size`。因此可确认的是 **HTTP 请求体约 100 MiB 默认上限且可配置**，不是输出目录累计 100 MiB。多部分请求也可能包含额外封装字节，不能简单说每张图片净荷恰好可达 100 MiB。[CLI 定义](https://github.com/Comfy-Org/ComfyUI/blob/e087d8f6cb7c6cdb11b59dc7c9bf17c79f8d877d/comfy/cli_args.py#L68-L76)、[服务器使用处](https://github.com/Comfy-Org/ComfyUI/blob/e087d8f6cb7c6cdb11b59dc7c9bf17c79f8d877d/server.py#L291-L292)
- 标准 `SaveImage.save_images()` 取输出目录、生成文件名，然后逐张调用 Pillow 保存 PNG。其 `get_save_image_path()` 检查输出目录边界、分配文件序号和创建目录。**这两段已核验的标准保存路径没有累计目录字节预算或通用 Agent patch 预算检查。**[保存实现](https://github.com/Comfy-Org/ComfyUI/blob/e087d8f6cb7c6cdb11b59dc7c9bf17c79f8d877d/nodes.py#L1669-L1728)、[路径实现](https://github.com/Comfy-Org/ComfyUI/blob/e087d8f6cb7c6cdb11b59dc7c9bf17c79f8d877d/folder_paths.py#L529-L575)
- 核验边界：这是标准 Python 服务/保存节点；第三方 custom nodes、反向代理、托管 Comfy 服务及其套餐不在结论内。图片仍可能因磁盘、权限、内存或编码等实际资源问题保存失败。

**判定：存在传输入口限制；未找到与本次争议等价的本地生成写入预算。**

### 2. Cherry Studio：生成图片的单次下载 100 MiB，磁盘剩余空间低于 1 GiB 时提示

- 固定源码：`CherryHQ/cherry-studio@dac9b72c7fd0982a9acacf46d8bda155f806d1c4`（2026-10-16 提交快照）。官方 Files 文档也明确将 Paintings 生成图片纳入本地文件管理，附件保存在本地应用数据目录。[官方 Files 文档](https://cherryai.com/docs/en/cherrystudio/preview/files/)
- 真实接线：`downloadAndPersistImageUrls()` 先解析结果。远程 URL 调用 `downloadImageAsBase64()`，再经 `FileManager.createInternalEntry({ source: 'base64', ... })` 写入本地库；`data:` 结果直接进入后半段，**不经过该下载上限**。[生成结果调用链](https://github.com/CherryHQ/cherry-studio/blob/dac9b72c7fd0982a9acacf46d8bda155f806d1c4/src/main/ai/provider/custom/tasks/imageGenerationJobHandler.ts#L206-L238)
- 下载函数将 `MAX_FILE_SIZE_BYTES` 定为 `100 * MB`；同时检查 `Content-Length` 和下载完成后的 Buffer 长度，超过则返回失败。该项目的 `MB` 等于 `1024 * 1024`。**这是单个远程响应 100 MiB 的保护**，没有把已经保存的历史文件合计进来。没有 `Content-Length` 时，第二次检查发生在 `arrayBuffer()` 读取之后，因此它也不能被描述为完备的流式内存上限。[常量与检查](https://github.com/CherryHQ/cherry-studio/blob/dac9b72c7fd0982a9acacf46d8bda155f806d1c4/src/main/utils/downloadAsBase64.ts#L40-L41)、[检查位置](https://github.com/CherryHQ/cherry-studio/blob/dac9b72c7fd0982a9acacf46d8bda155f806d1c4/src/main/utils/downloadAsBase64.ts#L106-L141)、[单位定义](https://github.com/CherryHQ/cherry-studio/blob/dac9b72c7fd0982a9acacf46d8bda155f806d1c4/src/shared/utils/constants.ts#L1-L3)
- 本地保存段解码 base64，准备临时文件写入，提交后登记文件 size/hash；已核验的 `createInternal()` 与 `prepareAtomicWrite()` 没有查询媒体库累计占用，也没有读取 Agent patch 字节预算。[本地文件创建](https://github.com/CherryHQ/cherry-studio/blob/dac9b72c7fd0982a9acacf46d8bda155f806d1c4/src/main/services/file/internal/entry/create.ts#L59-L80)、[提交与登记](https://github.com/CherryHQ/cherry-studio/blob/dac9b72c7fd0982a9acacf46d8bda155f806d1c4/src/main/services/file/internal/entry/create.ts#L144-L184)、[临时文件写入](https://github.com/CherryHQ/cherry-studio/blob/dac9b72c7fd0982a9acacf46d8bda155f806d1c4/src/main/utils/file/fs.ts#L467-L489)
- 另一路 `StorageMonitorService` 用 `statfs(app.userdata)` 读取**所在磁盘卷**的可用空间，低于 `1 * GB` 标为 low。渲染端在 low 时显示持续 warning、恢复后关闭；这一监控链只发预警，没有拦截生成保存。[主进程监控](https://github.com/CherryHQ/cherry-studio/blob/dac9b72c7fd0982a9acacf46d8bda155f806d1c4/src/main/services/StorageMonitorService.ts#L13-L83)、[预警消费方](https://github.com/CherryHQ/cherry-studio/blob/dac9b72c7fd0982a9acacf46d8bda155f806d1c4/src/renderer/hooks/useStorageMonitorNotification.ts#L10-L32)
- 核验边界：结论针对上述当前生成任务/文件保存路径，不扩大到每个模型适配器、插件和所有历史版本。

**判定：找到了生成媒体接收阶段的真实保护，但其对象为单次下载与真实剩余磁盘，不是本次争议中的通用 Agent 写入预算。**

### 3. Jaaz：本地创作 Agent 的 OpenAI 图片路径直接落盘到用户数据目录

- 固定源码：`11cafe/jaaz@145dd85067be77e36d400637a595e19a7b07c77a`（2026-03-02 提交快照）。这是本次覆盖的本地 Lovart 类工具；不使用非官方镜像或二次转载作为证据。
- `FILES_DIR` 为 `USER_DATA_DIR/files`；`USER_DATA_DIR` 可由环境变量指定，默认在服务目录下。[目录定义](https://github.com/11cafe/jaaz/blob/145dd85067be77e36d400637a595e19a7b07c77a/server/services/config_service.py#L65-L70)
- `OpenAIImageProvider.generate()` 读取用户配置的 API Key/base URL 后调用图片 API；收到 `b64_json` 或 URL，均交给 `get_image_info_and_save()`，目标位于 `FILES_DIR`。该函数解码/下载、用 Pillow 打开并保存 PNG；上层随后把文件加入画布。[供应商结果处理](https://github.com/11cafe/jaaz/blob/145dd85067be77e36d400637a595e19a7b07c77a/server/tools/image_providers/openai_provider.py#L28-L105)、[解码/下载与保存](https://github.com/11cafe/jaaz/blob/145dd85067be77e36d400637a595e19a7b07c77a/server/tools/utils/image_utils.py#L18-L122)、[接入画布](https://github.com/11cafe/jaaz/blob/145dd85067be77e36d400637a595e19a7b07c77a/server/tools/utils/image_generation_core.py#L83-L97)
- **上述调用链中没有找到总媒体字节配额、每图字节预算或通用 Agent write/patch 限额检查。** 这里只说明源码实际做了什么；其 URL 分支直接读取响应，不能因此宣称可安全接收无限大文件，也不能据此推荐移植它的资源防护方式。
- 核验边界：OpenAI provider 与共用图片保存函数；未将每个 provider、视频链路或企业云版概括为相同实现。

**判定：这是本地 BYOK 生成与画布落盘的直接可比对象；已核验链路没有等价规则。**

### 4. TapNow：30MB 图片上传上限是 per file

官方《Upload files to the canvas》的表头明确写的是 “Maximum size per file”，图片 JPG/PNG 为 30MB，视频 MP4/MOV 为 500MB，音频为 50MB；同页说明不同入口可能有不同格式要求。它讲的是把电脑上的媒体上传成画布节点，**不是已生成结果落盘，也不是本机媒体库总大小**。[官方上传文档](https://docs.tapnow.ai/en/docs/canvas/upload-files-to-the-canvas)

官方 Agent outputs 文档说明，生成图片/视频/音频通常直接成为画布节点；Tapies 文档说明计量随模型、规格、时长、数量和任务复杂度变化。两者都不足以推导“本地媒体写入总配额”或“Agent 文件写预算”。[Agent 输出](https://docs.tapnow.ai/en/docs/agent/manage-agent-outputs)、[Tapies 与计划](https://docs.tapnow.ai/en/docs/account/manage-tapies-and-plans)

**判定：确认有云产品上传限制；在本次查看的官方上传、输出、计划与故障排查文档中，未找到等价本地生成写入预算。不能据此宣称 TapNow 完全没有存储限制。**

### 5. Lovart：每次输入最多 10 个上传项，另有套餐对象数量

官方《Adding References》的 Upload Files 限制是 “Maximum of 10 uploaded items per conversation input.”；同页 Brand Kit quota 按套餐给的是 kit 数量。Assets Library 支持把资产留给后续项目复用，但该页没有给出媒体总字节容量。[官方引用素材文档](https://www.lovart.ai/docs/how-to-prompt/adding-references)

官方 Canvas Objects 页面讲的是将图片/视频加入画布；Subscribe FAQ 讲 credits、订阅与设备并发限制。这些页面没有提供可据以确认“本地 BYOK 图片落盘受通用 Agent 字节预算约束”的资料。公开文档缺失不能当作产品后台无任何限制的证明。[画布对象](https://www.lovart.ai/docs/edit-your-design/canvas-objects)、[订阅 FAQ](https://www.lovart.ai/statement/lovart-subscribe-faq)

**判定：确认有输入数量和套餐对象数量限制；本次未找到等价本地生成写入预算。**

## InvokeAI 补充核对：确有本地库总量限制，但对象是字体

为避免把“本地应用绝不设总量限制”说成另一种绝对结论，额外核对了 `invoke-ai/InvokeAI@596c1d0b60ae5d5d6d3e86051dd3741986db586b`（2026-10-16 提交快照）：

- 图片标准保存链路 `ImageService.create()` → `DiskImageFileStorage.save()` 先保存记录/PNG/缩略图，再记录文件大小；上述链路没有累计图片字节预算检查。官方配置文档说明生成图片位于可配置输出目录，默认 `outputs/images/`。[创建与大小记账](https://github.com/invoke-ai/InvokeAI/blob/596c1d0b60ae5d5d6d3e86051dd3741986db586b/invokeai/app/services/images/images_default.py#L65-L165)、[文件保存](https://github.com/invoke-ai/InvokeAI/blob/596c1d0b60ae5d5d6d3e86051dd3741986db586b/invokeai/app/services/image_files/image_files_disk.py#L238-L313)、[配置文档](https://invoke-ai.github.io/InvokeAI-7/configuration/invokeai-yaml/)
- **确实存在字体限制配置**：`max_font_upload_bytes` 默认 32 MiB；`max_font_library_bytes` 默认 1 GiB，字段描述是每账户/共享字体库的总上传字体大小。它是明确命名、可配置的字体资产边界，不能偷换成生成图片限制，更不能为任意 MB 数的通用媒体预算背书。本报告只据配置确认该规则的声明，不冒称已经穷尽字体上传与并发执行的完整实现。[配置源码](https://github.com/invoke-ai/InvokeAI/blob/596c1d0b60ae5d5d6d3e86051dd3741986db586b/invokeai/app/services/config/config_default.py#L214-L218)

## 对本项目能得出的设计判断

以下是根据已核验同类路径作出的**工程判断**，不冒称行业统一标准：

1. 生成媒体的接收、解码和落盘可以有明确的资源保护；保护应按该媒体路径的真实风险设计，并清楚说明是单文件、单次处理、实际磁盘不足还是用户主动设置的存储容量。
2. 通用 Agent 文本/patch 写入预算与生成媒体持久化的输入来源、大小分布、计费时点及恢复方式不同。若要共用，须有本项目独立论证，不能用 TapNow 上传表或 Lovart 输入数量替代论证。
3. Cherry Studio 可作为“生成图片远程接收设置单文件上限，另用真实磁盘空间预警”的可追溯对照；这里不把它的 100 MiB/1 GiB 数字直接推荐为本项目默认值。
4. 本报告不确认本项目预算是单次还是累计、不推荐未经验证的阈值、不声称提高阈值就完成故障修复。错误归属、供应商已完成但落盘失败时的恢复与结果保留，需要由本项目原场景验证。

Toonflow 的固定源码、画布与媒体落盘另见[《Toonflow 本地画布与媒体落盘源码分析》](./Toonflow本地画布与媒体落盘源码分析.md)，本报告不重复该仓库核验，也不预先引用其尚未完成的结论。

## 核验方法与限制

- 首先检索官方域名/源码仓库；源码经 GitHub API 取固定 commit 的相关文件，逐段追标准生成/保存消费方，不靠搜索结果摘要判断实现。
- 云文档核验覆盖 TapNow 上传、Agent outputs、Tapies/计划、故障排查，以及 Lovart Adding References、Canvas Objects、Subscribe FAQ。另用 `storage/quota/capacity/GB/MB/存储/容量` 的官方域检索查找相近限制；检索未命中不构成不存在证明。
- 没有调用真实生成接口，没有读取本地供应商配置或密钥，没有执行同类应用，故结论属于官方文档/源码审查，不是 GUI/运行时验收。
- 没有修改 `references/` 或业务代码；所有第三方源码只读作核验，不复制进本项目实现。
