# 媒体生成供应商适配核验

核验日期：2026-10-15。范围：GPT Image、Gemini Image、Seedream、Seedance、MiniMax H3 的官方协议与本仓接线。本文记录核验开始时的代码缺口；后续修复及测试以实施台账为准。未读取或修改供应商凭据，未发起付费生成请求。

用户已明确暂缓真实图片、视频模型验收。本轮可确认请求协议、实例配置透传、同步/异步执行接线及模拟供应商响应；不能据此声明真实模型账号、计费、区域权限或最终画面质量通过。

## 1. 结论与既有决策

这五类模型不需要五套任务系统。维持 [生成通道轮子选型 §11](05-生成通道轮子选型.md) 的既有 jobs/PGMQ 引擎：同步 HTTP 图片请求作为同一 jobs 引擎的一次执行；异步视频提交只返回厂商任务引用，持久化后由引擎分次查询。厂商适配器负责字段和状态翻译，不各自持有轮询调度器。

初始代码已有大部分适配器，但不能把“存在类或声明模型”视为“对应模型能用”：GPT Image 丢弃官方 base64 产物；Seedream 丢弃参考图并使用不适配新版模型的尺寸；Google 丢弃自定义地址且限制原生模型 ID；Seedance 丢弃分辨率及第二张图片；Metaso 的实例工厂未暴露已有异步方法。详见 §3。

维持 Google 官方 SDK 与已有 Metaso 协议，不为本轮新增另一个闭合协议枚举。MiniMax 官方文档用于核对 H3 请求结构，并不证明第三方 Metaso 代理逐项支持官方全部能力。

## 2. 官方协议矩阵

| 家族 | 官方请求与认证 | 请求核心字段 | 返回与执行语义 |
| --- | --- | --- | --- |
| GPT Image | `POST https://api.openai.com/v1/images/generations`；`POST /v1/images/edits`；Bearer | 生成 JSON：`model`、`prompt`、`size`、`quality`、`output_format`；编辑使用 multipart 图片文件 | 非流式请求直接返回 `data[].b64_json`；GPT Image 不支持用 `response_format=url` 换取图片 URL。另有流式与 Responses 工具面，本仓无需为接入 Images API 同时实现它们。[生成](https://developers.openai.com/api/reference/resources/images/methods/generate)、[编辑](https://developers.openai.com/api/reference/resources/images/methods/edit) |
| Gemini Image | `POST https://generativelanguage.googleapis.com/v1/models/{model}:generateContent`；`x-goog-api-key` | `contents[].parts[]`：文本与 `inlineData`；`generationConfig.responseModalities`；图片配置 | 同步响应 `candidates[].content.parts[].inlineData`；读取实际 `mimeType`。无图片、安全拒绝、文本结果必须区分，不把空数组当成功。[图片指南](https://ai.google.dev/gemini-api/docs/generate-content/image-generation)、[API](https://ai.google.dev/api/generate-content) |
| Seedream | `POST https://ark.cn-beijing.volces.com/api/v3/images/generations`；Bearer | `model`、`prompt`、`size`；参考图为 `image: string \| string[]`，支持 URL/data URL；`response_format` | 非流式 `data[].url` 或 `data[].b64_json`；`data[].size` 为实际尺寸。URL 24 小时有效，须由原 jobs 产物链及时保存。[官方图片 API](https://docs.volcengine.com/docs/ark/image-generation-api?lang=zh) |
| Seedance | `POST https://ark.cn-beijing.volces.com/api/v3/contents/generations/tasks`；Bearer | `model`、`content[]` 文本及 `image_url`/`video_url`/`audio_url`；图片 `role` 为首帧、尾帧或参考图；`resolution`、`duration`、`ratio`、`generate_audio` | 创建返回 `id`；`GET /contents/generations/tasks/{id}` 返回 `status`、`content.video_url`。异步；查询仅覆盖最近 7 天，产物 URL 24 小时有效。[创建](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)、[查询](https://docs.volcengine.com/docs/ark/get-video-generation-task-api?lang=zh) |

### 2.1 模型 ID 与尺寸不能跨家族推断

- GPT Image：官方当前文档列出 GPT Image 1/1.5、2/2.5 等代际。通用横竖尺寸 `1536x1024` / `1024x1536` 与 `1024x1024` 可作为标准尺寸；2/2.5 的自定义像素规则不可套给 1 代。`standard/hd/ultra` 是本仓语义，官方 GPT 请求是 `low/medium/high` 等，必须明确翻译。[官方生成参数](https://developers.openai.com/api/reference/resources/images/methods/generate)
- Seedream：4.0、4.5、5.0 的像素下限不同。例如 4.5 与 5.0 lite 要求总像素至少 `2560×1440=3686400`，4.0 下限为 `1280×720`。`1024×576` 不能作为所有 Seedream 的“16:9”请求。官方允许真实 Model ID 或本账号 Endpoint ID；模型列表变动不应因本地显示目录过期阻断用户配置的合法 ID。[官方图片 API](https://docs.volcengine.com/docs/ark/image-generation-api?lang=zh)
- Gemini：官方指南当前出现原生 `gemini-2.5-flash-image`、`gemini-3.1-flash-image`、`gemini-3-pro-image` 等；文档目录与 preview 名会演进，不应要求用户手写本仓 `google-official/` 前缀。2.5 与 3 系可用图片配置不同，不能无条件给 2.5 发送 `imageSize: 2K`。指南部分示例已迁向 `responseFormat.image`，但 API 仍列出 `imageConfig`，不能只凭示例变化认定旧参数失效。[图片指南](https://ai.google.dev/gemini-api/docs/generate-content/image-generation)、[API 字段](https://ai.google.dev/api/generate-content)
- Seedance：火山中国站与 BytePlus 国际站命名不能混用；实际 `model` 由用户实例提供。官方当前接口还出现 2.5 等新能力，支持范围必须按具体版本声明。两张首尾帧必须分别标记 `first_frame`、`last_frame`；参考素材与首尾帧模式互斥，不能把数组统一当首帧后静默丢弃其余输入。[官方创建参数](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)
- MiniMax：本次直接从官方确认 `MiniMax-H3` 和 `MiniMax-H3-Max`，不是推测名称。H3 为 768P/2K、整数 4–15 秒；H3 Max 为 480P/768P、整数 5–15 秒，不支持 2K。H3 与旧 `/v1/video_generation` Hailuo 链路不是同一响应契约。[官方模型和参数](https://platform.minimax.io/docs/api-reference/video-generation-v2-create)

### 2.2 H3 与 Seedance 的状态边界

Seedance 官方查询列出 `queued/running/cancelled/succeeded/failed`，并在执行过期字段中规定 `expired` 终止；MiniMax 创建文档的回调列出 `queued/running/succeeded/failed/cancelled`。厂商终态不能统一落为“继续查询”，未知状态也不能无限掩盖。回调仅是可选优化：桌面没有公网入口时直接使用共享引擎的持久查询链。[Seedance 查询](https://docs.volcengine.com/docs/ark/get-video-generation-task-api?lang=zh)、[MiniMax 创建与回调](https://platform.minimax.io/docs/api-reference/video-generation-v2-create)

| 落点 | 已有能力 | 初始缺口与实际后果 |

## 4. 安装 SDK 核对

从本机包符号及解析后的 package 路径只读确认：`@google/genai@2.23.0`、`@ai-sdk/bytedance@2.0.48`、`openai@7.20.0`。版本是本次安装事实，不是上游最新版本承诺。

- Google SDK 的 `GenerateContentConfig.imageConfig` 存在，`HttpOptions.baseUrl` 存在；无需因当前文档示例迁移而升级 SDK 才能修复现有地址透传与模型路由。
- ByteDance SDK 的 `doStart`/`doStatus` 已直接使用官方 tasks 路径，operation 为 `{taskId}`；支持首尾帧、参考内容、`generateAudio`。`resolution` 既有像素→480p/720p/1080p 映射，也会透传未在映射表中的值。SDK 已把 failed/expired/cancelled/canceled 作为失败终态处理，本仓不必重复实现网络协议。
- 本仓 `generation/aisdk/video-job.ts` 已隔离 `experimental_startVideo`/`experimental_getVideoStatus`；该防腐层只做提交/单查，不持有轮询调度。它是应继续复用的接缝。

安装包只证明这些方法和字段存在。还需测试最终 HTTP 包体、认证保留头、实际实例工厂与 executor 接线，避免只测孤立 delegate。

## 5. 本轮验收建议与未验事项

在不调用真实计费模型的约束下，建议覆盖：

1. 官方等价响应：GPT 生成/编辑 base64，Gemini 原生/历史前缀 ID 与非默认 baseUrl，Seedream 参考图、合法尺寸、URL/base64，Seedance 首尾帧与分辨率，H3 V2 创建与查询。
2. 从 BYOK 实例工厂一路进入既有 executor：同步结果与异步任务都落同一 jobs 权威；异步提交保存 task/operation 后结束该次执行，后续只查不重建。
3. 负路径：空产物、被安全拒绝、非法 JSON、HTTP 401/429/5xx、终态取消/过期、不支持的参考输入显式失败；错误和持久记录不带 key。
4. 生命周期：运行取消、重启恢复、并发重复查询、画布删除或权限撤销后的迟到结果，不能重复请求付费生成或重复发布资源。

真实账号权限、供应商网络连通、实际生成质量、视频播放格式以及真实模型产物落画布仍为用户明确暂缓事项。模拟 HTTP 及本地队列测试通过后，可以声明协议适配与接线已验证，不能声明五家真实模型端到端验收完成。

## 6. 本轮修复范围

- GPT Image：生成/编辑读取 URL 或 base64；标准横竖尺寸、质量与输出格式映射；多图 multipart 数组与尾斜杠地址。
- Gemini：保留原别名，允许用户声明的原生模型 ID；实例自定义地址与请求头传至 Google SDK；已知 2.5 模型不发送不支持的 imageSize。
- Seedream：完整发送参考图；新版缺省请求满足总像素下限，3.0 保留原尺寸规则；读取 URL/base64 及供应商回传尺寸。端点 ID 原样传递。
- Seedance：已有 AI SDK 防腐层传递分辨率、首尾两帧和音频开关。超过两张图片或参考视频显式拒绝，尚未实现的参考素材模式不再静默截断。
- H3：原生 MiniMax-H3 与原内部别名共用 V2 协议；实例工厂暴露已有单次 submit/poll，进入既有异步视频 executor；取消是查询终态，未知状态报错。
- 共享链路：正常异步查询不再消耗失败重试预算，随本批适配器提交。outputFormat 从工具经 Run、Job 到图片适配器的透传已取得三处 RED 和 GREEN，属于共享宿主的待提交批次，不冒充本批适配器提交已包含的改动。具体测试命令与实际结果记在《日志》一百九十八。

## 7. 共享队列仍需收口的事项

以下是此次只读审计识别的缺口，未包含在上述适配器修复中，不得宣称整条媒体生命周期已完成：

| 事项 | 现状与后续验证要求 |
| --- | --- |
| HTTP 图片旁路 | `/api/agent/generate-image` 仍直接调用供应商；Agent 图片/视频与 HTTP 视频已创建 Job。同步交互也应通过相同 Job 执行，避免另一条资产发布链。 |
| 桌面冷恢复 | in-process 队列不持久，未发现按持久 Job 补投消息的启动消费方。不能用“重新调用 executor 可续查”证明真实桌面重启会恢复。 |
| 异步图片 | ImageProvider 只有 generate；Replicate 的 Prefer: wait 请求若仍在 processing，尚无图片 submit/poll 续查。 |
| 并发与回执窗口 | Job 消费缺排他 claim；外部 submit、保存句柄/修订、投消息分步进行。需覆盖重复消息及提交成功后本地持久化失败，避免重复计费。 |
| 取消 | 当前主要阻止本地发布；厂商取消接口尚未经统一 Job 取消消费。不能承诺云端任务已停止。 |
| 会话迟到结果 | worker 可按冻结目标落画布，工具等待超时后的 Session 媒体投影还缺持久补放。不得伪造成功工具事件补齐。 |
| 元信息与用量 | 异步视频目前只传 URL，实际尺寸/时长缺失；阻塞视频路径存在重复记 usage 的调用点。应由共享资产/Job 层读取真实结果并验证唯一记账。 |

继续使用现有 jobs/queue/生成结果发布服务，按以上行为补回归，不新增按厂商分叉的队列或第二份 Task 状态。
