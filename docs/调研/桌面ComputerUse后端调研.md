# 桌面 Computer Use 后端与跨平台补足调研

> 日期：2026-10-05。范围：KenFutWork 桌面端在 macOS / Windows / Linux 的本机 GUI 截图、无障碍观察与输入执行后端；比较已锁定的 `@computer-use/nut-js@4.2.0`、平台原生 API 和外部 Computer Use MCP。本文是研究材料，不把候选库公开的能力列表当作 KenFutWork 产品能力上限。
>
> 证据标记：**一手事实**来自官方 API 文档、项目源码或本仓当前锁文件/已安装包；**推论/建议**是基于这些事实的工程判断；**待实测**表示不能仅由源码证明目标发行形态可工作。没有在本回合运行平台实机验证、测试或构建。联网读取以 GitHub 官方连接器为主；本机 `curl` 访问 GitHub 受代理/DNS 限制。

## 结论

1. `@computer-use/nut-js` 能承担一部分共通输入和主显示器截图，但不是完整的跨平台桌面后端。锁文件固定 4.2.0；包元数据声明 Linux/macOS/Windows、x64/arm64，许可证 Apache-2.0。本仓已安装 `libnut` 2.7.1 的三个 OS 包。上游 nut.js 自己的 README 明确 Linux 只支持 X11、Wayland 不支持；当前 Linux 二进制动态依赖 `libX11.so.6` 与 `libXtst.so.6`，所以 X11 能力不能外推到 Wayland。其 `ScreenClass` API 文档描述的是 **main display**；没有可移植的显示器枚举 / monitor-id 捕获契约。
2. 显示器列表、捕获源选择、可访问性树和输入授权必须是可替换平台 provider 的能力，不是统一 Boolean。macOS 的 Screen Recording、Accessibility 与合成事件授权彼此独立；Windows 的 Windows.Graphics.Capture、UI Automation 与 `SendInput` 各有不同边界；Linux 必须区分 X11 与 Wayland portal。
3. 已有 Computer Use MCP 可以做特定 OS 的补足或协议参考，没发现一个经过证据确认、同时覆盖三个桌面 OS、能由 KenFutWork 统一收口授权/取消/事件记录的成熟 server。`domdomegg/computer-use-mcp` 包装 nut.js，但它当前依赖另一个 nut.js fork；本次未确认该 fork 对 Linux / 多显示器的实际支持。CursorTouch 的 Windows-MCP 与 MacOS-MCP 是分开的产品，且暴露多于 CUA 的能力。MCP server 可替换原生库实现，但不能替代 KenFutWork 自己的宿主权限、确认、取消、审计和实例生命周期。
4. **建议**保留 KenFutWork 自己的 `ComputerUseExecutor` / host 接口与统一观察结果协议；按宿主平台选择原生 provider。nut-js 作为输入与兼容 X11/单主屏路径的实现选项之一；macOS AX / 截屏权限、Windows UIA / WGC、Linux AT-SPI / Wayland portal 采用原生或轻量宿主 helper。外部 MCP 只经宿主 broker 作为可选 provider 接入，并对工具做 allowlist 与 KenFutWork 审批映射。

## 当前仓库与锁定依赖

- `apps/server/package.json` 固定 `@computer-use/nut-js: 4.2.0`，并含 `@computer-use/node-mac-permissions`；`pnpm-lock.yaml` 锁定三个平台包 `@computer-use/libnut-{darwin,linux,win32}@2.7.1`。本地已安装包的 `package.json` 声明 Apache-2.0、仓库 URL `https://github.com/nut-tree/nut.js.git`、Node >=16、OS 为 linux/darwin/win32、CPU 为 x64/arm64。
- 仓库里曾将该 scoped package 说成“字节 fork”。当前安装物的 package 元数据仍指向 `nut-tree/nut.js`，而 MIT MCP `computer-use-mcp` 当前 manifest 使用的是另一个包 `@nut-tree-fork/nut-js@^4.2.6`。**可确认的是包名、版本、许可与它声明的上游 URL；仅凭这些材料无法确认 4.2.0 的 fork 作者身份、补丁范围或与 4.2.6 fork 的差异。**不要把两套包的行为假定相同。
- 本机安装的 `.node` 产物由 `file` 静态检查得到：darwin 是 x86_64 + arm64 universal，linux 是 x86-64 ELF，win32 是 x86-64 PE。包清单虽声明 arm64，当前 checkout 中看不到 Linux/Windows arm64 原生产物。**这只证明本机 pnpm 安装快照的内容，不证明 npm 为所有平台/架构实际发布物均一致；Linux/Windows arm64 发布必须做目标架构安装烟测。**
- Linux `libnut.node` 的 ELF NEEDED 表依赖 `libX11.so.6`、`libXtst.so.6`、`libstdc++.so.6`、`libgcc_s.so.1`、`libc.so.6`；`strings` 可见 `XOpenDisplay`、`XTestFakeKeyEvent`、`XTestFakeButtonEvent`。这是 X11/XTest 实现的直接二进制证据，不能用于 Wayland session。
- 本仓 `apps/server/src/features/computer-use/executor.ts` 已将执行器作为可替换接口，含 `listDisplays?`、`perform?`、`AbortSignal` 上下文等预留。当前同文件的平台工厂仍只启用 darwin，其他平台返回 unavailable（源码注释标出后续阶段）。该事实用于描述当前树状态；并行工作中的新原语需要由主线整合与实机验证。

上游入口：[`@computer-use/nut-js@4.2.0` npm 包](https://www.npmjs.com/package/@computer-use/nut-js/v/4.2.0)、[nut.js README](https://github.com/nut-tree/nut.js/blob/develop/README.md)、[nut.js API docs](https://nut-tree.github.io/apidoc/)。本仓锁定证据见 `apps/server/package.json` 与 `pnpm-lock.yaml`；静态检查所依据的安装物位于 `node_modules/.pnpm/@computer-use+nut-js@4.2.0/` 与 `@computer-use+libnut-{darwin,linux,win32}@2.7.1/`。

### nut-js 能力边界

| 能力 | 一手证据 | 可依赖程度 / 空白 |
| --- | --- | --- |
| 键鼠与剪贴板 | nut.js README 列出 native keyboard/mouse/clipboard；4.2.0 包组合 `KeyboardClass` / `MouseClass` 与 libnut | 共通输入候选。单次原生注入是系统副作用；调用返回 Promise 不代表操作可取消。对 macOS 的 TCC、Windows integrity/UIPI、Linux display server 限制不能由统一 API 消除。 |
| 截图 | `ScreenClass` API 注释限定 main display；`grabRegion` 的契约同样按 main display 描述 | 单主显示器及主屏 region；**未找到**稳定可移植的枚举屏幕、捕获指定 monitor 或窗口源接口。也不应把 `getWindows()` 当无障碍树。 |
| 窗口 | 包公开 `getWindows/getActiveWindow`，`Window` 暴露 title/region/focus/move/resize/minimize/restore；还要有相应 provider | 可做部分窗口操作；目标窗口是否能取到、后台窗口截屏和多显示器位置需按平台核实。名称“Window”不代表 AX/UIA 树完整。 |
| 无障碍树 | core package 接口/依赖没有统一 AX/UIA/AT-SPI provider；README 的“GUI elements”功能需要额外 provider / addon | 不具备跨 OS 等价 a11y contract。产品需要独立 host provider，并对不支持元素动作的应用保留 raster 坐标路径。 |
| Linux | 官方 nut.js README 的安装前置明确 `libXtst`，并写明“only supports X11; Wayland is NOT supported” | Wayland 原生 session 明确不支持。XWayland 是兼容运行方式，不是对所有原生 Wayland 窗口/桌面安全面的承诺。 |
| 取消 / 超时 | 公共 API 的 `AbortSignal` 出现在图像/窗口 `waitFor` 轮询参数；键鼠与 native capture 方法未暴露 signal 参数 | 可取消轮询，不能据此声称能中止正在执行的原生输入/截屏。宿主超时可能只停止等待，不会撤销已发送动作。要强制回收卡死 native call，helper 子进程可被宿主终止，但终止前输入可能已送达。 |

**坐标约定是主要集成风险。** nut.js 屏幕尺寸文档称返回硬件像素分辨率，并举 Retina 屏作为 pixel density 高于 1 的例子；`colorAt` 源码会显式按 `pixelDensity.scaleX/scaleY` 转换坐标。不能推导出所有 low-level `grabRegion`、鼠标注入与外部模型截图坐标自动使用同一个空间。多屏还有主屏原点、负坐标、每显示器缩放、旋转、窗口 logical bounds 与捕获 raster 像素之间的差异；官方 main-display 契约也没有替 KenFutWork 定义这些转换。

**建议统一协议**：每个 frame 绑定 `frameId + displayId + captureBounds + rasterWidth/Height + logicalBounds + scaleX/Y + rotation`；动作坐标显式绑定当前 frame，并只在 provider 边界转换。窗口 `bounds`、平台桌面逻辑坐标、模型看到的 raster 像素都分别命名，禁止只传无单位的 `{x,y}`。副屏负坐标和混合 DPI 必须作为桌面验收样例；捕获范围/目标窗口变了就使旧 frame 坐标失效。

### 2026-10-05 macOS 实机坐标偏移回报

主线程在单块 2x 屏上回报：`NSScreen.bounds=[0,0,1920,1080]`；fixture AX 窗口 bounds `[150,598,420,332]`；系统 `screencapture -R` 捕获同一 420×332 区域后得到 840×664 像素；nut-js worker 请求 `mouse.setPosition(255,704)` 后 `mouse.getPosition()` 为 `(255,681)`，y 差 23。系统确实收到 move/down/up 事件，但因指针落点偏移，按钮点击没有命中。该证据说明权限并非单纯拒绝，也说明截图尺寸有 2x 缩放；它**不能单独证明**屏幕内容与 AX bounds 的 y 原点或 `screencapture -R` 的裁剪位置一致。

源码对照使用与本仓安装版本号匹配的上游 tags：[`nut.js v4.2.0`](https://github.com/nut-tree/nut.js/tree/aaca4af31e6ba6591804aeed981d57df7fc12eb5) 与本仓 `@computer-use/libnut-darwin@2.7.1` 对应的 [`libnut-core v2.7.1`](https://github.com/nut-tree/libnut-core/tree/3a02763bbd80eb7c8f7d509d5e0562e93249e497)。包元数据都声明指向 `nut-tree/nut.js`，但仓库没有证明 scoped 安装物与上游二进制字节相同；以下是上游同版本源码结论：

- [`nut.js v4.2.0 MouseProvider`](https://github.com/nut-tree/nut.js/blob/aaca4af31e6ba6591804aeed981d57df7fc12eb5/providers/libnut/lib/libnut-mouse.class.ts) 的 `setMousePosition()` 直接调用 `libnut.moveMouse(p.x,p.y)`，读取位置则直接返回 `libnut.getMousePos()`，中间没有菜单栏或 DPI 补偿。
- `libnut-core/src/main.cc` 将 move 输入经 `Int32Value()` 转成 `size_t`，构造 `MMPoint` 后调用 `moveMouse()`；`src/macos/mouse.c` 将点直接放进 `CGPointMake(point.x,point.y)` 创建 Quartz `CGEvent`。`getMousePos()` 也是从 `CGEventGetLocation()` 读取并原样转成 `MMPoint`。此版本源码中没有 `menuBarHeight`、23px 常量或 y 偏移修正。因此偏差不是 nut-js/libnut 中一段写死的菜单栏减法。
- Retina 截图采用另一条坐标路径：`src/macos/screengrab.m` 对 `CGMainDisplayID()` 调用 `CGDisplayCreateImageForRect()`，rect 原样传入；图像宽高再按 `[NSScreen mainScreen].backingScaleFactor` 做像素扩展。单主屏的 420×332 → 840×664 与该 2x 路径相符。也因此 raster 像素坐标不能直接作为 Quartz 鼠标屏幕坐标。
- 多屏边界更明确：同一版本 `src/macos/screen.c` 与 `screengrab.m` 只以 `CGMainDisplayID()` 读主屏尺寸/截图；未枚举显示器、未捕获所选副屏，backing scale 只取 `NSScreen.mainScreen`。鼠标则提交 Quartz 点，没有与显示器 id 绑定的映射。`src/main.cc::_moveMouse` 还把 `Int32Value()` 结果存入无符号 `size_t`；负 x/y 在进入 `MMPoint` 前会转成大正数，所以主屏左边/上方的负全局坐标布局不能安全依赖此入口。

**结论与下一步诊断方向**：菜单栏高度正好接近 23 只能说明偏移值像 UI chrome 尺寸，不能据此在代码里加/减 23。源码表明 nut/libnut 两端没有该补偿；偏差更可能出在传入点与 Quartz/实际桌面点使用了不同的坐标空间，或 event 输入与 readback 的平台坐标语义存在转换。当前材料不足以把它确定归因为 menu bar。后续应分别记录当前指针 `CGEventGetLocation`、Mac native accessibility window/element bounds、`NSScreen.frame`/`visibleFrame`、同一 `CGDisplayCreateImageForRect` 和 `screencapture -R` 的像素内容，以及 posted event 的 `CGEventGetLocation`；在同一原点用光标 overlay/可见标记核对截图实际落点，再对屏幕上/下不同 y、scale=1/2 和副屏排列重复。若用户点坐标来自截图，先使用 frame-bound transform；不要先做固定 23px 修正。实机回报尚未包含这些同点交叉读数，本报告不将原因写成已确认事实。

## 平台原生能力与真实限制

| 平台 | 截图 / 显示器源 | 结构化观察 | 输入与授权边界 | 部署含义 |
| --- | --- | --- | --- | --- |
| macOS | [ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit) 提供可枚举共享内容与屏幕/窗口捕获流；屏幕录制权限有独立系统控制（[CGRequestScreenCaptureAccess](https://developer.apple.com/documentation/coregraphics/cgrequestscreenscreencaptureaccess%28_%3A%29) / `CGPreflightScreenCaptureAccess`） | [AXUIElement](https://developer.apple.com/documentation/applicationservices/axuielement) 查询可访问元素树、属性和动作；[AXIsProcessTrustedWithOptions](https://developer.apple.com/documentation/applicationservices/1462089-axisprocesstrusted) 检查/请求 Accessibility trust | 合成事件授权是另一个面：[`CGRequestPostEventAccess`](https://developer.apple.com/documentation/coregraphics/cgrequestposteventaccess%28%29) / `CGPreflightPostEventAccess`。Screen Recording、AX trust、post-event 不应合成一个权限状态 | TCC 授权归属真实执行的签名 app/process。桌面打包、更新签名/路径、dev terminal helper 的授权主体不同；要围绕最终 KenFutWork 桌面 helper 做引导/重授权测试。原生 helper 可以让 TCC 身份与 Web/API server 分离，但要验证签名、打包、公证与升级路径。 |
| Windows | [Windows.Graphics.Capture](https://learn.microsoft.com/en-us/windows/uwp/audio-video-camera/screen-capture) / [API](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture) 能以系统 picker 选择 display 或 window，frame pool 产出帧且系统显示 capture indicator | [UI Automation](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-overview) client 访问应用 provider 提供的 automation tree、属性及 control patterns；自绘或未暴露 provider 的控件可能不可用 | [`SendInput`](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput) 注入合成输入；UIPI 限制只能注入同级或更低完整性进程，且失败时 API 不可靠地区分 UIPI 拒绝。没有与 macOS TCC 等价的逐应用统一 consent 流程 | WGC 用户选择适合显式选源；若产品要由代理服务静默捕捉任意屏幕，不能从 WGC picker API 推导出已获许可。宿主应明确“用户选的捕获 item”并以 provider capability/authorization state 表达。与高完整性/管理员窗口的交互必须展示限制。 |
| Linux X11 | nut-js 2.7.1 实际链接 X11 + XTEST；X.Org 提供 [XTEST extension](https://www.x.org/releases/current/doc/)。X11 display 可取决于 Xauthority 和 server 访问策略 | [AT-SPI2](https://docs.gtk.org/atspi2/) 是桌面无障碍接口；可查询支持它的 app object/action | XTEST 合成输入；X11 的同-display 信任通常比 Wayland 开放，具体由 X server、Xauthority/策略和 session 决定，不等于“Linux 没权限” | 依赖登录中的图形 session、有效 `DISPLAY` / Xauthority、XTEST 与系统动态库。无用户会话/容器里不能假定可控桌面；要清楚区分真实桌面、Xvfb 与远程虚拟桌面。 |
| Linux Wayland | freedesktop [ScreenCast portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.ScreenCast.html) 创建会话、用户选择 source 并提供 PipeWire stream；[RemoteDesktop portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.RemoteDesktop.html) 可与 ScreenCast 共用 session | 仍可尝试 AT-SPI2，但应用 toolkit、portal/compositor 和桌面环境决定覆盖率 | `RemoteDesktop` 负责授权后的合成键鼠输入；`InputCapture` 是捕获/拦截输入的不同接口，不是注入替代品。Wayland 客户端隔离意味着 X11 任意全屏读取/注入不可作通用实现 | 依赖 xdg-desktop-portal、portal backend、PipeWire、登录 session 和桌面环境实现。不能只看 portal spec 就承诺 GNOME/KDE/发行版全覆盖；应 capability probe 并报告缺失，再按目标组合逐个 smoke。 |

上述原生 API 说明“能构造哪些实现”，不证明本项目的最终封装、签名、权限交互、窗口像素与输入映射已经验证。macOS 官方 `AXUIElement` 也不保证每个 Electron/游戏/自绘窗口暴露完整树；UIA、AT-SPI 有同样的 provider 可见性限制，因此产品需要“结构化动作 + raster 兜底”的双路能力。

## 首选平台接口收敛（实现候选）

本项目已有 MCP server / tool registry / `ComputerUseExecutor` 执行器缝。以下是执行器的后端实现选择，不引入新的模型调用循环，也不把系统工具直接注册成不受 KFW 治理的独立 agent。

| 宿主 | 最小可部署组合 | 必须固定的标识与坐标接口 | 能力边界 |
| --- | --- | --- | --- |
| Windows 10/11 | 专用交互用户进程：.NET Windows Desktop / PowerShell host + UIA (`UIAutomationClient`)；输入用 User32；当前桌面截图用 GDI+/`System.Drawing`。PowerShell 5.1 适合验证，发版建议小型 C# helper + JSON-RPC/stdio/本机 IPC，避免每个工具调用都解析 shell 输出 | 遍历顶层窗口 `EnumWindows` → `GetWindowThreadProcessId(hwnd,&pid)` 输出 PID（函数返回的是创建窗口的 thread id）→ 从该 PID 取 process start time；target identity 存 `{hwnd,pid,processStartTime,windowClass,rootRuntimeId,sessionId}`。每个动作重验 `IsWindow`、PID、进程 start time、window class 和当次 UIA root runtime id；PID/start time 检查可防 PID 复用，但同一进程内 HWND 也可能被重建/复用。UIA root 用 `AutomationElement.FromHandle(hwnd)`；节点保留 `ProcessId`、`NativeWindowHandle`、`ControlType`、`AutomationId`，其中 native handle 可为 0，不能只靠它判目标。优先用 app manifest 固定 DPI awareness 为 `PER_MONITOR_AWARE_V2`；若启动时调用 `SetProcessDpiAwarenessContext`，须检查返回值并在建 UI/Graphics 前完成；屏幕统一成虚拟桌面的物理像素矩形 | UIA 优先：`InvokePattern` / `ValuePattern.SetValue` / `ScrollPattern`；没有合适 pattern 时再坐标输入。GDI desktop capture 是屏幕当前合成画面，遮挡窗口会显示遮挡物、最小化窗口不等于可读、secure desktop/UAC 不可当普通桌面读取。需要用户选窗的隔离截图，再选 WGC，不把 GDI 当任意后台窗口捕获器。 |

### Windows 句柄、DPI、ARGB 与输入

- **窗口发现与复核**：`GetWindowThreadProcessId` 是 HWND→PID 的系统关联；`AutomationElement.FromHandle(hwnd)` 是 UIA subtree root。HWND 可在原进程退出后或同一进程重建窗口后复用，`IsWindow(hwnd)` 单独检查不足以证明是原窗口；在会话注册时把句柄、PID、process creation time、class name、UIA root runtime id 一起固定，每次动作前重验。UIA node `ProcessId` / `NativeWindowHandle` 以及 `AutomationId` 用来缩小节点范围；`NativeWindowHandle=0` 是合法情况，不把子控件要求成 HWND。若 provider 把 UIA root/node 映射到不同 PID，不能只按标题放行，应由宿主基于原 root HWND 的树关系明确允许或拒绝。
- **统一物理坐标**：Microsoft UIA 缩放文档明确 `BoundingRectangle` / `GetClickablePoint` 使用物理屏幕坐标，而常见 Win32 API 对 DPI-unaware caller 会虚拟化为逻辑坐标。启动时、第一次建 HWND/Graphics 之前设 `PER_MONITOR_AWARE_V2`；用 `EnumDisplayMonitors`/`GetMonitorInfo` 或 WinForms `SystemInformation.VirtualScreen` 取负原点也可表达的虚拟桌面 rect，并用同一 physical-pixel 标尺进行截图与 `SetCursorPos`。若 helper 不带 WinForms，就用 User32 monitor APIs。每个 monitor 保存 `{deviceName,rcMonitor,rcWork,dpiX,dpiY,rotation}`；混合缩放下禁止单一 `scaleFactor` 覆盖所有输出。
- **ARGB 规范化**：使用 `Graphics.CopyFromScreen(virtualRect.Location, ..., virtualRect.Size, SourceCopy)` 生成单张虚拟桌面 bitmap；若需要读到 layered windows，评估 `SourceCopy | CaptureBlt`。按 `Format32bppArgb` `LockBits` 读取时遵守 `BitmapData.Stride`（包括负 stride），不要把内存中的 32-bit 字节顺序直接冒充协议 RGBA。常见 little-endian `Format32bppArgb` byte layout 是 BGRA；截图编码前逐行转到协议约定的 RGBA/PNG，并为 GDI source copy 的 alpha 字节显式写 255，而不是依赖复制到的 alpha 值。每帧携带 virtualRect、raster 大小、rotation、`frameId`。
- **点击/拖拽/滚动**：屏幕点击先 `SetCursorPos(x,y)`，然后 `SendInput` 左/右/中 button down/up；拖拽将 `down → move… → up` 作为有清理责任的一次操作；滚动通过 `MOUSEEVENTF_WHEEL` / `MOUSEEVENTF_HWHEEL`，`MOUSEINPUT.mouseData` 使用滚轮 delta（标准一格 `WHEEL_DELTA=120`）。若用 `MOUSEEVENTF_ABSOLUTE`，需要正确加入 `MOUSEEVENTF_VIRTUALDESK`，按 `ax=round((x-vx)*65535/(vw-1))`、`ay=round((y-vy)*65535/(vh-1))` 将虚拟桌面像素映射到 0–65535（`vx,vy,vw,vh` 来自整个 virtual screen）；不要拿单显示器尺寸换算多屏点。
- **Unicode 与清理**：UIA `ValuePattern.SetValue(string)` 是替换控件整个 Value 的语义，先验 `IsReadOnly` 并只在产品请求“设置全文”时使用。UIA `TextPattern` 是观察/选择接口，不提供通用插入方法；要保留现有值并在焦点处追加，使用 `SendInput(KEYEVENTF_UNICODE)` 或临时剪贴板 `CF_UNICODETEXT` + paste，非 BMP 字符按 UTF-16 surrogate pair 发键事件并最终重新观察。clipboard fallback 要保存并在 `finally` 尽力恢复原剪贴板内容，并在用户授权、会话互斥下执行；不要把内容写入日志。注入仍会受 UIPI 限制，而且部分控件只接受自己的输入模型。helper 维护本次已按下 keys/buttons；任何异常/取消都尽力补对应 key-up/button-up。外层 deadline 终止阻塞 UIA helper 只能收回进程，不能撤销已注入事件，结果记 `actionSent=unknown|true` 并要求重新观察。

### Linux X11、AT-SPI 与 Wayland portal

- **X11 输入与句柄**：`xdotool search --pid PID` 源码支持 `_NET_WM_PID` 查询，但 upstream 明确该属性“不被所有 X11 应用支持”；`getwindowpid XID` 无 PID 时返回失败。把 PID 和 `/proc/PID/stat` 启动时刻与 XID/WM_CLASS 固定，动作前重新查窗口属性以防 XID 在同一 app 内重建/复用；如果窗口无 `_NET_WM_PID`，需要明确 unsupported / 由用户重新选中窗口，不能悄悄按标题猜。X11 app 运行窗口都在一个 X screen root 坐标域内；`xrandr --listmonitors` 用来获取当前输出矩形，截图以 root XImage 的 `width/height/bytes_per_line/byte_order/visual RGB masks` 解出像素再转 RGBA。XImage 的原始通道布局由 visual 决定，不能假定所有 Linux 桌面都是 BGRA。
- **动作 API**：`xdotool mousemove --sync X Y` 全屏坐标，`click 1/2/3` 为鼠标键，`click 4/5` 为垂直滚轮，`mousedown 1 → mousemove --sync → mouseup 1` 可做 drag。注意 upstream 的 `--sync` 只等“鼠标开始移动”，不保证到达目标。取消或异常时保底发 `mouseup` 和键盘释放；如果 helper 整体被 kill，动作状态仍是不确定。
- **Unicode 与语义动作**：AT-SPI `Component.GetExtents(ATSPI_COORD_TYPE_SCREEN)` 给可见节点坐标，`Action.DoAction(i)` 调用语义动作；`EditableText.SetTextContents` / `InsertText` 接受 UTF-8，可作为 Unicode 文本首选。`SetTextContents` 会替换整个文本框内容，光标位置插入使用 `InsertText(position, utf8, byteLength)` 并重新观察光标/内容。`xdotool type` 通过 XTEST + 当前 XKB/keymap 模拟键击（源码支持 stdin `--file -`，避免文本出现在 argv），不要把这一机制当所有 IME/Unicode 符号的无损字符注入接口；不可编辑控件需走字符/键盘布局兼容回退或报告 unsupported。
- **Wayland 请求与回收**：`RemoteDesktop` 的 D-Bus `CreateSession()`、`SelectDevices(types=KEYBOARD|POINTER)`、`Start()` 返回 Portal `Request` handle；`Start` response 0=success、1=user cancelled、2=other。要截图再在相同 session 调 `ScreenCast.SelectSources()` 与 `OpenPipeWireRemote()`；ScreenCast Start 的 D-Bus stream properties 明确有 position/size/source_type；position/size 是 compositor coordinate space，文档警告可能不等于 pixel space。PipeWire buffer 的实际尺寸/格式从 video format 读取。接口 v6 推荐用 `pipewire-serial`/`PW_KEY_TARGET_OBJECT` 建立 PipeWire 连接，不把可复用 node id 当 stream identity；RemoteDesktop 的 `NotifyPointerMotionAbsolute` 参数仍按 D-Bus 签名传同 session 返回的 stream id，坐标遵循 portal 定义的 stream logical coordinate space，不能以 raster 宽高推导。RemoteDesktop 文档指向 stream `logical_size`；如果当前 portal backend/stream 没有可读的 logical→pixel 映射，就不要伪造绝对坐标换算或回退成 xdotool。button 使用 Linux evdev 编码与 press/release state，scroll 用 `NotifyPointerAxis` / `NotifyPointerAxisDiscrete`。文本不能经 keysym API 直接发送 Unicode 字符串；可用 AT-SPI EditableText，或仅在 portal clipboard 能力获用户授权后再用 paste。
- **取消清理**：每个异步 portal call 先订阅 Request.Response；deadline 时 `Request.Close()` 结束等待中的授权交互。已启动 session 在释放时调用 portal `Session.Close()` 并监听 `Closed`，断开 PipeWire stream、关闭收到的 fd、销毁 EIS context；任何已按下的 keys/buttons 要先 best-effort release。X11 用子进程超时 + `finally` 释放按键/鼠标；AT-SPI D-Bus call 可取消本地等待，但服务端已经执行的 action 仍需标记不确定。不要把退出 helper 等同于 undo。

## 可部署补足方案

**阶段性路径（建议）**：

1. **共通协议先行**：保持主进程拥有用户确认、目标 app/display/window 绑定、action lease、`actionSent` 语义、frame-id 坐标绑定、超时与终态。按 capability 分项报告 `captureDisplay` / `captureWindow` / `accessibilityTree` / `syntheticInput` / `clipboard`，各项可 `available / needs-user-grant / unsupported / blocked`，不因一个维度失败就假报整体可用。
2. **native library 作为可选原语层**：nut-js 可留在键鼠原语与 X11 路径，减少重复底层代码；macOS 已有 TCC/JXA 路径可继续演进但截图需走可被签名宿主正确授权的 ScreenCaptureKit 或经实机证明的替代实现；Windows 第一版可用 UIA + User32 + GDI/System.Drawing，需隔离捕获窗口时再用 WGC；Linux X11 可先用 XTEST + AT-SPI，Wayland 用 portal ScreenCast + RemoteDesktop/PipeWire。`InputCapture` 是门户提供应用拦截物理输入的 API，不用于 Agent 注入输入。给每种 helper 设置明确发布 OS/架构包与原生依赖。
3. **宿主 helper 封装原生边界**：当原生库在 Node 同步阻塞、权限主体不稳定、或平台 FFI 不便维护时，拆一个按 OS 打包、只提供窄 RPC 的桌面 helper。macOS helper 用签名 app 建立稳定 TCC 主体；Windows helper 以交互登录用户会话运行；Linux helper 附着活动 compositor/portal session。helper 只暴露本协议能力，不把任意 Shell 作为 CUA 后端能力。
4. **第三方 MCP 经 adapter，不直连 agent loop**：如用户明确配置外部 MCP，则通过本机 stdio 或只监听回环、Bearer 鉴权的 HTTP 连接；对 tool 做版本锁定与 allowlist；每个动作仍经过 KFW 自有审批、预算、事件/截图脱敏与取消处理；原 MCP 标为执行 provider 插件。进程崩溃/断连时把动作结果标为可能已发出，不能自动重试非幂等动作。

**安装 / 发布护栏**：锁文件固定 nut 及 optional platform packages；CI 构建/发布矩阵要逐个验证 macOS universal、Windows x64/arm64、Linux x64/arm64。Windows C# helper 可 self-contained 发版，避免用户另装 Desktop Runtime；framework-dependent 变体须明确 .NET Desktop Runtime 最低版本。Linux Debian/Ubuntu runtime package names commonly include `xdotool`、`x11-xserver-utils`（含 `xrandr`）、`at-spi2-core`、`libx11-6`、`libxtst6`、`libxrandr2`；Wayland 需 `xdg-desktop-portal`、当前桌面 portal backend 与 PipeWire runtime。各 distro 包名及 license notice 可能不同；运行时先 probe，不能用 sudo/包管理器替用户安装。Linux 应在 X11 和 Wayland 两类桌面会话分开校验；声明支持 Wayland 时需确认 portal backend/PipeWire 而非仅 XWayland。发布工件应带原生 helper/动态依赖说明；安装或运行前输出清楚的依赖缺失诊断。仓库现有 macOS 权限检查包只有 macOS 平台属性，不应让 Windows/Linux 安装链导入该包。

**取消 / 超时纪律**：host 层 deadline 只能限制等待，除非底层明确支持 abort，不能表述成“已取消输入”。动作越过原生调用边界后返回取消/超时时要带 `actionSent=unknown|true`，通知 agent 重新观察，不得自动重放。对卡住的原生同步调用，需要可终止 helper 进程，但先把动作记为不确定；terminate 不能撤销 OS 已接受的按键/点击。对长时间屏幕采集可在 stream/session API 层停止订阅并释放 frame pool。

## 待实机验证的验收矩阵

- **机器/会话**：macOS 最终签名桌面包；Windows 10/11 交互登录会话与普通用户/管理员窗口；Ubuntu GNOME Wayland、KDE Wayland、一个 X11 会话。另验证无用户登录、锁屏、UAC/系统授权对话框时的明确失败原因。
- **显示器/坐标**：单显示器 Retina/HiDPI；两台不同 scale 的显示器；副屏在左侧/上方导致负原点；不同旋转方向；捕获窗口部分跨屏、最小化/遮挡。将模型看到的 raster 上 4 个角、中心和 element bounds 转成点击坐标往返校验，检查越界和显示器边缘误差。
- **授权**：macOS 三个 TCC 授权分别缺失/允许/撤回；Windows WGC 用户 source picker cancel/allow、UIA provider 缺失、SendInput 的 UIPI 阻止；Wayland portal 同意/拒绝与 portal service/backend 缺失。状态回报需与真实捕获像素及输入结果相互校验。
- **取消/故障**：调用开始前取消、native capture 卡住、点击已发出后 helper kill、stdio 断连、用户撤权时并发动作。断言宿主不会把超时当成未执行后重试，并会刷新观察状态。
- **发布依赖**：OS × CPU 下 fresh install 产物、动态链接依赖、签名/公证、增量升级后权限持续性；不靠开发机全局 Xcode/CMake/Python 依赖掩盖打包缺项。
