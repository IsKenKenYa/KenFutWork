# CAD 控制插件规划

> 角色：实施规格。2026-10-18 经用户逐项确认，方向属主见《改造计划》`DEC-22`；官方资料与证据见《[CAD官方接口与插件接入调研](../调研/CAD官方接口与插件接入调研.md)》。本文件不把参考附件中的方案当作已落地实现。

## 已确认的产品方向

- Agent 按用户指引或其它输入制作 2D／3D CAD；Code／Design 共用官方插件，不新增工作方式。未来 Work 仅保留复用方向，本轮不实现 Work。
- FreeCAD 后台独立工程与当前 GUI 文档控制分层：前者不接管可见应用；后者须显式选择目标并按权限审批，不自动关闭用户未保存的工程。
- 参数化零件完整流程优先：草图、约束、尺寸修改、拉伸／切除／旋转、布尔、圆角／倒角、阵列、重算、工程图与文件交换。装配、CAM、FEM、BIM 逐项研究，不把首件样例验收扩大成这些工作台已验收。
- 常用操作提供结构化工具，复杂操作允许完整 FreeCAD Python；脚本走当前 Task 的真实目录权限、审批、授权代际及取消。用户已覆盖附件中“禁止任意 Python”的限制。
- 返回原生可编辑 FCStd、按需交换文件和真实几何预览；不以网格或图片替代参数工程，不要求安装 Blender 才能使用 FreeCAD。
- AutoCAD、Blender 仅完成本轮官方接口研究；不擅自安装，不宣称本机通过。

## 首个纵向切片

官方市场 bundle 承载安装／启用状态，可信服务端 feature 提供服务接口、运行时实现与工具消费方。沿已有 profile、动态工具注册与按需发现接线，安装态在调用时重验。无需新 HTTP 路由或数据库表；如果后续新增契约／路由，按既有 shared→OpenAPI→Apifox AI 分支单源链执行。

执行绑定实例、持久 Task、分支代际、Run 与工具调用身份。CAD 运行时由宿主发现，精确运行树仅为该次进程增加只读授权；不能由模型路径签发任意宿主读权限，也不扩大 Task 写域。应用配置、缓存和临时文件放在本次执行目录，不改用户 FreeCAD 配置或向其解释器安装依赖。

Run／Task 取消覆盖后台启动等待：派发前中止本调用等待，派发后按原连接和原参数身份取得禁止派发或范围清空回执，未知停止状态保留屏障。helper 受理取消前存在跨进程传递时间，不承诺该时段零执行；返回句柄后的取消继续等待真实停止。共享准备在 Task 关闭时收束，单调用取消不终止其它调用的共享证明。

每次执行使用独立进程及请求／回执文件；stdout 噪声不作为成功协议。Stop／撤权后要确认进程范围清空，取消后的迟到回执不发布成功。默认保存新版本；修改输入工程时先建立独立副本，已有输出文件拒绝覆盖，同调用并发只执行一次。

创建／修改工程使用独立的 Qt 离屏 GUI 宿主，让 FreeCAD 官方保存器同时持久化视图状态；不连接用户可见应用，不手工拼接 `GuiDocument.xml`。检查、投影与交换操作仍用核心事件宿主。建模脚本可显式设置对象 `Visibility`，宿主不强制显示全部历史特征；离屏状态不承诺 OpenGL 截图，模型预览继续使用真实几何线框。

## 常用结构化操作

`cad_apply_operations` 复用既有 Task、审批、安装门控与新文件发布，不引入独立运行链路。输入为按序执行的 `operations`，支持 `create_body`、`create_sketch`、`create_pad`、`create_pocket`、`create_revolution`、`create_boolean` 与 `set_dimension`；同一 Sketch 的 `profiles` 可同时含矩形与圆，轮廓名不得重复。内部直接用已解析的 JSON 调可信 API，不将参数拼成 Python 源码执行。

矩形宽高与圆半径为正毫米数；`origin`／`center` 为固定绝对二维坐标，默认 `[0,0]`。固定位置只保证请求时的位置，不暗含改尺寸后相对居中。创建的矩形使用闭合、水平／垂直、位置与有向宽高约束，圆使用位置与半径约束；驱动尺寸命名为 `轮廓名_Width`／`_Height`／`_Radius`。`set_dimension` 只接受唯一、类型匹配的命名驱动尺寸，拒绝参考／停用约束和已有表达式，不解除用户已有关系。操作后须求解成功、完全约束并回读生效数值。

内部对象名称若已存在或被 FreeCAD 自动改名则明确失败，中文显示可用 `label`。每步回执 `data.operations` 含序号、操作类型、实际对象、求解状态及实际读取的命名尺寸。失败标明操作序号与原因，不发布最终文件；输入工程仍只读。工作副本／诊断文件的创建不是数据库事务，不承诺中间副作用全部回滚。空 Body 中途可存在，批末仍执行既有完整几何校验。圆角／倒角及阵列等常用封装继续分批交付，复杂形态仍由完整 Python 承接。


### 拉伸、切除与厚度联动

`create_pad` 显式指定 `body`、`profile`、`length`，提供 Body 内首个正向 XY、单侧、定长拉伸。`create_sketch.supportPad` 在同一 Body 的自由孔草图上，用固定的 `Placement.Base.z = Pad.Length` 表达式跟随当前 Pad；不引用易变的 Face 编号。草图二维坐标仍固定，厚度联动不等于相对居中。

`create_pocket` 显式指定 `body` 与 `profile`，作用于当前 Tip 的基础 Pad；孔草图须绑定此 Pad。`mode:depth` 必须提供正数 `depth`，`mode:through_all` 不接受 `depth`。不猜 ActiveBody、不重用其它 Body 或已被特征消费的草图、不静默重绑定过时支持或替换已有 Tip。更广的附着面、多侧／反向拉伸及特征链由 Python 承接，结构化入口不会把它们错误解释成这条基础链。

`set_dimension` 的 `length` 对应定长 Pad，`depth` 对应有限 Pocket；这两类不传 `profile`，也不解除已有 Length 表达式。草图宽高／半径仍必须带 `profile`。修改后重算并检查真实属性、单实体及实际材料切除；保留最终 Pocket Tip 与既有可见性。新特征只隐藏被消费草图与旧 Tip、显示新特征，不统一改写 Body 或其它对象的可见性。

操作回执在原序号／对象信息外，记录实际 Body、Profile、BaseFeature、当前 Tip、长度或切除模式、实体数和体积；孔草图另记录实际局部 Z 与支持 Pad。每步回执反映该步完成时的状态，最终文件的状态由整批末尾校验与重新打开验收确认。

### 旋转与角度联动

`create_revolution` 指定 `body`、`profile`、`axis` 与 `angle`。它是同 Body 的首个实体特征，轮廓为自由 XY 草图；`axis:x/y` 分别绑定本草图的局部 H／V 轴，按右手方向正向单侧旋转。角度单位为度，范围 `(0,360]`；长度和草图尺寸仍为毫米。矩形可形成环形柱或部分扇段，轴外圆可形成环体；跨轴自交、多实体或无效几何明确失败，不交付旧 Shape。

`set_dimension` 的 `angle` 不带 `profile`，只修改上述固定角 Revolution，拒绝反向、对称、多角、已有基体或外部基准轴等其它配置；不解除已有 Angle 表达式。草图宽高／半径修改仍沿命名尺寸路径，重算后核对旋转体及实际 Body／Tip。修改上游旋转保持现有后继 Tip 和可见性；下游失效则拒绝发布，源文件保持不变。回执追加实际 `axis`、`angle`，同时保留 Body、Profile、BaseFeature、Tip、实体数和体积。任意放置、外部轴、多侧或后续增材旋转由完整 Python 承接。

### Body 参数化布尔

`create_boolean` 指定目标 `body`、非空且唯一的 `toolBodies` 与 `operation:fuse/cut/common`，创建真实 `PartDesign::Boolean`，保留 `BaseFeature`、工具 `Group` 和当前 `Body.Tip`。目标与工具都须有所属、有效的单实体 Tip；不接受目标自身、已被其它 Boolean 使用的工具 Body、已有对象名、失效或空结果。工具 Body 隐藏，旧目标 Tip 隐藏，新特征显示；不把已消费的工具移动到另一个 Boolean 破坏旧参数链。无交集 cut 是合法的参数化结果，可保持原体；fuse 的不连通多实体及 common 的空结果拒绝发布。

回执增加实际 `operation`、`bodyName`、`baseFeatureName`、`toolBodyNames`、`tip`、体积和实体数。调用前检查工具的递归依赖，不能把已依赖目标 Body 的下游消费者反向作为工具制造循环；只引用旧基体属性的合法共享上游仍可使用，再由原生重算核验。源工程只读，失败不发布新FCStd，也不以残留旧Shape冒充成功。多工具 Common 沿用 FreeCAD 原生 Objects／Tools 算法，不偷偷改成顺序求交；即使原生报告 Shape valid，结果仍须单实体。需要依次求交时，按序创建多个单工具 Common，保留每层真实参数引用。后续用既有尺寸工具或Python修改上游，再保存重开核验参数与最终几何。安装版实证范围和未覆盖条件由《日志》及主调研矩阵记账。

## 几何与产物判定

`recompute()` 的返回值是重算数量，不能当成功布尔值。对象错误状态、非空 Shape、有效性、实体数以及任务特定的尺寸／体积分别检查。`check()` 对空 Shape 不抛异常不能当成功。2D 草图可不包含实体，须由任务显式采用对应判定。无 Tip 且仅含有效草图几何的 Body 可以没有聚合 Shape，其包围盒返回 null；草图自身仍逐项校验，普通空 Feature、空 Body、有实体特征却缺 Tip 或坏 Pad 不适用。Python 三维任务显式设置 `requireSolids:true`。

`documentPath` 仅用于读取已有工程，新建省略；`outputPath` 是工具最终发布的新路径。Python 中的保存重开验证使用 `output_directory` 暂存，最终保留 `doc` 交给工具保存，不先写占用 `outputPath`。

PartDesign 必须显式核对最终 `Body.Tip`，脚本中计算正确的最后特征不代表 Body 自动指向它；导出目标是实际需要的 Body／最终对象，不导出全部中间特征。保存后重开、导出后重新导入分别验收。拓扑边索引不是跨参数变化的永久身份；修改后重新解析并验证。

后台图纸投影与 GUI 视图导出分别标能力。TechDraw 投影有 Qt 事件循环条件；完整工程图的 PDF／SVG、可见 GUI 文档截图和后台线框预览不混称。预览必须由当前工程几何生成，确认非空并核对视角；图片只进入模型多模态内容，持久回执保留路径与元数据，不保存 base64。

| 批次 | 行为 | 关键判据 |
| --- | --- | --- |
| A | 精确运行树与 FreeCAD 所需 CPU 特性读取 | 当前 Task 可读指定应用、不能写该应用／读同级应用；下一进程不继承授权；撤权停止；实际 FreeCAD 建模成功 |
| B | 官方插件、结构化工具与 Python | 安装门控、两模式工具发现、严格审批证据、输出与代际复验、真实草图→特征→尺寸修改→FCStd→交换文件 |
| C | 真实几何预览与 2D 交换 | SVG 投影边界与方向正确；PNG 可解码且非空；模型视觉块与持久元数据分离；已有输出不覆盖 |
| D | 当前 GUI 文档控制 | 显式选择文档、未保存状态与撤销、保存审批、主线程调度、取消不误杀用户应用；另行逐项验收 |
| E | 其它 FreeCAD 工作台与其它应用 | 每项登记接口、依赖、运行形态、样例与失败边界；未安装 AutoCAD／Blender 仅记录文档证据 |

E 的 Assembly、CAM／Path、FEM、BIM／Arch／Draft 官方接口及本机安装依赖已在[专业工作台核验](../调研/FreeCAD专业工作台接口核验.md)逐项登记；代表流程、成功判据和失败范围仍为待执行方案，不把文件存在或可调用入口当专业任务已通过。后续先走独立工程与既有后台Python／真实Task链，按证据再决定是否增加专业结构化工具。

D 的首个切片为 `cad_gui_status`：macOS 从 NSWorkspace 读取实际运行的 GUI 实例，核验同一真实安装树中的官方启动器或内部 GUI 可执行文件，返回 PID、系统报告的启动时间、内核出生身份和规范路径。LaunchServices 的启动时间不换算成内核出生时间；两者各自保留。多个安装不按 bundleId 合并，不以默认安装位置替代实际进程；FreeCADCmd 不算 GUI。查询经既有插件安装门控、真实 Task、授权代际和取消，10 秒内结束，返回前重新校验。其它平台明确返回不支持，未运行应用正常返回空列表。

该工具不读取文档、启动应用、调度 GUI Python 或授予外部应用 Task 沙箱身份。内部身份复核拒绝 PID／启动时间／安装路径改变，系统启动时间只用于只读身份检查，不宣称外部进程已被接管。直接修改当前文档仍须按 D 批次单独实现与验收。

文档清单切片为 `cad_gui_documents`：输入只能是上述完整应用身份，服务端创建私有固定查询宏，经该进程实际持有的官方 socket 发送；在同一连接发送前核对 peer PID、内核出生身份和可执行路径。返回原生名称、文件名、UID、Modified／touched／pendingTransaction 与活动状态，不读取几何或任意属性，不保存、重算、关闭或修改文档。Name／Uid 是观察快照，后续修改仍需独立的每次打开句柄与观察修订，不能直接沿用它们作为编辑授权。

查询 v2 在外部 GUI 保留 App／Gui 事件观察器：桥代际 `bridgeEpoch`、每次打开的新 `documentHandle`、全局 `applicationRevision` 与文档 `revision` 随快照返回。只有明确给定文档的 App 事件定向计数；对象／Gui 事件只增加全局计数，不为定位而解引用正在删除的代理，也不扫描全部 Objects。关闭先使旧句柄失效，确认已离开实际文档清单后释放代理；同名、同 UID 重开仍签新句柄。无动作查询不重装观察器或自增计数；回调异常使旧桥失效，新观察换桥代际。失败回执使用空文档及 null 身份，不伪造有效句柄。

`clearDocument()`／`restore()` 可能在同一 Python 文档对象上发出 Delete→Created；显式 Created 是新的打开代际，可以移除该对象的旧墓碑并签新句柄，普通枚举不能解除墓碑。Created 还可能早于文件恢复开始，不能在回调里据此宣布内容已准备好。此原生分支已回归，不能只用“对象 `is` 不变”维持原句柄。

这些修订是**已收到事件和查询时元数据差异的观察计数**，不是完整内容版本／保存版本。`touch()` 和直接清除 GUI Modified 没有对应 Python observer 信号，查询时重读并比较；查询间修改后恢复原值的过程不能由此完整检测。未来编辑必须同时复验桥代际、打开句柄、全局／文档观察前提、当前原生状态及被修改属性，不能仅凭计数授予权限或宣称原子并发控制。恢复／部分加载／重算／编辑态与未结束事务分别验收；不借用错误 ID 的全局事务关闭 API 当锁。本切片仍不暴露编辑工具。

固定宏加载属于外部 GUI 执行，会改变 FreeCAD 文件对话框工作目录；工具标为 `access:execute`，审批 kind 为 `cad-gui-inspect`，审批证据明确 GUI 不继承 Task OS 沙箱。只读 Task 不派发。同 Task／Run／toolCall 并发及重放复用原查询结果，换参拒绝；匹配回执、应用身份和授权代际均复验后才发布元数据。无业务回执的超时／取消保留未知送达状态和排队宏，不自动重发、不终止用户应用。私有文件保留规则见《隐私政策》§4.2。此切片不接管文档事务或 GUI 内任意 Python。

`cad_gui_inspect_document` 复用同一固定查询管线：输入上述完整应用身份、桥代际、打开句柄及预期全局／文档观察修订；省略 `objectNames` 只列对象名称、标签和类型，指定唯一对象名才读取直接标量属性。读取前后及原生 getter 之间复验目标；失效快照或缺失对象返回可读原因，不使健康桥换代。值覆盖布尔、有限数值、安全整数、字符串和带八维单位签名的 Quantity，另读取只读／不可变标志及直接属性表达式；枚举仅报告当前值，暂不承诺编辑，复杂类型仅报告不支持原因。实际属性所有者须为目标对象，不把 Link 转发值作为该对象可编辑属性。读取不修改、重算或保存工程，但会执行外部文档的属性 getter，审批证据与隐私说明明确该边界。`editable` 是受控修改的类型条件，不是权限或写入成功；读取本身不修改、保存或撤销，属性写入由下文独立工具承接。

当前活动文档的直接标量写入由 `cad_gui_set_properties` 承接，参数包含持久 `operationId`、同样的目标快照与每项预期／修改值；`cad_gui_operation_status` 只按宿主持有的实例／Task 读取该编号，不连接或重发 GUI。整批先验证实际属性所有者、原生类型、标志、表达式、当前值、单位维度及文档／事务状态；全相等时 no-op，不开事务、不重算。实际变更使用唯一原生事务，逐步读回、按需重算并核对结果后提交，保留其它表达式。枚举、复杂类型和含 Python Proxy 的对象暂不接受此固定写入，复杂建模仍使用后台 Python。GUI 写入明确独立审批，仍不继承 Task OS 沙箱，也不自动保存源文件。

成功属性提交可在确认自身准确事务名、Undo／Redo名称摘要与原生计数一致、提交后快照可用时，携带 `undoProvenance`。宿主同时核验该快照的桥代际、打开句柄与原请求一致，观察修订未倒退。它记录事务归属，不授予撤销权限；完整历史名称不写入回执。历史或快照不能可靠确认时，保留实际 `committed` 结果但不签该字段；旧无字段回执仍可查询，不能按事务名前缀猜测用户历史项。

显式撤销由 `cad_gui_undo_operation` 承接：新 `operationId` 引用同一实例／Task 的 `sourceOperationId`，原操作须有可信 committed 回执、归属及提交后快照。首次准备由宿主冻结原请求与回执，模型不得提交证明正文、事务名、代码或私有路径。新 Run 使用当前 Task 的 scope／branch 代际、插件门控及独立 `cad-gui-undo` 执行审批；原记录可来自历史授权代际，其作用仅为历史归属，不能代替当前准入。应用身份沿用原操作，桥代际、打开句柄和两个预期修订必须严格等于原提交快照，不允许通过新 inspect 刷新已经变化的撤销前提。

预检复核自身准确栈顶、完整历史摘要、当前值与原 observed 值，拒绝 pending／活动事务、编辑或恢复态、后来事务及外部引用方；不因目标单纯具有向外依赖就一刀切。仅调用一次原生 App `doc.undo()`，不重算、redo、保存、关闭或处理用户事务；原生 apply 中为 Redo 建立的临时 pending 属正常状态，返回后仍须确认事务结束、目标事件、原 before 值及历史转移。成功报告 `undone`，partial 保留现场，不作自动补偿。新撤销记录自带冻结来源，同编号终态重放不依赖原修改记录或 GUI 存活；unknown 不重发，不能用新编号绕过历史／观察前提。真实工具链及未覆盖范围见[桥接接口核验](../调研/FreeCAD当前文档桥接接口核验.md)第15节。

实例私有目录持久发布不可变请求和固定宏，派发认领与 GUI 执行认领分别在临时文件写齐／fsync 后用不覆盖的硬链接发布；已有认领或回执不重发，记录不随 Run／插件生命周期删除。固定准备时间加首次超时设置决定过期，不因新 Run／重启延长；执行设置不限时时，GUI 写操作默认等待60秒，超时保留状态、不终止原生调用；状态读取允许恢复旧结果，派发仍核对当前 Task／授权代际及实现。只有匹配原参数、幂等编号、指纹、进程和语义的回执才报告成功；认领后无可信回执保持 unknown，不声称最终恰好一次。原生提交与文件回执不是原子事务。

固定写入在每次原生调用之间检查取消／过期、目标活性、控制文件身份和事务；控制文件丢失、重入或不可确认的改变停止后续步骤，保留现场，报告 partial／unknown，不在 finally 盲 abort／undo。原生 API 缺少事务 CAS，故不承诺任意工作台回调下整批原子性；不关闭后来用户事务。当前目标须活动、可撤销且全部文档无待提交事务，恢复、部分加载、重算或编辑态拒绝。取消不能中断已开始的原生函数，不能终止用户 FreeCAD；未知结果先查同一编号及现场，不换新编号盲重试。磁盘回执 64KiB 是该固定 JSON 协议的格式边界，超出时在读取文档前用小回执拒绝，不是工程文件或工作区容量预算。覆盖保存源文件仍为后续切片。

GUI 文档副本切片为 `cad_gui_copy_document`：沿用最新应用身份、桥代际、文档打开句柄、两个预期修订及持久 `operationId`，可显式选择非活动文档。固定宏仅向本次实例私有操作目录的 `document.FCStd` 调用原生 `saveCopy`，不切活动文档、不覆盖保存源文件、不重算、清脏或处理用户事务。保存可以调用工程 provider，不整对象拒绝 Python Proxy；执行审批明确外部 GUI 不继承 Task OS 沙箱，只读 Task 不派发。恢复、部分加载、重算、原生事务或编辑未结束时拒绝；首期还拒绝外部依赖、引用者及无法可靠解释的外链，具体官方接口及安装版事实归[桥接接口核验](../调研/FreeCAD当前文档桥接接口核验.md)第13节。

副本只在确认私有新文件为稳定常规文件、完整 FCStd ZIP 含 `Document.xml`／`GuiDocument.xml`、CRC 与 SHA-256／大小可复验，并且观察到的源状态、打开身份、活动文档及 Undo／Redo 历史保持后报告 `copied`。该状态只表示私有副本，不代表 Task 文件发布；`statePreserved` 仅指已观察的原生状态，不是完整内容 CAS。宿主随后重新核对真实 Task、授权代际和停止状态，通过既有新文件发布能力写入 `outputPath`，默认 `.kfw-cad/gui-snapshots/操作编号.FCStd`，不覆盖已有文件，确认发布才报告 `published`。原生副本与 Task 发布分别认领／对账；状态查询不连接 FreeCAD，也不触发发布。原生操作、回执与发布之间的未知窗口不承诺回滚，不因无回执重发或换编号掩盖未知结果。

复制按内存工程原貌保存，可保留 touched 或错误模型，不以几何有效性作为副本保存的条件；需要几何检查时，由后续 `cad_describe_document` 在 Task 沙箱中打开发布文件验证。副本本体不套固定工作区字节预算，控制回执的格式上限不用于限制工程大小。本批已在独立 GUI 经真实 Task 验证内存副本→Task 发布→后台检查／改尺寸→STEP，另验未保存文档、其它文档 pending 拒绝及同编号重放／状态一致；原生状态、Undo／Redo、活动文档和源磁盘字节保持。准确样例及限制见[桥接接口核验](../调研/FreeCAD当前文档桥接接口核验.md)第13节，结果由《日志》同批记账，不扩大为用户现存 GUI 或任意 provider 已验收。

停用、卸载、替换和宿主关闭还会扫描本feature私有hash目录，将跨宿主留下的无回执请求持久取消；Run关闭只筛原来源Run。正常终态保留不改，不完整但未发布的slot不重建；有派发痕迹的损坏记录／不安全路径报stop_unconfirmed，并继续取消其它可验证记录。非hash旁杂文件不进入扫描，已知其它Run的宏损坏不阻断本Run关闭；全量插件撤销仍完整校验。持久取消失败保留准入屏障，不能靠启用事件绕过；成功重试撤销才可恢复。

官方 CAD 安装的生命周期精确绑定 `bundled__kenfutwork-cad`，同名本地包不签发此内置能力。首次成功装载前不注册 CAD 工具或提示段；撤销时先撤下贡献、阻止新派发、取消在途操作并等待收尾。原生后台进程停止未确认则保留屏障，不能以重新启用消除未知状态。成功重新激活才生成新代际，旧调用和旧 Run 需重新提交；运行内计数不冒充跨服务重启的持久 GUI 操作日志。只读 JXA 查询的取消目前证明调用结束，不作为用户应用或底层查询子进程均已退出的证明。

当前 macOS／Qt 6.8.3 的 `QMacAccessibilityElement` 崩溃已有本机日志与上游匹配证据。D 阶段默认采用固定原生桥及主线程调度，不通过 CUA／AX 读取用户 FreeCAD，也不以宏回执成功代表应用随后保持存活；须另验执行后的稳定性。GUI 内任意 Python 不继承后台 Task OS 沙箱，不能复用后台 `cad-python` 审批口径。当前文档身份应含每次打开的句柄和观察修订；只允许处理自己持有且仍匹配的事务，不跨后来用户事务盲目撤销。具体证据及未证实因果见调研记录。

测试由主线程串行运行：范围回归后执行 `pnpm test:workspace`、`pnpm exec turbo run test --concurrency=1`、`pnpm typecheck`、`pnpm lint`。真实应用测试使用明确开关，默认跳过；普通测试通过不替代真实 FreeCAD 或原生 KFW 验收。每批证据、SHA、遗留项在《日志》同提交记账。
