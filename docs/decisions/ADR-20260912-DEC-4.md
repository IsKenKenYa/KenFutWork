# ADR-20260912-DEC-4：权限默认档 = code 模式 default 档

> 状态：已采纳（2026-09-12，维护者）
> 原条目：《改造计划》§6 `DEC-4`

## 背景

《改造计划》§4.6 定义了三档权限策略（default / auto-approve / full-access）。P6 权限缝实现前必须定默认档，这直接决定 code 模式的安全底线与审批交互量。

## 决策

code preset 默认 **`default` 档**：危险/不可逆操作（execute/shell/文件写入/越工作区访问）触发 ask 审批，记忆粒度为 本次/本会话/永久；`auto-approve` 只放行命中已批准策略的调用；`full-access` 需明示开启 + 二次确认 + 全量审计。design preset 默认不激活权限闸门（画布操作危险度低，保持现有行为不变）。agent 无「自我授权为永久」路径，权限记忆只能由用户批准产生。

## 备选与取舍

- **默认 auto-approve**：审批交互少但 prompt injection 下一号风险不可控（§4.6 威胁模型），否决。
- **默认 full-access**：与「不可逆动作必过人审」红线直接冲突，否决。

## 后果

- 正面：安全底线清晰；审批记忆粒度让交互成本可控；与《多端产品设计》§7 沙箱策略分离（策略管要不要拦，沙箱管拦不住时的隔离）。
- 负面：code 模式初体验审批偏多，靠「永久」记忆粒度缓解。
- 同步：P6 `permissions` 缝默认值、审批 UI 记忆粒度、审计日志按本结论落地；design preset 配置不激活闸门。
- 重新评估条件：default 档审批通过率数据积累后，可评估按工具类放宽 auto-approve 策略表。
