# ADR-20260912-DEC-8：第三方插件生态 = 暂缓

> 状态：已采纳（2026-09-12，维护者）
> 原条目：《改造计划》§6 `DEC-8`

## 背景

《多端产品设计》曾隐含第三方插件生态承诺，与《改造计划》「不引入 Cordis/YAML 组合层、不做分发体系」的非目标冲突。本次双模式改造开工前必须消除该矛盾。

## 决策

**暂缓第三方插件安装/分发生态**。本次改造聚焦内部能力插件化（kernel + ctx key 缝 + capabilities 贡献点），不提供外部插件安装、分发、签名机制。开放贡献、封闭 key：第三方能力未来经 `ctx.tools`/`ctx.capabilities` 注册表型 key 进入，但分发体系（类似 `dsh plugin add`）不在本次范围。重新评估触发条件见《改造计划》§2.3（Cordis/dsh 出稳定版、出现可直接消费的高价值插件、或决定做热插拔生态）。

## 备选与取舍

- **本次就做生态**：需要插件分发格式、签名、兼容性矩阵与 YAML 组合层——全部是被否决的非目标，且 dsh 生态尚小，投入产出不成比例，否决。

## 后果

- 正面：消除文档矛盾（《多端产品设计》原生态承诺随本 ADR 失效）；改造交付面收敛。
- 负面：第三方开发者暂无官方接入路径，需在 README/CONTRIBUTING 写明边界。
- 同步：docs/README.md 登记表已标注 FORM-5 为 DEC-5 别名；本次不再修改《多端》冻结区之外的生态表述（其状态本就是概念稿）。
- 重新评估条件：《改造计划》§2.3 三条件任一成立。
