# ADR-20260912-DEC-3：执行模式边界 = v1 只做 agent + plan

> 状态：已采纳（2026-09-12，维护者）
> 原条目：《改造计划》§6 `DEC-3`

## 背景

《改造计划》§4.6 定义了 5 种执行模式（agent/plan/goal/loop/solo）。P6 开工前必须定 v1 边界，避免「大一统 mode 引擎」式过度建设。

## 决策

v1 只实现 `agent`（默认自主循环）与 `plan`（先规划待批准再执行）。`goal`/`loop`/`solo` 不做，但其扩展点（`agentModes` 缝 + `capabilities` 贡献）一次性建好，后续以独立能力包增量加入，不改 loop 代码。

## 备选与取舍

- **5 种全做**：goal/loop/solo 缺乏已验证的产品语义，过度建设；且模式是「引导不是强制」（§4.6 克制原则），先做两个跑通缝更稳，否决。
- **只做 agent（不做 plan）**：plan 是 code 模式差异化卖点（dsh `plan-mode` 参照），且权限审批流程依赖 plan 的「规划-批准-执行」节奏，否决。

## 后果

- 正面：v1 交付面收敛；`agentModes` 缝 + capabilities 贡献机制可被后续模式零改 loop 复用。
- 负面：goal/loop/solo 用户预期需在产品文档中标注「未提供」。
- 同步：P6 的 `agentModes` 缝实现只带两个内置模式；`capabilities` 贡献接口按开放设计落地。
- 重新评估条件：plan/agent 跑通后按用户反馈逐个增量评估 goal/loop/solo。
