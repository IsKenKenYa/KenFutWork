# decisions — 决策落地目录（ADR）

> 状态：目录规则（属主：ADR 文件命名与必填字段，见 `docs/README.md` 属主登记表）
> 用途：《改造计划》§6（`DEC-*`）与《多端产品设计》§14（`FORM-*`）的决策**拍板后**在此落 ADR；编号定义与登记表在 `docs/README.md`，本目录只存「已拍板」的记录。

## 与待决策清单的关系

| | 待决策清单 | ADR（本目录） |
| --- | --- | --- |
| 位置 | 《改造计划》§6 / 《多端》§14 | `docs/decisions/` |
| 内容 | 问题 + 候选 + 建议 | 结论 + 理由 + 后果 |
| 时机 | 拍板前 | 拍板后 |
| 编号 | 定义与登记表在 `docs/README.md` | 复用同一 ID，不新编号 |

**一个决策只有一个 ID**：若同一决策在两份清单各有一号（当前仅 `DEC-5` / `FORM-5`），引用一律用主 ID，别名见 `docs/README.md` 的「决策 ID 登记表」。

## 文件命名

```text
ADR-<YYYYMMDD>-<ID>.md
```

- `<YYYYMMDD>`：拍板日期（UTC），与 git 提交日期一致。
- `<ID>`：登记表在册的 `DEC-*` / `FORM-*` 编号（如 `DEC-1`、`FORM-3`），与登记表一致。
- 示例：`ADR-20260915-DEC-1.md`。

命名被 `scripts/check-docs.mjs` 校验（格式非法即失败），**不要**用中文名或自定义前缀——本目录是编号索引，不是普通文档。

## 必填字段（模板）

```markdown
# ADR-<YYYYMMDD>-<ID>：<决策标题>

> 状态：已采纳（<YYYY-MM-DD>，<拍板人/角色>）
> 原条目：《改造计划》§6 `DEC-x`（或《多端》§14 `FORM-x`）

## 背景
<!-- 为什么必须现在决定；约束与前提 -->

## 决策
<!-- 结论一句话；关键参数/边界写清 -->

## 备选与取舍
<!-- 评估过的其他选项，各自代价，为何不选 -->

## 后果
<!-- 正面影响 / 负面影响 / 需要同步修改的文档与代码 / 触发重新评估的条件 -->
```

## 落地时必须同步的三处

拍板后，除本目录新增 ADR 外，**同一 PR 内**还要：

1. 在《改造计划》§6（或《多端》§14）对应条目**就地标注结论与日期**，正文不要复述理由（理由在 ADR）。
2. 若结论改变了架构描述（ctx key、扩展点、缝、路线图），改对应的**权威章节**，不要在 ADR 里维护架构副本。
3. 若结论使 `future/03` 冻结区失真，按 `docs/README.md` 规则 3 走「变更冻结区」流程（PR 说明理由 + `--update-lock`）。
