# ADR-20260912-DEC-5：计费口径 = 桌面/自托管默认关闭 credits，迁移期保持现状

> 状态：已采纳（2026-09-12，维护者）
> 原条目：《改造计划》§6 `DEC-5`（《多端产品设计》§14 `FORM-5` 为其别名）

## 背景

2026-09-11 已决策去 Supabase 云托管，形态收敛为桌面本地 + 自托管。BYOK 自管模式下不存在平台计费的正当性，`credits/tierGuard/payments` 三件套的去留必须拍板，影响 P3 迁移中它们的 `enabled(env)` 判定。

## 决策

**目标态**：桌面/自托管形态下 credits/tierGuard/payments 默认 `enabled=false`（插件 `enabled(env)` 判定表达），usage 用量表（DEC-6）成为唯一计量。**迁移期**（当前代码仍运行在 Supabase 云）：credits 保持现状启用，行为不变——关闭动作随《多端产品设计》D3（自管 Postgres 落地）切换。商业化改为增值模型池/企业支持（FORM-7），不依赖平台云 credits。

## 备选与取舍

- **现在立即默认关闭**：会破坏现存云端部署的计费行为，违背「每个 PR 行为不变」纪律，否决。
- **永久保留 credits**：与去云托管决策矛盾——自管部署无法也不应依赖平台支付体系，否决。

## 后果

- 正面：BYOK 自管无平台计费的口径提前锁定；credits 代码以插件 `enabled` 收编，目标态零删除成本。
- 负面：迁移期两套计量并存（credits + usage），D3 切换时需一次显式迁移 PR。
- 同步：P3 credits/payments 插件的 `enabled` 语义按本结论实现（迁移期恒启用 + 表达式可关）；D3 落地时翻转默认值并落新 ADR 引用本条。
- 重新评估条件：D3 开工时复核。
