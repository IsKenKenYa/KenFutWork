# ADR-20260912-DEC-1：事件缝（3 个 agent-run 拦截事件）

> 状态：已采纳（2026-09-12，维护者）
> 原条目：《改造计划》§6 `DEC-1`

## 背景

《改造计划》v2 曾把事件系统列为非目标；v3 修订指出：code 模式的执行模式、权限控制、用量归属都要挂钩 agent 主循环，没有拦截缝只能硬编码进 loop，「一切皆插件」名不副实。P1 内核落地前必须先定事件缝的存在与形态。

## 决策

松绑「不建事件总线」：在 kernel 内建**最小事件缝**，只含 3 个 agent-run 事件——`pre-step`（waterfall，决定模型看到什么，可改写/拒绝）、`tool-pre-execute`（waterfall，权限/审批拦截）、`turn-stopping`（serial，收尾结算）。waterfall 监听器必须调 `next()` 委托。仍不建通用事件总线。

## 备选与取舍

- **维持零事件**：权限/模式/用量只能硬编码进 agent loop，违背插件化目标，否决。
- **通用事件总线（任意事件任意监听）**：扩展面失控、性能与调试成本高，且当前只有 3 个真实消费者，否决。

## 后果

- 正面：执行模式（§4.6）、权限缝、用量归属都可以做成插件；事件契约收敛在 3 个名字上，评审面小。
- 负面：新增事件必须评审并登记契约（《改造计划》§8 风险对策），有流程成本。
- 同步：`kernel/` 事件派发实现与 `packages/shared` 的 agent-run 事件契约按本结论落地。
- 重新评估条件：出现第 4 个真实事件需求时按 waterfall 机制扩展并新增 ADR。
