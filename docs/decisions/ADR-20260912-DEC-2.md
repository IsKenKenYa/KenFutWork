# ADR-20260912-DEC-2：design/code 模式承载 = agent preset（会话级）

> 状态：已采纳（2026-09-12，维护者）
> 原条目：《改造计划》§6 `DEC-2`

## 背景

design（画布）与 code（编码）两种产品模式需要确定承载方式：agent preset（会话级组合能力集）还是独立 profile（部署级装配）。这决定 P7 模式装配的形态与前端切换 UI 的粒度。

## 决策

采用 **agent preset**：design/code 是同一服务端进程内的两套能力集组合（design preset = 现有画布能力 + 基础能力层；code preset = agent 能力层 + 基础能力层），用户按会话切换，基础能力层始终挂载。`profiles/` 只承担进程/形态差异（server/worker/desktop/selfhost），不承担产品模式。

## 备选与取舍

- **独立 profile（部署级）**：切模式要重启或双部署，用户成本高，且两模式共享的基础能力层会被装配期割裂，否决。
- **两者都做**：无真实需求支撑部署级模式隔离，违反「不为投机灵活性堆抽象」，否决。

## 后果

- 正面：切换轻量、无需重启；与 dsh「给会话不同能力集 = 组合一个 agent preset」心智一致。
- 负面：两 preset 共享同一插件树，需要工具 scope 过滤机制（§4.5 已设计）防止能力越界。
- 同步：P7 的 preset 实现、前端模式切换 UI、`profiles/` 目录职责按本结论落地。
- 重新评估条件：出现「整站只跑单一模式」的真实部署诉求时再议。
