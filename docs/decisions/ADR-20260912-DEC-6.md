# ADR-20260912-DEC-6：用量统计 = BYOK v1 必备

> 状态：已采纳（2026-09-12，维护者）
> 原条目：《改造计划》§6 `DEC-6`

## 背景

BYOK 模式下用户用自己的 Key，但 agent 对话与图/视频生成仍消耗真实成本；credits 关闭后（DEC-5）需要替代计量手段。P4 开工前必须定用量统计是否 v1 必备。

## 决策

用量统计是 **BYOK v1 必备**。按《改造计划》§4.5 落地：两个采集点（agent 链路读 LangChain `streamUsage`、直连生成链路读 job 完成回调），均不新增事件，落同一张 `usage` 表（按 workspace/provider/model/run 维度）。credits 关闭后 usage 是唯一计量，直连生成不能留盲区。

## 备选与取舍

- **v1 不做（后置）**：credits 退役后将出现成本盲区，且改造期正是建表的最低成本窗口（P3 迁移提供了干净挂载点），否决。

## 后果

- 正面：BYOK 成本可见；为 DEC-5 的 credits 退役铺路；用量数据为后续商业化（FORM-7 增值模型池）提供依据。
- 负面：新增一张表与一条采集链路，P4 交付面增加。
- 同步：P4c 用量表迁移（走 `supabase/migrations`，目录名沿用）、`usage` ctx key、`capability-contracts.ts` 用量 schema 按本结论落地。
- 重新评估条件：无（已定必备）。
