# ADR-20260912-DEC-7：凭证安全边界 = v1 服务端加密落库 + 永不回传前端

> 状态：已采纳（2026-09-12，维护者）
> 原条目：《改造计划》§6 `DEC-7`

## 背景

BYOK 意味着用户 API Key 进入服务端存储。P4 `modelProviders` 缝实现前必须定凭证安全边界——「端到端 Key 不落服务端明文」方案复杂度显著更高，影响交付节奏。

## 决策

v1 凭证安全边界：**服务端加密落库 + 工作区隔离 + 永不回传前端**。`apiKeyRef → apiKey` 解析封装在 `modelProviders` 内部（§4.8）；Key 只写不读（前端永不回显，更新即覆盖）；日志脱敏、不落 worker 日志。工作区隔离在迁移期沿用 RLS；去 Supabase 后按《多端产品设计》§5 步骤 5 拍板 repository 应用层过滤或自管 RLS。桌面形态的 OS 钥匙串（SecretStore 桌面 Provider）随 D1+ 落地，本决策只约束 v1 服务端实现。

## 备选与取舍

- **端到端不落服务端明文（浏览器加密）**：密钥管理与丢失恢复体验差，实现复杂度高，v1 否决；列为远期增强选项。

## 后果

- 正面：v1 可交付；与现有 Supabase RLS 体系自然衔接；SecretStore 缝为桌面钥匙串留了升级位。
- 负面：服务端持有明文窗口（解密实例化模型时），依赖服务端自身的安全边界。
- 同步：P4 `modelProviders` 的凭证读写封装、`provider-contracts.ts` 的 `apiKeyRef` 语义、日志脱敏测试按本结论落地。
- 重新评估条件：出现「企业部署要求 Key 不落地」的真实需求时再议。
