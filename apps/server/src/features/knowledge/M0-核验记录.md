## ③ 代码／配置文件类型默认是否索引（结论：默认不索引）

- `protocol/src/types.rs::FileTypes::default()`：`markdown: true, text: true, **code: false, config: false**`。
- `Settings::default().excluded` 默认排除 `.git, node_modules, dist, target, .venv, venv, __pycache__`（对 KB-3「只注册工作区根」是有利的隐私护栏）。
- CLI 有解：`cli/src/main.rs` 的 `Add` 带 `--types`，注释原文「只索引指定扩展名，如 md,txt,html,py,ts；**省略时保留已有设置**」，映射到 `Command::AddWithTypes { extensions }`（`protocol/src/cli.rs`）。
- `check --json` 的 `extensions` 会回报当前**实际生效**的索引格式列表（main.rs `output.extensions.join(",")`）。
- **处置**：不必猜默认值。初始化顺序 = `check --json` 读 `extensions` → 未注册的新根用 `sag add <root> --types <文档+代码扩展名>` 显式指定 → 再 `check` 复验。若根已存在（用户装了桌面端、coverage=included），**不自动改 `--types`**（`--types` 是「只索引这些」，会覆盖用户既有设置），只在侧栏提供「启用代码索引」显式动作。见计划 §4.3 与 §8.3「代码排错」。

### 上游 `configure()` 行为核实（KB-1 落地依据）

- `sag config` **无参数**在非交互（`interactive()` 为 false）下走 `configure()` 末尾的 `return Ok(current)`，main 打印 `to_string_pretty(&config)` → **输出脱敏 ModelConfig JSON、不阻塞**。
- `sag config --auth bearer --key-stdin`：`std::io::stdin().read_to_string()` 读取并 `trim()`，发 `Command::Configure { url: None, model: None, key: Some(...), auth_mode: Bearer }` → **保留现有 url/model**。`--key` 与 `--key-stdin` 互斥，且 `--key` 自带「可能保存在终端历史」警告 → 只能用 stdin。
- **待实机验证的风险**：`main.rs` 在 `args.query.is_none()` 分支有一段「首次未配置 JEV 则调用 `configure(ConfigOptions::default())` 并可能 `return Ok(0)`」的引导逻辑。若该分支对 `config` 子命令同样生效，首次未配置时 `sag config` 可能不返回 JSON。当前实现把「无输出 / 非 JSON」显式上报为 `missing` 并给出原因，不静默；`probe/collect.mjs` 实采时可确认。

## 2026-11-09 实机核验（Windows x64 / `@zleap-ai/sag@0.1.8`）

为避免污染全局与用户真实知识库，CLI 装在临时目录 `npm install --prefix <tmp> @zleap-ai/sag@0.1.8 --no-save`，直接调 `native/win32-x64/sag.exe`（17,724,416 字节），并把 `SAG_DATA_DIR` 指向隔离的临时数据目录。

| 核验项 | 实采结果 | 结论 |
| --- | --- | --- |
| `sag --build-info` | `{"version":"0.1.8","build_id":"release-980c0eff659959f8","channel":"release","protocol_version":2}` | **无条件输出 JSON**，不受配置引导影响；可作为最稳的 CLI 可用性探测 |
| `sag config`（**全新未配置数据目录**） | 正常输出 ModelConfig JSON，未阻塞、未进入交互 | M2 悬着的「首次 JEV 未配置时 main 引导分支可能截断 config 子命令」风险**实证不成立**，stdin 注入方案可用 |
| `sag check <dir> --json` | 输出 `path / coverage / index_ready / enabled / indexed_files / roots`，`coverage="none"`，无 `extensions` | 与 `sagCheckOutputSchema` 一致；`extensions` 可选的设计正确 |
| `sag list --json` | 首次调用 ETIMEDOUT（探针 120s 上限） | service 冷启动耗时；产品侧要给 `list` 留更长超时／有限重试，别在状态心跳里同步等 |
| `sag "<query>" --json` / `sag -F ... --json` | 无输出 | 无 Jev 凭据时语义检索不可用，与「语义检索需 JEV」一致；纯本地 `-F` 在 service 未就绪时也无输出，需实机复验 |

**实采抓到的真实字段漂移（已修）**：0.1.8 **发布版** `sag config` 输出为 `{url, model, models, has_key}`，**没有 `auth_mode`**；而 main 分支 `protocol/src/types.rs::ModelConfig` 声明 `auth_mode: ModelAuthMode` 且无 `skip_serializing_if`。即发布二进制与当前源码结构不一致。若按源码把 `auth_mode` 设为必需，真机初始化会直接解析失败。已改为 `.optional()`，`isSagConfigured()` 缺省时按 `has_key` 判定（语义不变），并在 `sag-cli-contract.test.ts` 加回归用例锁死。

**探针自身的修复**：初版 `probe/collect.mjs` 会把实采输出**直接覆盖 fixture 样例字段**，导致本机绝对路径（`\\?\D:\...`）与实时索引状态写进仓库、契约测试随机器漂移。现改为：实采原始输出落到 `SAG_DATA_DIR/sag-last-collection.json`（本机产物、不入库），fixture **只更新 `_meta`**，样例值保持按 serde 推导。

**Apifox**：按仓库惯例创建 AI 隔离分支 `ai/20261109-from-main-sag2-knowledge`（`--from main`）并导入全量 spec（247 端点、`--overwrite-mode overwrite`）。**合并回 main 未执行**，按 `AGENTS.md` 与 CLI 提示需用户确认。

## 2026-11-09 全链路冒烟与 `--types` 白名单修复
