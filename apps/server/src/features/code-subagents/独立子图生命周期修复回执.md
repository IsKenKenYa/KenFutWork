# 独立子图生命周期修复回执

问题：真实后台 Task 的子模型仍持流，父模型自然完成却触发子图 `Error("Abort")`，TaskWork 变 failed。detached 子任务不能跨 Run 存活。

本地实际 SDK 为 LangGraph 1.4.16、LangChain Core 1.2.12。Task 工具已排除后台的显式父 signal，manager与子 runtime 有独立 controller。实际污染来自父工具的异步 RunnableConfig：Pregel.stream 带入 `__pregel_read`与父 `__pregel_abort_signals`，runner优先使用旧 externalAbortSignal；父 V2 stream自然收尾 abort其内部controller，子图随之失败。子 runtime自己的controller未被取消，所以裸Abort不能被正确视为用户停止。

默认子 Harness 的完整异步执行通过 SDK 公开 `AsyncLocalStorageProviderSingleton.runWithConfig({}, callback, true)`隔离；沿同一 AgentRunService/factory/native流程运行，不新建模型循环，不改 Scope、角色、目录、权限与治理。产品父子归因仍由 CodeChildRequest、实际 SQL 派发事实和 eventSink持有。前台的明确父 signal与用户停止仍生效，未用吞Abort或伪造成功修症状。
