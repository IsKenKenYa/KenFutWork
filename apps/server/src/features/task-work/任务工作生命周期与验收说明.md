# Task 工作生命周期与验收

`types.ts` 是公共契约，`service.ts` 持有活executor与前台lease，`repository.ts` 是生产Postgres provider；原始命令句柄仍由process-sandbox持有，UI/HTTP/WS与工具consumer由各自plugin接线。这里不复制Agent loop，也不创建第二套Task身份。

宿主启动先通过persistence.acquireSessionLock取得独占物理会话，再恢复同executionHost的旧owner。生产provider使用专用pg.Client，锁与unlock在同一session，普通query pool即使max=1仍可推进。第二活实例不能恢复/重复派发。lease signal丢失时立即禁止新的派发/前台/通知，发onHostLost到Harness/FS consumer，同时真实stop本实例工作。PG fencing本身不能证明旧OS范围已退出；真实stop或失败证据必须另行保留，不能据metadata中断状态声称rangeEmpty。

`initialize()` 返回恢复记录并发布onChanged。旧running标interrupted；旧terminal-unconsumed保留原status、summary、endedAt及日志/统计，只抑制旧通知，不重放有副作用的执行。生产settle对未提供的outputRef/outputStats使用COALESCE，保留此前recordOutput已采集数据。

每Task前台只一个lease。忙碌时终态在下一模型边界原子consume，空闲时onReady返回严格boolean：真正admit后保留准入锁，false/异常释放，用户上下文恢复后可再次通知。Root CodeUI跨API的active_run_id admission仍须由消费者事务锁承担；manager内存lease不是跨机器FG锁。

stop、closeTask、host close共享每work一次真实stop Promise；确认前保持running。失败不会因迟到run rejection变成虚假canceled。close fence读取Task权威scope/branch/state：revoking已推进版本，所以墓碑取被关闭旧版本；必须确认旧close完成才允许较新可信scope重开。墓碑继续过滤旧scope终态，branch/current谓词拒绝迟到通知。origin Run signal只在start持久准入与模型消费前检查；accepted显式BG工作独立存活，wake/recordOutput不读取旧Run signal。

子任务与命令复用同一记录：detached默认true；foreground子任务detached=false从创建起consumed=true，参与持久化/并发/changed，但不再mailbox或显示为后台卡片。foreground生命周期的parent signal由executor consumer连接。dispatch fingerprint复用execution公共canonical serializer，规范化detached默认值；同键异参数拒绝，省略default true与explicit true同键重放。

新增forward迁移：`supabase/migrations/20261002235403_task_work_detached.sql`，由官方Supabase CLI生成；既有迁移未修改。代码数值只从resolveMaxConcurrent/既有治理传入，本域未新增业务magic limit。
