## 真实问题

本机未创建供应商、模型或实例设置行时，单字段 PATCH autoCompactEnabled=false 会正常写入 PG。原 SQL 为新行生成真实 default_model=''，服务端 nullish 解析保留此空值；原完整响应 schema 却要求模型字符串至少一字。PATCH 已保存后返回 400，随后 GET 也返回 400，用户无法再读取设置。

28147 公开 GET→PATCH→GET / 隔离迁移 PG 实际 exit1：两个公开响应均为 invalid_request，诊断为 settings.defaultModel 长度不足，库值已是空模型与 false。不是输入无效，也不是写入失败。初始无行 GET 仍有既有 env fallback，不将其说成已配置模型或为了测试设置假模型。

## 接线与保持的边界

- shared 实例设置状态/响应如实允许空字符串，字段仍为必需 string。
- 稀疏 PATCH 另保持显式默认模型非空约束；缺省模型不注入，其他字段默认值仍剥除。不改 repository、SettingsService 或 SQL，不用 fallback 掩盖真实空值。
- 中央 registry 的 GET/PATCH 中文说明与生成 OpenAPI 同步；输出 defaultModel 无 minLength，显式输入仍 minLength=1。
- 8654 原 case 实际 GREEN。94086 两文件 17 条实际通过，包括两个公开 HTTP/PG case：局部保存成功且其他设置完整保留；显式空模型+其他字段的 PATCH 被拒绝，并保持原库无设置行、公开读回不变。反向 case 首次 GREEN，不伪称另一次 RED。
