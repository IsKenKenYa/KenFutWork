# 历史附件复制规格

本模块承接原 forkAssistant，保留原 V4 附件协议。目标是：父 Task 删除并清理自己的附件 Blob 后，新 Task 的预览、分享读取、重试及后续编辑仍可独立使用原内容。native 内联内容不替代私有附件所有权迁移。

- **业务幂等键**：原命令持久认领键 `(instanceId, clientId, commandId)`，由原 GUI 生成并在重放时保留；原参数指纹包含源 Task、目标行及分支 guard。认领一次后服务端生成唯一新 Task ID。每个复制项使用 `attachmentKey(target, sourceUploadKey)`；不把名称、正文、checksum 或访问凭据当业务键。
- **事实指纹**：同一复制项必须保持正规 fileName/MIME/长度/checksum 与全部目标身份、代际、引用、路径一致。相同 committed 事实允许重放；不同事实或 aborted 墓碑明确冲突，不能覆盖。
- **独立所有权**：新对象路径固定 `instance/project/newTask/newKey`；新 committed 记录的 Task/session/创建者均是目标根身份，不留父 FK。行附件与 canonical 依次重绑定，顺序与 attachmentIndex 不变；重复 source ref 仅复制一次。previewRef 正规化为目标主附件的读取路径，不留父临时引用。
- **准备**：从当前已授权源 Task 的 committed 记录取字节，校身份、私有路径、长度与 checksum，逐项读取和上传，内存最多持当前一项字节，遵守现有附件字节预算，不扩大文件/命令沙箱。外部 Blob I/O 不放入 SQL 发表事务，不自动重试。
- **原子发表**：原 source guard、授权与项目锁仍生效。创建新根 Task/native binding/state 后，attachment provider 在同一 scoped SQL 事务关联已准备 committed 事实，再发表原 ACK；发表回调只做 SQL，不做 Blob I/O。Provider 核真实新根/项目/创建者/ready/准确代际及宿主租约。
- **终态与补偿**：确认未发表才删除本操作独占的目标 Blob 和 native；源对象永不由复制补偿删除。COMMIT 回包丢失先沿原根锁回读 durable ACK；已发表只释放准备租约，结果不明保留资源，不据 catch 猜测回滚。
- **删除与迟到**：父删除中断准备的本机 admission，或由最终 source guard 拒绝；迟到复制不能发表新根。目标删除沿原附件清理链删除自己的 Blob 并只保留最小 aborted 身份墓碑，防止旧键复活。

## 验证边界

原 HTTP/SSE/V4 上传与读取、Task 列表/快照/重试、实际模型请求是主断言。真实 PG 提交故障、Blob 公共下载与独占目录文件对账只补强原子性/独立性；不 mock 自家协调器，不制造执行过的 Run。

必须覆盖正常文本/PNG/PDF、顺序/并发重放、同键不同参数、真实 COMMIT 回包丢失、发表事务失败后无半 Task/Blob/native、复制中删除源、目标删除后迟到读取、多个输入共享同一图片 ref 的原无 target 缩略图读取。

## 本轮边界

本轮租约由当前宿主持有。native 与 Blob 的持久准备清单、进程中断后的结果不明重对账仍是总 Goal 的后续工作；资源保留不等于冷恢复已完成。不自动重放未证明幂等的外部 I/O。子会话的私有转录复制另行实施，不用附件复制冒充完整历史迁移。
