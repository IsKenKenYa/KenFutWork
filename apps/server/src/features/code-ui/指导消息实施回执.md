# 指导消息实施回执

2026-10-05；本线程继续原 Code/Design 与 Harness 完整目标，不将本切片视为完整 guide 或完整 UI 验收。

## 接线与事实

- 同一 Harness 的 `agent-run-extension` 注册 Code 主 Run middleware。Definition 为 `CodeGuideConsumer`，Provider 为 `guide-input.ts`，Consumer 为 `guide-model-mailbox.ts`；插件注册并调用真实 `CodeUiService`，不新增模型选择循环或另一个 Agent loop。
- 忙时纯文本、当前模型及其调用配置、mode/plan 不变的指导绑定原 Run 和 Task 两种代际。保留同一 canonical 输入的 sourceCommandId/clientId/modelInvocation，持久状态先 steering；原 ACK 的 queue 是异步接收语义，不作为模型消费证据。
- 真实工具返回或正文结束后、下一模型请求前，在 Task 事务内按 FIFO 每次提升一条指导、生成 guided 用户行与工作段。后一条仍保留 steering/queue 状态，进入再下一次请求；不提前合并多个输入的模型配置。注入 HumanMessage 使用稳定消息 ID，已有 graph 消息按 ID 去重；已提升但 graph 尚未提交的消息可用同一 ID 补回。
- 主 Run、主 scope、Actor、目录和两种代际均复核；子代理不消费主指导。问题等待不被指导代答，仍由实际 resolveInteraction 释放原工具。
- 停止或未到合法模型边界时，未消费指导保持完整 canonical 输入，转回普通队列并取得新的运行身份；停止后的队列暂停，不自动继续旧 Run。此处仍需补完全部并发、删除与冷恢复用例。
- 原 ZCode 从历史稳定回复的实际用户原因决定操作。本项目重试现在选择同轮最新真实用户行；独立 guide pre 边界未接通时不开放会丢失指导的原输入重试。普通未指导轮次的冻结重试仍通过。

## 原源码与阶段差距

固定参考为 ZCode `29628c9` / 3.14.3：`prompt-admission.ts`、`turn-guide-drain.ts`、`message-persistence.ts`、`product-projection.ts` 的 admission、持久提升与 guided 工作段机制。原实现支持 guide 携带显式模型/mode/plan 变化，并可在文本结束边界续跑。本项目已验证同配置的工具/正文边界及每边界单输入 FIFO；显式切配置尚未接通，保持后续目标，不能称原实现也仅支持相同配置。

工作段始末时间来自实际投影事件；activeMs 为原契约可选字段。扣除人工等待的权威时钟尚未接通，不以墙钟时长伪装 activeMs，工时与全视觉仍待验收。工作台输入 routing 与原 UI 实际点击也仍需验证，不能用 RPC 通过替代 GUI 验收。
