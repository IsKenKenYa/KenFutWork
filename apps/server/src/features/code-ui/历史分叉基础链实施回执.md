# 历史分叉基础链实施回执

角色：原 forkAssistant 首条生产纵向链与窄范围验收回执。完整 Code/Harness Goal 继续实施；本回执不代表全部分叉场景或原 GUI 已完成。

## 行为

- 原 forkAssistant payload/ACK 与回调保留。成功 agent 轮末完整 assistant 可在父 B 运行时分叉；新建独立根 Task、独立 native thread，同事务发布 Task/state/ACK，不恢复文件、不停止父 Run、不创建 Canvas。
- 完成轮次真实 config/Todo/usage 由 conversation 在成功完成时冻结；恢复保留、重复完成不改写。失败、取消、手动压缩与子完成不伪造根成功事实。A 同轮指导及 Enter/Exit 的最终配置不从父 B 当前值推算。
- fork 配置取 A 的完成事实，移除父 permissionGrant/planTransition；物理目录/附加授权/沙箱取当前父 Task，复核授权与分支代际。Project 默认改 B 不迁移既有 A 或从 A 分叉的 Task。
- 不复制父 active Run、queue、pending interaction、后台工作、批准计划或调度输入；继承行清除 owner 专属 actions，不能冒用父文件回退能力。新 Task 累计消费从零开始，保留原历史上下文窗口信息。
- native 历史使用原 post opaque reference、完整祖先及真正工具结果；没有从展示 rows 拼模型输入。原生资源先准备，事务成功后 release，确认未发表才 discard。
- 发表事务异常先经同一 source-root 行锁等待 COMMIT/ROLLBACK，再读取同 fingerprint 的持久 ACK。已发表按原 ACK收尾；结果不明保留资源并报可读错误。PG借出事务连接的 error 事件有监听，查询 Promise 仍如实拒绝。
