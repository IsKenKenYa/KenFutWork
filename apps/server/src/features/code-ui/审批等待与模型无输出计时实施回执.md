日期：2026-10-06。共享分支：`codex/完整移植ZCode-Code界面`。

## 问题与实现

Computer Use线程在用户实际`pnpm desktop`/GLM-5.3-Flash实例确认：模型已发出工具调用，服务端等待人工审批；原协议批准后工具立即返回，模型正常完成。只读发现权限由该线程独立修复并提交`0a850a4c`。本批处理共享的等待计时和原审批消费，不读取或修改用户模型Key、数据库或系统授权。

原看门狗把等待下一个任意流事件当作模型上游停滞，长工具与人审等待因此会被误杀。现在适配器按真实`on_chat_model_start/end/error`维护模型请求集合，仅该集合非空时启用无输出计时；通用迭代器的取消竞争始终保留。真实模型停滞仍失败并中止底层请求，人审/工具等待不再提示更换模型。

`agentStreamIdleTimeoutMs`归入现有实例治理：默认值和物理timer护栏唯一来自shared governance，库值优先于原env兜底，0显式关闭；沿现有JSON存储、设置API和Code/Design治理表单接线，无新SQL或服务key。退役env顶层第二份标量，运行时从同一次实例设置读取取得预算。原审批已结算的迟到回执映射为`noop/proto.alreadyResolved`，不再称作新批准；不签发权限或恢复已停止Run。
