## 公开 manual 预算可达性更正

此前静态审查遗漏 runtime 预算块的外层 autoEnabled || operation=compact 条件：auto 关闭的普通 Run 根本不生成 manualCompactPlan。V4 compact 在 service.admitText 资格化并冻结当前 snapshot 的完整选择，始终获得新 Run；runTurn 传 controlOperation/operation=compact，runtime 为此 Run 新建 factory、解析冻结模型并求预算，再通过唯一 streamCompactOperation 消费新 agent 的 compactCurrent。第一方 HTTP/RPC 没有直接消费旧 agent port 的入口。

所以 Guide B 已消费后准入 compact 就冻结 B；若 B 仍排队，compact 冻结当时 A，派发时不重新解释，这是准入契约。不能把后者当旧预算 stale，不能为未暴露的内部 port 添加生产补丁。这是基线5a5b3f41的公共调用链源审，尚不是 auto-off→Guide→manual 的实际端到端 GREEN。
