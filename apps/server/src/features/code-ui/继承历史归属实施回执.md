# 继承历史归属实施回执

本回执承接《历史分叉基础链实施回执》。完整 Code/Design/Harness Goal 继续实施；本轮只验收继承历史的独立归属与原历史操作链。

## 行为与事务边界

- Code UI 私有 `inheritedHistory` 保存当前 Task 的 owner、原 source 溯源、pre/post capture 状态、opaque 引用、原始 replay 输入与成功完成视图。source 不作读取父 Task 的依赖，也不在 `agent_runs` 或 `agent_turn_boundaries` 伪造子 Task 执行过的 Run。
- Native adapter 一次复制所选完整祖先链及 pending writes，返回所请求 pre/post 的目标 opaque 引用；只有 adapter 解析 key。写前拒绝空/空白/重复 ID、跨 thread、非 root namespace 及不在祖先链的引用。缺省能力的 adapter 明确不可用。
- 新 Task 的 turn、row、entity、response、tool 和 work segment 展示身份归属新 Task；原生消息及工具调用关联保留。后续 conversation 事件与冷读不会擦掉继承记录。
- 原 `forkAssistant` 使用可信完成视图与 captured 非空 post；原 `retryTurn` 使用 pre 对应的原始 start canonical/modelInvocation。指导输入不能替换重试起点。原 `editUserQuery` 保留当前文件并使用新文本，继承历史不签发父文件回退权限。
- 编辑或重试切 thread 时，所有保留前缀的可信边界都由 adapter 重绑定；被截断的继承记录和完成视图移除。新 thread/state/ready/ACK 沿既有事务发布，失败沿既有补偿释放未发布目标。
- 单个边界缺失保留 `unavailable`，不会变成 `captured:null`；已有真实 pre 仍可重试，缺少 post 不提供分叉。两个 phase 都不存在仍拒绝猜测上下文。
