## 修复的行为

真实 Read→正文包含两次模型调用，输入 token 都是 10、输出分别 3/7。旧实现通过输入 token 变化猜调用，Run 账本又覆盖最后一次，公开汇总实际只有 10/7。现以 SDK 的真实模型调用 ID 更新绝对值：同调用 stream/end 覆盖，不同调用相加；最终 API、持久 Task/Run 账本和原 V4 累计都是 20/10。

模型 start 的安全归属由服务端解析后的模型 metadata 提供，只包含 provider/model/providerInstanceId/configRevision；实例与接入客户端仍从可信 Run 获取。账本固定同调用归属，结束时按模型归属分桶结算，不要求每调用生成 SQL 行。缺调用 ID 不借 message ID、token 数或事件序号猜身份。

用量提取在 tool-call、已流式正文和子文本过滤之前，同时消费 stream/end。重复绝对值不重复投影；实际变化与向下修正可见，停止缺 end 时也保留最后观察值。非法计量拒绝采集，采集回调失败不使正常正文/Run失败，日志不输出异常对象。上游未上报的 token 不估算。

Code 宿主保存各 Run 的绝对总量，主/子会话分别持有账本；重复事件、完成 A 后启动 B、导出恢复、旧 Run 迟到都不能重计或抹掉既有累计。缓存缺字段保留已知值，显式 0 可覆盖。原 V4 必填缓存数字字段保留原形状，显示 0 不证明上游已上报；内部账本与外部事件仍保留未知语义。
