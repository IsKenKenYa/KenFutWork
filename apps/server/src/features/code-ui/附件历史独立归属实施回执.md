# 附件历史独立归属实施回执

本批解除原 forkAssistant 的用户附件前缀限制，继续使用原 V4 DTO、上传与读取回调。子会话的私有转录仍另行迁移；本文不代表完整历史复制或原 GUI 视觉验收完成。

## 行为

- 附件 provider 从当前 Task 的正规 committed 记录读取实际字节、验证所有权/路径/长度/checksum，逐项准备新 Task 的独占 Blob；重复 source ref 去重，保留数组顺序与 index。
- 原生上下文完整复制后，新根/state/native binding/committed 附件/原 ACK 在同一事务发表。仓库 provider 校新根、项目、创建者、ready、双代际、私有 key/path 与宿主租约；相同完整事实幂等，不覆盖异事实或墓碑。
- UI 用户行与 inherited canonical refs 都指向目标 Task 的新正规附件；native 模型内容仍由原完整历史保留，不从展示行拼接或制造执行过的 Run。
- 确认回滚才分别清理本操作准备的 Blob/native，清理互不遮断、源内容不动；COMMIT 回包丢失沿原 durable ACK 收尾，不删除已发表目标。结果不明资源与冷恢复仍遵守《历史附件复制规格》的明确未完成边界。
- 原无 target 图片预览允许同 Task 中多处完全一致的 immutable canonical 引用；仍保留 Task、具体 target/index、元数据和 committed 字节检查。不同内容、错误引用与错误 index 不因此放宽。
