## 两个独立行为修复

1. 原手动压缩从真实 SDK `handleLLMEnd` 获得 call ID 与 input10/output3/cache4，但 runtime 只转发 input/output，Run 总量和内存账本丢 cache4。现保留已知缓存的可选字段，不把缺失编为0。
2. 原 V4 compact→追问实际集成暴露：设置关闭自动压缩时，本项目用 noop 替换 native summarization `wrapModelCall`，也跳过了已提交手动摘要的有效输入投影。现共用固定 SDK adapter 的有效消息投影，真实后续请求消费摘要与保留尾部；关闭自动压缩仍不触发新的自动/overflow摘要，不使用超大阈值或另起模型循环。native 历史不改写，旧 checkpoint 仍可读取原历史。

私有 `_summarizationEvent` 仅在 `native-context-history.ts` 的固定 SDK adapter 内校验/投影；`deep-agent.ts` 传完整状态对象，不把这个 SDK 私有字段写进产品契约。现有公开 contextHistory 读面和 passive middleware 消费同一函数。
