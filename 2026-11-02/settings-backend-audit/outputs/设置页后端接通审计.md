# 工作台设置页（七项）后端接通审计

日期：2026-11-02。方式：只读审计，以仓库当前源码为准；对照 `references/zcode`（ZCode 3.14.3）。中间材料见 [work/证据笔记.md](../work/证据笔记.md)。

## 载体架构（读表前提）

`/workbench` 设置页是从 ZCode 移植的 zcode UI，运行在 iframe 内。zcode UI 的服务调用统一走 `POST /api/code-ui/rpc`（service + method + args），服务端在 [service.ts](file:///Volumes/FanXiangMac/MyOpenSource/KenFutWork/apps/server/src/features/code-ui/service.ts) 的 hostRpc 分派；宿主自有能力（权限、实例设置）走独立 HTTP。服务端 setting 服务设有一份 key 白名单 `preferenceKeys`（[workspace-rpc.ts](file:///Volumes/FanXiangMac/MyOpenSource/KenFutWork/apps/server/src/features/code-ui/workspace-rpc.ts#L71-L91)），不在白名单的设置项保存时会直接抛错「当前宿主尚不支持设置」。这是本轮多条结论的根源。

## 补齐建议（按优先级）

1. **P1 记忆页开关**。要么补齐，要么先隐藏。补齐需两层：服务端把 `memoryEnabled` 加入 workspace-rpc.ts:71-91 白名单（shared schema 已支持，无需改接口定义），并在 agent 运行时建立真实消费方（新会话是否启用记忆）；若近期不建记忆能力，应在 Web 宿主隐藏该开关，避免「一点就报错」的假开关（违反入口可用纪律）。列表 viewer 在 Web 已被占位遮蔽，无额外工作量。
2. **P2 常规页被拒行**（搜索增强、HTTP 代理×3、任务自动归档×2）。每项二选一：进白名单并给出 Web 消费方（httpProxy 可由服务端出站请求消费，taskAutoArchive 可由后台任务消费），或按平台条件隐藏行。改动层：server 白名单 + 对应 service 消费 + 前端条件；不改 shared 接口定义（appSettingsSchema 均已含这些字段）。
3. **P3 快捷键真机验证**。持久化链路已通，重点验证录制互斥与应用内命令实际触发；如录制期间按键被页面其它监听器吃掉，在录制态加临时互斥（前端层）。
4. **P4 浏览器控制桌面能力**。Web 侧已是诚实空态，无需动；未来桌面端在宿主平台适配层实现 importChromeBrowserData/clearEmbeddedBrowserData 真实版本。
5. **P5 模型设置、权限**。无需补齐，保持现状。
